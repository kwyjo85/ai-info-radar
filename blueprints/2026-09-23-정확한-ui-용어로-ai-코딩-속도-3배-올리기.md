# 정확한 UI 용어로 AI 코딩 속도 3배 올리기

## 쉽게 말하면
AI에게 코드 수정을 시킬 때 "화면 뜨면 나오는 거 그거"라고 말하면 AI도 헤매고 다시 물어봐야 하지만, "스플래시 화면"이라고 정확히 말하면 한 번에 알아듣습니다. 마치 병원에서 "배 아파요" 대신 "명치 아래가 콕콕 찔러요"라고 말하면 진료가 빨라지는 것과 같은 원리로, UI 부품 이름을 정확히 알면 AI 코딩 지시가 즉시 통합니다.

## 이걸로 할 수 있는 것
1. Jev 관련 랜딩페이지를 Claude Code로 만들 때 "이 팝업 말고 저 팝업"이 아니라 "모달 대신 토스트로 바꿔줘"라고 바로 지시해 수정 왕복 횟수를 줄인다.
2. 이 대시보드(kwyjo85.github.io/ig-dashboard) UI를 고칠 때 "카드 위에 뜨는 그거"가 아니라 "배지(badge)", "칩(chip)" 같은 정확한 용어로 요청해 한 번에 원하는 결과를 받는다.
3. 외주로 앱/웹 UI 수정 작업을 받아 Claude Code로 처리해주는 부업을 할 때, 클라이언트의 모호한 요청("여기 뜨는 거요")을 정확한 컴포넌트 용어로 번역해 작업 속도를 높이고 더 많은 건을 처리해 수익을 늘린다.

## 개요
Material Design 3, Apple HIG, daisyUI, Mobbin 네 사이트를 "UI 용어 사전"으로 삼아 자주 쓰는 컴포넌트 이름(스플래시, 모달, 토스트, 배지, 칩, 바텀시트 등)을 정리하고, Claude Code에 디자인 수정을 요청할 때 이 용어를 그대로 사용하는 습관을 만드는 것입니다. 프롬프트 정밀도가 올라가면 AI가 되묻거나 엉뚱하게 고치는 일이 줄어 실질적인 코딩 반복 속도가 빨라집니다.

## 구현 가능성
**상** — 새로운 도구 설치나 API 연동이 전혀 필요 없고, 참고 사이트 4곳도 이미 무료로 공개되어 있습니다. 실질적으로는 "용어집 문서 하나 만들고 그걸 보면서 프롬프트 쓰는 습관"만 들이면 되는 수준이라 당일 적용이 가능합니다.

## 필요 도구
- Material Design 3 (m3.material.io) — 무료
- Apple HIG (developer.apple.com/design/tips) — 무료
- daisyUI 컴포넌트 문서 (daisyui.com/components) — 무료
- Mobbin (mobbin.com) — 기본 열람 무료, 고급 검색/필터는 유료 플랜 있음
- Claude Code — 이미 사용 중인 유료 구독으로 충당
- 노션 또는 마크다운 파일 1개 (용어집 저장용) — 무료

## 구현 단계
1. daisyUI 컴포넌트 페이지(daisyui.com/components)를 훑어보며 자주 쓸 것 같은 컴포넌트 20~30개(모달, 토스트, 스플래시, 배지, 드로어, 바텀시트 등) 이름만 리스트업한다.
2. Material Design 3(m3.material.io/components)와 Apple HIG(developer.apple.com/design/tips)에서 같은 개념의 플랫폼별 명칭 차이(예: Android는 "Snackbar", iOS는 "Toast"에 해당하는 개념이 다름)를 확인해 표로 정리한다.
3. Mobbin에서 실제 앱 스크린샷을 보며 "이게 이 이름이구나"를 시각적으로 매칭해 기억을 굳힌다.
4. 정리한 내용을 `ui-glossary.md` 같은 파일로 만들어 `cocobaby/ai-info-radar` 저장소나 개인 노션에 저장해두고, Claude Code 세션 시작 시 CLAUDE.md에 링크해 언제든 참조 가능하게 한다.
5. 실전 적용: 이 저장소의 대시보드(ig-dashboard) UI를 수정할 일이 생기면 "이 부분 고쳐줘" 대신 용어집을 보고 "이 배지 컴포넌트 색상 바꿔줘" 식으로 지시해보고, 실제로 수정 왕복 횟수가 줄어드는지 체감 확인한다.
6. 부업/외주 관점: 클라이언트 요청을 받을 때 모호한 표현을 용어집 기준으로 번역해 Claude Code에 전달하는 것을 표준 워크플로우로 삼아, 동일 시간에 더 많은 수정 건을 처리할 수 있는지 트래킹한다.

## 예상 공수
- 용어집 초안 작성: 1~2시간 (난이도: 하)
- 실전 대시보드 적용 및 검증: 30분~1시간 (난이도: 하)
- 총 반나절 이내 완료 가능한 초경량 작업

## 리스크/유의점
- 용어집을 만들어도 실제 프롬프트에 습관적으로 적용하지 않으면 효과가 없으므로, CLAUDE.md나 프롬프트 템플릿에 강제로 끼워 넣는 장치가 필요합니다.
- Mobbin은 고급 기능이 유료라 무료 범위 내에서만 참고하면 충분합니다.
- 용어가 플랫폼(iOS/Android/Web)별로 다르게 불리는 경우가 있어, 어떤 플랫폼 기준인지 Claude Code에 함께 명시해야 혼선이 줄어듭니다.
