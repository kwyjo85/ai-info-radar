# Bastion으로 MCP 서버 인프라 통합 — Claude Code 자동화 안정화 및 인프라 컨설팅 상품화

## 개요
Bastion은 macOS에서 Claude Desktop, Claude Code, Cursor 등 여러 AI 클라이언트가 각자 중복 실행하던 MCP 서버를 단일 프로세스로 묶어 공유하는 프록시/데몬입니다. 자체 제작한 MCP 서버(인스타 대시보드 수집기, Jev 연동 스크립트 등)를 한 번만 띄우고 모든 클라이언트에서 재사용할 수 있어 개인 자동화 인프라의 리소스 낭비와 관리 부담을 줄이고, 이 구성 노하우를 "AI 자동화 인프라 셋업" 컨설팅 상품으로 확장할 수 있습니다.

## 구현 가능성 — 중
- 설치 자체는 단순할 것으로 예상되나, 기존에 운영 중인 커스텀 MCP 서버들을 Bastion 프록시 구조에 맞게 재배선해야 실질적 이득이 발생
- HN 게시물이 제목/URL 위주로 정보가 얕고(포인트 2, 댓글 0) 초기 단계 프로젝트일 가능성이 높아, 문서·안정성·라이선스를 직접 확인하는 선행 검증이 필요

## 필요 도구
- Bastion 본체 (bastion.mgcrea.io) — 비용·라이선스 미확인, 설치 전 확인 필요
- Homebrew — 무료 (macOS 설치용)
- Claude Code / Claude Desktop / Cursor 등 기존 MCP 클라이언트 — 기보유
- 기존 자체 MCP 서버 (ig-dashboard 수집기, Jev 연동 스크립트 등) — 기보유
- Model Context Protocol 공식 문서 (modelcontextprotocol.io) — 무료, 레퍼런스용

## 구현 단계
1. bastion.mgcrea.io에서 설치 방법, 라이선스, 지원 클라이언트 범위, 프로젝트 활성도(GitHub 커밋 이력 등)를 먼저 확인
2. Homebrew 등으로 Bastion 설치 후 데몬을 실행하고 로그로 정상 기동 확인
3. 현재 Claude Code / Claude Desktop 설정 파일(mcp.json 등)에 등록된 MCP 서버 목록을 백업해 둔 뒤, Bastion 프록시 엔드포인트로 전환 준비
4. 기존 커스텀 MCP 서버 중 하나(예: ig-dashboard 수집기)를 시범적으로 Bastion에 연결해 Claude Code와 Claude Desktop 양쪽에서 동시 접속·정상 동작 테스트
5. 문제가 없으면 나머지 MCP 서버들도 순차 이전하고, 각 클라이언트 설정에서 중복 실행 항목 제거
6. 안정화 후 설치·이전·트러블슈팅 과정을 체크리스트로 문서화해 외주/컨설팅용 "AI 자동화 인프라 셋업" 서비스 상품 초안으로 정리

## 예상 공수
- 설치 및 1차 시범 테스트: 1~2시간
- 전체 MCP 서버 이전 및 안정화: 3~5시간
- 서비스화 문서 작성: 2시간
- 총 6~9시간, 난이도: 중

## 리스크/유의점
- 프로젝트가 신생(포인트 2, 댓글 0)으로 보여 유지보수 중단 리스크가 있으므로 기존 설정 백업 없이 전면 전환하지 말 것
- 프록시 계층 추가로 단일 장애점(SPOF)이 생겨, 다운 시 모든 클라이언트의 MCP 기능이 동시에 마비될 수 있음
- 개인정보 포함 가능한 커스텀 서버(ig-dashboard 등)를 다중 클라이언트에 공유할 때 접근 권한·인증 범위를 재검토해야 함
- 개인 규모(1인, 소수 서버) 사용에서는 리소스 절감 효과가 미미해 실질 ROI가 낮을 수 있음
