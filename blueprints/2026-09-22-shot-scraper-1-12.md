# shot-scraper 1.12 — WebP 스크린샷 자동화 도입

## 개요
shot-scraper는 커맨드라인으로 웹페이지 스크린샷을 찍는 Playwright 기반 도구이며, 1.12 버전부터 `--quality` 옵션과 함께 WebP 포맷 출력을 지원한다. 블로그 포스트 썸네일, 문서 스크린샷, OG 이미지 등을 자동 생성하는 개인 워크플로우에 적용하면 PNG/JPEG 대비 파일 용량을 크게 줄여 빌드 속도와 저장공간, 페이지 로딩 속도를 개선할 수 있다.

## 구현 가능성 — 상
- CLI 도구 설치와 명령 실행만으로 즉시 사용 가능하며 별도 인프라나 서버가 필요 없음
- macOS에서 Python/pip와 Playwright 브라우저 바이너리만 설치하면 로컬에서 바로 동작
- launchd 등 기존에 이미 구성된 자동화 파이프라인(30분 사이클 등)에 스크립트 한 줄 형태로 손쉽게 편입 가능

## 필요 도구
- **shot-scraper** (오픈소스, 무료) — `pip install shot-scraper`
- **Playwright** (오픈소스, 무료) — shot-scraper 설치 시 함께 필요, `shot-scraper install`로 브라우저 바이너리 설치
- **Python 3.9+** (무료, macOS 기본 내장 또는 Homebrew 설치)
- (선택) **cwebp / ImageMagick** (무료) — 기존 PNG/JPEG 자산 일괄 재변환 시 보조 도구
- (선택) **launchd** (macOS 내장, 무료) — 정기 스크린샷 자동 갱신 스케줄링

## 구현 단계
1. `pip install --upgrade shot-scraper` 로 1.12 이상 버전 설치 확인 (`shot-scraper --version`)
2. `shot-scraper install` 실행하여 Playwright용 Chromium 바이너리 설치
3. 테스트 캡처: `shot-scraper https://example.com -o test.webp --quality 80` 실행 후 파일 크기·화질 확인
4. 기존에 PNG/JPEG로 캡처하던 스크립트(블로그 썸네일 생성, 대시보드 스크린샷 등)에서 출력 확장자를 `.webp`로 변경하고 `--quality 80` 옵션 추가
5. `--quality` 생략 시 무손실(lossless) WebP가 생성되므로, 텍스트/UI 캡처처럼 선명도가 중요한 경우와 사진성 이미지의 용도를 구분해 옵션 값 결정 (사진성 콘텐츠는 quality 70~85 권장, 다이어그램/텍스트는 무손실 또는 90+ 권장)
6. 웹페이지·문서에서 `<img>` 태그가 WebP를 참조하도록 경로 업데이트, 또는 정적 사이트 빌드 스크립트 내 이미지 확장자 변수 수정
7. 기존 launchd job(있다면)에 새 명령을 반영하고, 1~2 사이클 동안 실행 로그와 생성된 WebP 파일 크기를 모니터링해 이전 PNG/JPEG 대비 절감률 확인
8. 필요 시 `shot-scraper multi` 등 배치 설정 파일에도 동일하게 출력 포맷을 `.webp`로 일괄 수정

## 예상 공수
- 설치 및 기본 테스트: 15~30분
- 기존 스크립트/파이프라인 반영: 30분~1시간
- 전체 난이도: **하** (CLI 옵션 변경 수준의 단순 작업)

## 리스크/유의점
- WebP는 구형 브라우저(구 IE, 일부 이메일 클라이언트)에서 지원되지 않을 수 있으므로 용도가 이메일 첨부나 레거시 호환이 필요한 경우 PNG/JPEG 병행 고려
- 무손실 모드(옵션 미지정)는 파일 크기가 예상보다 클 수 있어, 실제 절감 효과를 보려면 `--quality` 값을 명시적으로 테스트해 적정값 찾기
- 기존에 PNG/JPEG 경로를 하드코딩한 다른 스크립트나 정적 사이트 템플릿이 있다면 확장자 불일치로 이미지 깨짐이 발생할 수 있으니 전수 점검 필요
