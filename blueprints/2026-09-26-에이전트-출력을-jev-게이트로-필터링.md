# 에이전트 출력을 Jev 게이트로 필터링

## 쉽게 말하면
여러 AI 에이전트가 아이디어나 후보를 잔뜩 쏟아낼 때, 그걸 사람이 일일이 걸러보지 않고 "심사위원 역할의 AI"를 하나 더 세워서 1차로 추려내게 하는 방법입니다. 예를 들어 에이전트가 주제 40개를 뽑아오면, 심사위원 AI가 "중복이야, 근거가 약해" 하며 30개를 걸러내고 남은 10개만 다음 단계(정밀 분석)로 넘기는 식입니다. 지금 운영 중인 ai-info-radar의 "관련성 필터"와 정확히 같은 구조입니다.

## 이걸로 할 수 있는 것
1. 여러 소스(유튜브, 뉴스, 커뮤니티)에서 자동 수집한 후보 주제 수십 개 중 중복·저품질을 걸러내고 핵심만 남겨 분석 시간을 단축한다.
2. 클라이언트 업무 자동화 컨설팅 시 "1차 필터 에이전트 + 2차 정밀 분석 에이전트" 2단계 파이프라인을 표준 상품으로 제안해 수익화한다.
3. 인스타 대시보드 평가 파이프라인에서 "게이트 통과 기준"을 명문화해 채점 일관성을 높이고, 이 노하우를 블로그/컨설팅 콘텐츠로 재판매한다.

## 개요
에이전트가 만든 대량 후보 출력(주제, 리드, 클립, 이메일 등)을 값비싼 정밀 LLM 분석에 넣기 전에, 저비용·고속 게이트 단계에서 명시적 기준(중복 여부, 최소 근거, 형식 적합성)으로 필터링하는 아키텍처입니다. 핵심 가치는 "비용 절감"과 "일관성"입니다 — 사람이 정성 판단하던 1차 걸러내기를 규칙화된 AI 게이트가 대신하되, 최종 판단은 여전히 사람 또는 정밀 에이전트가 내리게 합니다.

## 구현 가능성 — 중
게이트 패턴 자체(값싼 필터 → 값비싼 분석)는 이미 검증된 흔한 아키텍처이고, 지금 ai-info-radar 파이프라인의 관련성 필터가 이미 이 역할을 하고 있어 확장이 쉽습니다. 다만 영상에서 소개된 "Jev(TypeSafe)"라는 특정 벤더 제품을 쓸 필요는 없고, 이미 쓰고 있는 Claude 모델로 동일한 게이트를 구현하면 되므로 "중"입니다 — 새 도구 도입이 아니라 기존 파이프라인 리팩터링에 가깝습니다.

## 필요 도구
- Claude Code / Claude API (Haiku 4.5 등 저비용 모델을 게이트용으로) — 이미 보유, 추가 비용은 API 호출량 기준
- 기존 ai-info-radar 수집 스크립트 (Python/Node, 현재 저장소 코드) — 무료, 이미 존재
- 로컬 launchd 스케줄러 — 무료, 이미 사용 중
- (선택) Jev/TypeSafe — 유료 SaaS, 이번 구현에는 불필요 (자체 게이트로 대체 가능)

## 구현 단계
1. 현재 수집 스크립트에서 "원본 후보 리스트"가 어디서 생성되는지 확인하고(예: 주제 40개 산출 단계), 그 지점과 최종 분석 단계 사이에 새로운 "게이트" 함수를 삽입할 위치를 정한다.
2. 게이트 기준을 명문화한 프롬프트를 작성한다 — 예: "중복 주제 제거", "출처 신뢰도 최소 기준 미달 제외", "이미 다룬 주제 재등장 제외" 등 3~5개 판정 규칙.
3. 저비용 모델(Haiku 4.5)로 게이트 함수를 구현: 입력은 후보 리스트 전체(예 40개), 출력은 통과/탈락 여부와 사유를 담은 JSON.
4. 게이트 통과 항목만 기존 정밀 분석(현재 채점 파이프라인)으로 넘기도록 파이프라인을 수정한다.
5. 탈락 항목과 사유를 로그 파일(data/gate_log.json 등)로 남겨, 나중에 기준이 너무 빡빡한지/느슨한지 검토할 수 있게 한다.
6. 1~2주간 운영하며 게이트 통과율(예: 40개 중 10개)을 모니터링하고, 기준을 조정한다.
7. 파이프라인이 안정화되면 이 "게이트 → 정밀 분석" 패턴을 문서화해, 다른 클라이언트 프로젝트(리드 스코어링, 콘텐츠 선별 등)에 재사용할 수 있는 템플릿으로 만든다.

## 예상 공수
- 게이트 프롬프트 설계 및 스크립트 삽입: 2~3시간
- 로그/모니터링 추가: 1시간
- 기준 튜닝 및 검증 (실제 운영 데이터로): 1~2주에 걸쳐 틈틈이 30분씩
- 난이도: 하~중 (기존 파이프라인에 필터 단계 하나 추가하는 수준, 새로운 인프라 불필요)

## 리스크/유의점
- 영상 제목("100배 강화")은 근거 없는 과장이며 실제로는 단순한 2단계 필터링 아키텍처에 불과하니, 별도 유료 툴(Jev/TypeSafe) 도입 없이도 동일 효과를 낼 수 있음을 인지할 것.
- 게이트 기준이 너무 엄격하면 유효한 주제까지 조기에 걸러낼 수 있으므로, 초기에는 탈락 사유를 반드시 로그로 남겨 사람이 주기적으로 검토해야 함.
- 게이트 단계와 정밀 분석 단계의 판단 기준이 겹치면 이중 작업이 되므로, 두 단계의 역할(게이트=형식/중복 체크, 분석=품질/가치 판단)을 명확히 분리해야 함.
