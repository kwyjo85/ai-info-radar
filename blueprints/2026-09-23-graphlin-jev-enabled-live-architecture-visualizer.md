# Graphlin 벤치마킹 — Jev로 "실시간 아키텍처 드리프트 감지" SaaS/VS Code 확장 만들기

## 개요
Graphlin은 코드베이스의 의존성 그래프를 실시간으로 그려주는 "라이브 아키텍처 시각화" 도구로, 파일이 저장될 때마다 각 모듈을 어떤 아키텍처 레이어(프론트/백엔드/DB/서비스 등)에 속하는지 즉시 분류해야 하는데, 이 분류 작업은 텍스트 생성이 필요 없는 전형적인 "타입 값 + 확신도" 문제라 Jev로 치환하기 적합하다. 기존에 LLM으로 이런 분류를 하면 저장할 때마다 초 단위 지연과 비용이 발생하지만, Jev는 100배 빠르고 저렴해 "타이핑하는 동안 실시간으로 갱신되는" 경험이 가능해진다. 이 아이디어를 그대로 벤치마킹해 엔지니어링 팀 대상 "아키텍처 거버넌스" 유료 도구(VS Code 확장 + 팀 대시보드)로 재구성해 수익화한다.

## 구현 가능성 — 중
- 근거(가능): 의존성 그래프 추출(madge, dependency-cruiser, pydeps 등)과 그래프 시각화(React Flow, Cytoscape.js)는 이미 성숙한 오픈소스 생태계가 있어 MacBook에서 로컬로 전체 파이프라인을 구축·테스트하는 데 무리가 없다.
- 근거(제약): 원문(robotpaper.ai)이 HN에서 포인트 1, 댓글 0으로 사실상 검증 트래픽이 없고 출처 자체의 신뢰도가 낮아, "Graphlin"이 실제로 존재/작동하는 제품인지부터 확인이 필요하다. 또한 Jev는 게임/로봇의 실시간 의사결정용으로 소개된 모델이라 "코드 구조 분류"라는 용도에 대한 실제 정확도·지연시간이 검증되지 않았다 — 별도 PoC로 직접 확인해야 한다.

## 필요 도구
- TypeSafe AI Jev API 키 (유료, 종량제 — 요금제 확인 필요)
- madge 또는 dependency-cruiser (JS/TS) / pydeps (Python) — 정적 의존성 그래프 추출 (무료, 오픈소스)
- React Flow 또는 Cytoscape.js — 실시간 그래프 시각화 (무료, 오픈소스)
- chokidar — 파일 변경 감지(watch) (무료)
- Hono 또는 Express + WebSocket(ws) — 실시간 업데이트 서버 (무료)
- Zod — Jev가 반환하는 레이어 타입/확신도 스키마 검증 (무료)
- VS Code Extension API — 에디터 내 임베딩 (무료)
- Redis/Upstash — 분류 결과 캐싱 (무료 티어 있음)
- Vercel 또는 Fly.io — 대시보드 호스팅 (무료 티어~소액)
- Stripe — 팀/저장소 단위 구독 과금 (거래 수수료만 발생)

## 구현 단계
1. TypeSafe AI 공식 문서에서 Jev API 스펙(엔드포인트, 인증, 커스텀 타입 스키마 정의 방법, 입력 크기 제한)을 확인하고 평가판 키를 발급받는다. 동시에 robotpaper.ai의 Graphlin 원문을 재확인해 실제 구현체·데모 링크가 있는지 검증한다.
2. 테스트용 오픈소스 저장소 1개(중간 규모, 예: 100~300 파일)를 골라 madge/dependency-cruiser로 import 그래프를 JSON으로 추출하는 파이프라인을 만든다.
3. 레이어 분류 타입 스키마를 정의한다 — enum(frontend/backend/db/service/util/test) + confidence(float). 각 모듈의 파일 경로, import/export 목록, 폴더 위치를 입력으로 Jev에 넘겨 레이어를 분류하는 함수를 작성하고 Zod로 응답을 검증한다.
4. chokidar로 파일 저장 이벤트를 감지해 변경된 파일만 재추출·재분류(Jev 호출)하고, 결과를 WebSocket으로 프론트엔드에 push하는 서버를 구현한다. 전체 재계산이 아닌 증분(diff) 갱신으로 설계해야 "실시간" 체감이 나온다.
5. React Flow로 그래프 UI를 만들어 레이어별 색상 노드 + 확신도를 표시하고, "아키텍처 드리프트 감지" 기능을 추가한다 — 베이스라인 스냅샷(예: main 브랜치 분류 결과) 대비 새 커밋에서 레이어 규칙 위반(예: DB 모듈을 프론트엔드가 직접 import)이 생기면 실시간 경고를 띄운다.
6. 핵심 로직을 VS Code 확장으로 패키징(웹뷰에 그래프 임베딩)하고, 팀 단위로 저장소를 등록·공유할 수 있는 호스팅 대시보드를 별도로 만들어 Stripe로 저장소 수/팀원 수 기준 월 구독을 붙인다.
7. 데모 영상(실시간 저장 → 그래프 갱신 → 드리프트 경고)을 만들어 Show HN/Product Hunt에 공개하고, 초기 사용자 피드백으로 지원 언어(Python/JS 외 Go, Java 등)를 확장한다.

## 예상 공수
- Jev 스펙 확인 + Graphlin 원문 검증: 2시간
- 정적 의존성 추출 파이프라인: 6~8시간
- Jev 분류 스키마 + 호출 로직: 8~10시간
- 파일 watch + 증분 갱신 + WebSocket 서버: 10~12시간
- React Flow 그래프 UI + 드리프트 감지 로직: 10~14시간
- VS Code 확장 패키징: 8~10시간
- 대시보드 + Stripe 과금: 6~8시간
- 총 50~64시간 (2~3주, 주말 포함 파트타임), 난이도: 중상

## 리스크/유의점
- 원문 신호가 매우 약함(HN 포인트 1, 댓글 0, 출처가 robotpaper.ai라는 생소한 사이트) — "Graphlin"이 실제 운영 중인 제품인지, 아니면 콘셉트 소개 글에 불과한지 먼저 확인하지 않으면 존재하지 않는 제품을 벤치마킹하는 셈이 될 수 있다.
- Jev가 코드 구조 같은 "구조화된 텍스트 입력"에 대해서도 게임/로봇 의사결정과 동일한 수준의 정확도를 내는지 검증되지 않았다 — 소규모 PoC(2단계)에서 분류 정확도를 사람이 라벨링한 정답셋과 비교해 먼저 확인할 것.
- 고객사 코드의 파일 경로·모듈 구조(경우에 따라 함수/클래스명 일부)가 Jev API로 전송되므로, 사설 저장소를 다루는 엔지니어링 팀 고객에게는 데이터 처리 방침과 온프레미스/자체 호스팅 옵션 요구가 나올 수 있다.
- CodeSee, Sourcegraph, Swimm 등 기존 코드 시각화/온보딩 도구와 기능이 겹칠 수 있어, "실시간성"과 "저비용 아키텍처 드리프트 경고"라는 차별점을 명확히 포지셔닝해야 한다.
