# Jevmem: Jev 기반 Claude Code 자동 메모리 관리

## 쉽게 말하면
Claude Code로 코딩할 때마다 "이 프로젝트는 이런 구조야", "이 사용자는 이런 스타일을 좋아해" 같은 걸 매번 새로 설명해야 하는 게 번거로운데, Jevmem은 이런 맥락을 자동으로 기억해뒀다가 다음에 또 알아서 꺼내 쓰게 해주는 "AI의 노트 정리 비서"입니다. 사람으로 치면 매번 처음 만난 사람처럼 자기소개를 시키는 대신, 비서가 미리 프로필 카드를 정리해서 건네주는 셈입니다.

## 이걸로 할 수 있는 것
1. 여러 클라이언트 프로젝트를 Claude Code로 병행 작업할 때, 프로젝트별 코딩 컨벤션·요구사항을 매번 재설명하지 않고 자동 유지하기.
2. 반복적으로 의뢰받는 "AI 업무 자동화 컨설팅" 납품 시, 고객사별 맥락(툴 스택, 과거 결정사항)을 기억한 채로 세션을 이어가 응답 품질과 속도를 높이기.
3. 개인 블로그/뉴스레터(ai-info-radar 같은) 자동화 파이프라인을 유지보수할 때, 과거에 내린 설계 결정을 Claude가 스스로 기억해 매번 같은 실수를 반복하지 않게 하기.

## 개요
Jevmem은 Claude Code 세션 간에 프로젝트/사용자 맥락을 자동으로 저장·검색·주입하는 메모리 레이어입니다. 반복 설명(온보딩 비용)을 줄여 실질적인 작업 처리량을 늘리고, 특히 여러 프로젝트·여러 클라이언트를 동시에 다루는 "AI 자동화 대행" 비즈니스 모델에서 세션당 준비 시간을 줄여 수익성을 높이는 데 직접적으로 기여합니다.

## 구현 가능성
**중**
- 근거: GitHub 오픈소스 프로젝트로 코드가 공개되어 있고 Claude Code 확장/훅 구조를 사용하는 것으로 보여 설치 자체는 어렵지 않을 가능성이 높습니다.
- 다만 HN 포인트 61점, 댓글 40개 수준의 초기 단계 프로젝트로, 문서화·안정성·유지보수 지속성이 검증되지 않았고, 사용자의 기존 자동 메모리 시스템(`.claude/projects/.../memory`)과 기능이 겹쳐 통합 시 충돌 가능성이 있어 "상"으로 매기지는 않았습니다.

## 필요 도구
- **Claude Code** (이미 사용 중, 유료 구독)
- **jevmem** (GitHub, https://github.com/Avinash-jetwani/jevmem — 오픈소스/무료로 추정, 라이선스 확인 필요)
- **Node.js 또는 Python 런타임** (jevmem 구현 언어에 따라 다름, 저장소 README 확인 필요 — 무료)
- **로컬 저장소/DB** (SQLite 또는 파일 기반일 가능성, 무료)
- (선택) **git** — 메모리 변경 이력 버전관리용, 무료

## 구현 단계
1. `git clone https://github.com/Avinash-jetwani/jevmem`으로 저장소를 받아 README를 정독하고 실제 구현 언어·의존성·설치 요구사항을 확인합니다.
2. 별도의 테스트용 디렉터리(예: `~/sandbox/jevmem-test`)에서 먼저 설치해 Claude Code 훅/MCP 연동 방식을 파악합니다 — 기존 `ai-info-radar` 프로젝트에 바로 적용하지 않습니다.
3. jevmem이 저장하는 메모리 형식과 저장 위치가 기존 `/Users/W/.claude/projects/.../memory/`의 자동 메모리 시스템과 충돌하는지, 중복 저장이 발생하는지 점검합니다.
4. 충돌이 없다면 실제 업무 프로젝트 1개(예: 진행 중인 자동화 컨설팅 건)에 시범 적용해 1주일간 사용하며 "재설명 시간이 줄었는지"를 체감 기준으로 평가합니다.
5. 효과가 검증되면 다른 클라이언트 프로젝트로 확대 적용하고, 컨설팅 상품화 시 "Claude Code 작업 효율화 셋업" 옵션으로 패키징할지 검토합니다.

## 예상 공수
- 저장소 파악 및 설치: 1~2시간
- 격리 환경 테스트 및 기존 메모리 시스템과의 충돌 점검: 2~3시간
- 실제 프로젝트 시범 적용 및 1주일 관찰: 추가 작업 시간 거의 없음(사용하며 관찰)
- **난이도: 하~중** (설치 자체는 쉬우나, 기존 메모리 시스템과의 통합 판단에 신중함 필요)

## 리스크/유의점
- 초기 단계 오픈소스라 갑자기 유지보수가 중단되거나 breaking change가 생길 수 있음 — 프로덕션 워크플로우에 바로 얹지 말고 격리 테스트 우선.
- 기존에 이미 구축된 자동 메모리 시스템과 역할이 겹쳐, 두 시스템이 서로 다른 방식으로 같은 정보를 저장하면 오히려 맥락 혼란(중복/모순된 기억)을 유발할 수 있음.
- 클라이언트 프로젝트의 민감 정보(고객사 코드, 요구사항)가 로컬에 영구 저장되므로, 저장 위치의 접근 권한과 백업 정책을 확인할 것.
