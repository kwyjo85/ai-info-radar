# Jev로 구현한 판단 기반 안전장치 (Guardrails)

## 쉽게 말하면
AI 에이전트에게 "이 요청 처리해도 되나?"를 매번 사람이 아니라 또 다른 AI(Jev)가 먼저 판단하게 만드는 장치입니다. 마치 신입 직원 옆에 항상 붙어서 "이건 보내도 돼, 이건 상사한테 먼저 물어봐"라고 코치하는 선배를 두는 것과 같습니다. 규칙을 일일이 코드로 짜는 대신, 판단 자체를 AI에게 위임해서 애매한 경계 케이스도 걸러낼 수 있습니다.

## 이걸로 할 수 있는 것
1. Claude Code로 고객사 코드베이스에 자동 커밋/PR 봇을 만들 때, 위험한 명령(rm -rf, force push, 시크릿 노출)을 Jev가 실시간으로 차단하게 설정.
2. 판매 중인 AI 자동화 파이프라인(예: 인스타 대시보드 데이터 수집 봇)에 "이 데이터는 외부로 보내도 되는 개인정보인가"를 Jev가 사전 검토하도록 붙여서 컴플라이언스 리스크 줄이기.
3. 여러 고객에게 Claude Code 기반 자동화를 판매할 때, "이 가드레일 세트를 붙였습니다"를 신뢰 요소이자 가격 프리미엄 포인트로 제안.

## 개요
이 프로젝트는 정적 규칙(정규식, 화이트리스트) 대신 LLM의 판단력을 이용해 에이전트 행동의 안전성을 실시간 평가하는 가드레일 프레임워크입니다. Jev(2026-09 출시 TypeSafe AI System One 모델)를 판단 엔진으로 붙이면, Claude Code나 다른 자동화 에이전트가 수행하려는 액션(파일 삭제, 외부 API 호출, 데이터 전송 등)을 실행 전에 "안전/위험/애매함"으로 분류해 차단하거나 사람 확인을 요청할 수 있습니다. 자동화를 파는 입장에서는 "폭주 방지 장치가 있다"는 것 자체가 판매 포인트가 됩니다.

## 구현 가능성: 중
- 근거: 오픈소스 저장소(deepansh-saxena/jev-guardrails)가 존재하지만 HN 포인트 2점, 댓글 0개로 초기 단계 프로젝트입니다. 코드 성숙도·문서화 수준이 검증되지 않았고, Jev API 자체도 2026-09 출시라 실사용 경험이 적습니다. 개념 검증(PoC)은 하루 이틀이면 가능하지만, 프로덕션 신뢰도 확보에는 반복 테스트가 필요합니다.

## 필요 도구
- Jev API 키 (TypeSafe 제공, 유료 — 사용량 기반 과금 확인 필요)
- jev-guardrails 저장소 (무료, GitHub 클론)
- Claude Code CLI (기존 사용 중, 무료/구독)
- Python 또는 Node.js 런타임 (무료)
- (선택) LangChain/직접 미들웨어 레이어로 Claude Code 훅에 연결 (무료)
- 로컬 로그 저장용 SQLite 또는 JSON 파일 (무료)

## 구현 단계
1. `git clone https://github.com/deepansh-saxena/jev-guardrails` 로 저장소를 받아 README와 예제 코드를 먼저 읽고 의존성(requirements.txt/package.json) 파악.
2. Jev API 키를 발급받고 `.env`에 저장, 저장소의 설정 파일에 Jev를 판단 모델로 지정.
3. 로컬 테스트용 "위험 시나리오" 10~15개를 직접 작성 (예: 프로덕션 DB 삭제 명령, 개인정보 외부 전송, 알 수 없는 URL로 curl 요청).
4. 이 시나리오들을 가드레일에 통과시켜 Jev의 판단(허용/차단/보류)이 기대와 맞는지 수동 검증.
5. Claude Code의 hooks(사전 도구 실행 훅)에 가드레일 미들웨어를 연결해, 실제 Claude Code 세션에서 위험 명령 시 자동 차단되는지 확인.
6. 판단 로그(차단 사유, 시각, 명령 내용)를 파일로 남겨 나중에 고객에게 "이만큼 위험 행동을 막았다"는 리포트로 활용.
7. 안정화되면 판매 중인 자동화 패키지(예: 인스타 대시보드 봇, 커밋 자동화 봇)에 옵션 기능으로 통합해 프리미엄 요금제 항목으로 제시.

## 예상 공수
- PoC 구축 및 시나리오 테스트: 4~6시간
- Claude Code 훅 연동: 2~3시간
- 로그/리포트 기능 추가: 2시간
- 총 예상: 8~11시간, 난이도 중 (신규 API·초기 단계 오픈소스라 디버깅 시간 변동성 있음)

## 리스크/유의점
- 저장소가 초기 단계(별점/댓글 거의 없음)라 버그·미완성 기능 가능성이 높음 — 프로덕션 투입 전 충분한 시나리오 테스트 필수.
- Jev 자체가 최신 모델(2026-09)이라 장기 안정성·요금 정책이 아직 검증 부족.
- 판단형 가드레일은 확률적 모델이므로 100% 차단을 보장하지 않음 — 규칙 기반 하드 스탑(예: rm -rf 절대 금지)과 병행 사용 권장.
- 고객에게 판매 시 "AI가 판단해서 막아준다"는 문구는 과신을 유발할 수 있으니, 한계를 명확히 고지할 것.
