# AI 매매 봇의 3구간 백테스트 & 섀도 테스트 방법론

## 쉽게 말하면
실제 돈을 걸기 전에 "가짜 돈 통장"으로 매매 로직을 먼저 돌려보고, 여러 번의 시험(학습→검증→홀드아웃)을 통과한 전략만, 그것도 아주 적은 금액으로만 실전에 투입하는 방식입니다. 마치 운전면허를 딸 때 도로주행 전에 시뮬레이터로 여러 번 연습하고, 그 다음엔 초보운전 스티커를 붙이고 저속으로만 운행하는 것과 비슷합니다.

## 이걸로 할 수 있는 것
1. 퇴근 후 또는 주말에 AI에게 매매 아이디어를 코드로 짜게 한 뒤, 실제 돈을 걸지 않고 24시간 가상 수익률을 지켜볼 수 있다.
2. 여러 코인/종목 조합을 한 번에 테스트해 우연히 잘 맞은 전략과 진짜 쓸만한 전략을 구분할 수 있다.
3. 실전 투입 후에도 손절·목표·청산 규칙을 숫자로 고정해두어, 감정적으로 추가 베팅하는 것을 시스템적으로 막을 수 있다.

## 개요
이 블루프린트는 "AI가 생성한 매매 로직을 실전에 바로 쓰지 않고, 단계적 검증 절차를 거쳐 리스크를 최소화하는 자동화 파이프라인"을 구축하는 것을 목표로 합니다. 핵심 가치는 과최적화(우연히 잘 맞은 결과를 실력으로 착각하는 것)를 걸러내고, 실계좌 투입 시에도 베팅 규모를 기계적으로 제한해 손실을 한정하는 데 있습니다. 개인 맥북에서 로컬 스크립트 + 거래소 테스트넷(또는 모의투자 API)만으로 구현 가능한 수준입니다.

## 구현 가능성: 중
- 3구간(학습/검증/홀드아웃) 백테스트는 데이터만 있으면 로컬 스크립트로 충분히 구현 가능 (난이도 낮음).
- 섀도 테스트(가상 거래를 실시간 시세에 맞춰 모의 체결)는 실시간 데이터 수집 + 상태 관리 로직이 필요해 중간 난이도.
- 실계좌 자동 연동(소액 2% 베팅 포함)은 거래소 API 인증, 주문 오류 처리, 리스크 가드 코드가 필요해 신중한 설계가 요구됨 — 원문에서도 "전체 코드는 확인 불가"라고 명시되어 있어, 이 부분은 직접 설계해야 함.
- 종합적으로 개인이 단계적으로(1→2→3단계 순서로) 구현하면 상~중 수준의 난이도로 완성 가능.

## 필요 도구
- **Claude (Claude Code 또는 Claude.ai)** — 매매 로직 및 백테스트 스크립트 생성 (유료 구독 필요, 플랜별 상이)
- **Python** — 백테스트/섀도 테스트 엔진 구현용 (무료)
- **거래소 공개 시세 API** (예: 암호화폐 거래소의 공개 REST/WebSocket API) — 과거·실시간 시세 수집 (대부분 무료, 거래소별 요청 한도 상이) [공식 문서 확인 필요]
- **pandas, numpy** — 데이터 처리 및 지표(변동성, z-score 등) 계산용 라이브러리 (무료, 오픈소스)
- **로컬 SQLite 또는 CSV 파일** — 가상 거래 로그 및 이벤트 기록 저장 (무료)
- **거래소 테스트넷/모의투자 계정** (지원 거래소에 한함) — 섀도 테스트 단계에서 실제 체결 환경과 유사하게 검증 (무료, 단 지원 여부는 거래소별 확인 필요) [공식 문서 확인 필요]
- **거래소 실계좌 API 키 (읽기/주문 권한)** — 최종 소액 실전 투입 단계용 (거래소 수수료 외 별도 비용 없음, 단 API 사용 약관 확인 필요)
- **cron 또는 launchd (macOS 기본 스케줄러)** — 정기적으로 백테스트·섀도 테스트 스크립트 실행 (무료, macOS 내장)

## 구현 단계
1. Claude에게 매매 아이디어(예: 특정 지표 기반 진입/청산 조건)를 설명하고, 과거 시세 데이터를 입력받아 백테스트할 수 있는 Python 스크립트를 작성하도록 요청한다.
2. 수집한 과거 데이터를 시간순으로 "학습(초반)/검증(중반)/홀드아웃(최근)" 3구간으로 분할하는 함수를 작성한다.
3. 여러 종목·조합에 대해 3구간 모두에서 수익이 양수인 조합만 필터링하는 로직을 만들고, 그 결과를 로컬 파일(CSV/SQLite)에 기록한다.
4. 손절(예: 최근 N시간 변동폭 기준), 목표(변동폭의 배수), 최대 보유시간(청산 조건) 같은 리스크 규칙을 코드 상수로 고정해 하드코딩한다 — 매매 중 임의로 바뀌지 않도록 한다.
5. 통과한 전략에 대해, 실시간 시세를 받아와 "가상 자금"으로 모의 체결하는 섀도 테스트 스크립트를 launchd(또는 cron)로 주기 실행하도록 등록한다.
6. 가상 거래 10건(또는 원하는 기준 건수)이 모두 종료될 때까지 섀도 테스트를 지속하고, 결과를 로그 파일/대시보드로 기록한다.
7. 가상 거래 성과가 일관되게 양호하면, 거래소 API로 실계좌 소액 자동 주문 로직을 연결하되, 1회 거래당 베팅 비율(예: 자본의 2% 이내)을 코드에서 강제 제한하는 가드를 추가한다.
8. 실전 전환 후에도 동일한 손절/목표/청산 규칙을 유지하며, 주기적으로(예: 주 단위) 성과를 재검토해 규칙 변경 여부를 판단한다.

## 예상 공수
- 1~3단계 (백테스트 엔진 구축): 약 6~10시간 [추정], 난이도 중
- 4~6단계 (섀도 테스트 자동화): 약 8~15시간 [추정], 난이도 중~상 (실시간 데이터 처리·상태 관리 로직 때문)
- 7~8단계 (실계좌 연동 및 리스크 가드): 약 5~10시간 [추정], 난이도 상 (API 인증, 주문 오류 처리, 금전 리스크 직결)
- 전체 합산: 약 20~35시간 [추정], 전체 난이도는 중~상

## 리스크/유의점
- 원문 자체가 "투자 권유 아님"을 명시하고 있으며, 과거 백테스트 성과가 미래 수익을 보장하지 않는다는 점을 항상 전제해야 한다.
- 50개 조합 중 1개만 3구간 모두 양수였다는 사례처럼, 다중 비교로 인한 우연한 성공(데이터 스누핑)을 경계해야 하며, 반드시 홀드아웃 구간 결과를 최종 검증 기준으로 삼아야 한다.
- 실계좌 API 키는 주문 권한만 최소로 부여하고, 출금 권한은 절대 포함하지 않도록 거래소 설정을 확인해야 한다.
- 거래소 API 요청 한도, 테스트넷 지원 여부, 수수료율 등은 거래소마다 다르므로 실제 사용 전 해당 거래소 공식 문서를 반드시 확인해야 한다 [공식 문서 확인 필요].
- 자동 주문 로직에 네트워크 오류·API 응답 지연 등 예외 처리가 없으면 의도치 않은 중복 주문이나 미체결 상태가 발생할 수 있어, 충분한 예외 처리와 로깅이 필요하다.
- 원문의 대시보드와 전체 코드는 비공개 상태이므로, 이 블루프린트의 구체적 수치(변동성 배수, 청산 시간 등)는 참고용 아이디어이지 검증된 공식이 아니며, 본인의 자금 상황에 맞게 재설계해야 한다.
