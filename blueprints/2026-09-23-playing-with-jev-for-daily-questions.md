# Yesno.fyi 벤치마킹 — Jev로 만드는 "즉답형 Yes/No 마이크로 SaaS"

## 개요
yesno.fyi는 재미 목적의 랜덤 Yes/No 응답 사이트지만, 이 구조를 Jev의 강점(텍스트 생성 없이 타입 값+확신도를 100배 빠르고 저렴하게 반환)으로 대체하면 "실제 맥락 기반 즉답 서비스"로 바꿀 수 있습니다. 예: 이메일/캘린더/문서 내용을 넣고 "이 요청 승인해도 될까?", "이 거래 리스크 있나?" 같은 진짜 의사결정 질문에 Boolean+confidence를 즉시 반환하는 API/위젯을 만들어 B2B SaaS 구독 또는 API 종량제로 수익화합니다.

## 구현 가능성 — 상
- 입출력이 매우 단순(텍스트 컨텍스트 → Boolean + confidence)해 Jev의 대표 유스케이스와 정확히 일치.
- MacBook에서 로컬 프로토타입 + 클라우드 API 호출 조합으로 하루 이틀 내 MVP 가능.
- 유사 사례(비교 블루프린트 다수, 예: `jev-vs-codex-flight-booking`, `adaptive-reranking-with-jev`)가 이미 폴더에 존재해 참고 패턴 확보 용이.

## 필요 도구
- Jev API 접근 (TypeSafe AI 제공, 유료 — 토큰당 과금, LLM 대비 저렴)
- Python 3.11+ 또는 Node.js 20+ (무료)
- FastAPI 또는 Express (무료, API 서버)
- Vercel / Railway 배포 (무료 티어 있음, 트래픽 증가 시 유료)
- Stripe API (수익화용, 거래 수수료만 발생)
- SQLite 또는 Supabase (무료 티어, 질문/응답 로그 저장)
- (선택) Zapier/Make — 슬랙·이메일 연동 자동화 (무료~유료 플랜)

## 구현 단계
1. Jev API 키 발급 및 로컬에서 curl/SDK로 `input: 텍스트, output: {answer: bool, confidence: float}` 응답 형식 확인.
2. FastAPI로 `/ask` 엔드포인트 구현: 사용자가 질문+컨텍스트(예: 계약서 발췌, 이메일 본문)를 POST하면 Jev 호출 후 즉시 Boolean+confidence 반환.
3. confidence < 0.6 구간은 "확실하지 않음" 처리 로직 추가해 오답 리스크 완화 (임계값은 실사용 데이터로 튜닝).
4. 간단한 웹 위젯(HTML+JS) 제작: yesno.fyi 스타일 UI에 "컨텍스트 붙여넣기" 입력창 추가.
5. Stripe 연동으로 무료 10회/일, 유료 플랜(월 $9~19)으로 무제한 호출 구조 설계.
6. 사용 로그(질문, 답변, confidence, 정답 여부 피드백)를 DB에 적재해 추후 파인튜닝/정확도 지표로 활용.
7. Product Hunt / HN Show 형태로 런칭, "yesno.fyi인데 진짜 맥락 이해함" 포지셔닝으로 초기 트래픽 확보.
8. 첫 유료 고객 확보 후 Slack/이메일 워크플로우 연동(승인 요청 자동 판정 등 니치 B2B 유스케이스)으로 확장.

## 예상 공수
- MVP(API+위젯): 8~12시간, 난이도 중
- 결제 연동 + 로그/피드백 시스템: 추가 6~8시간, 난이도 중
- 런칭 및 B2B 확장: 지속적 반복 작업, 난이도 중상

## 리스크/유의점
- Jev의 확신도(confidence) 보정이 도메인마다 다를 수 있어, 실제 정답률 검증 없이 "즉답"을 파는 건 신뢰 리스크가 큼 — 초기엔 저위험 유스케이스(재미/생산성 보조)로 시작 권장.
- 법률·의료·금융 등 고위험 의사결정에 Yes/No 자동 판정을 제공할 경우 책임 소재 문제 발생 가능 — 면책 조항 및 "참고용" 명시 필수.
- yesno.fyi류 컨셉은 차별화 없으면 바이럴성은 있어도 리텐션이 낮음 — 진짜 수익화하려면 반드시 "실제 데이터 기반 판단" 니치(계약 승인, 리스크 스코어링 등)로 좁혀야 함.
- Jev가 신규 모델(2026-09 출시)이라 API 안정성·요금제 변동 가능성 있음 — 초기엔 소규모 트래픽으로 검증 후 확장.
