# Keel – AI 에이전트용 타입 전략 언어

## 쉽게 말하면
Keel은 AI에게 "이렇게 자유롭게 코드를 짜봐"라고 맡기는 대신, 정해진 규격의 레고 블록(타입이 있는 작은 조각들)만 조립하게 해서 트레이딩 전략을 만드는 도구입니다. 블록 규격이 정해져 있으니 AI가 실수로 엉뚱한 조합을 만들기 어렵고, 사람도 완성된 블록 구조를 빠르게 훑어보며 검증할 수 있습니다. 다만 원문 기준으로는 암호화폐 거래소(Hyperliquid) 전용 사례만 소개되어 있어, 주식 시장 적용 가능 여부는 확인되지 않았습니다.

## 이걸로 할 수 있는 것
1. (만약 주식 데이터/브로커 연동이 지원된다면) 자연어로 "RSI 과매도 시 매수" 같은 전략을 설명하면 AI가 Keel의 타입 블록으로 변환해 즉시 오류를 검증받는 식의 작업이 가능할 수 있음 [추정].
2. (지원 시) 동일한 전략 아티팩트를 백테스트와 실거래에 그대로 재사용해, 백테스트 따로·실거래 코드 따로 작성하는 이중 작업을 줄일 수 있음 [추정].
3. (지원 시) 전략의 중간 계산 단계(DAG)를 하나씩 들여다보며 "왜 이 시점에 매수 신호가 났는지"를 사람이 직접 추적·검증할 수 있음 [추정].

## 개요
Keel은 원문 기준으로 **암호화폐 거래소(Hyperliquid) 전용 도구로 보이며, 주식 시장 적용 가능성은 검증되지 않았습니다.** 핵심 아이디어는 LLM이 자유 형식 코드를 직접 짜게 하지 않고, 타입과 시간 흐름(clock)을 가진 DAG(방향성 비순환 그래프) 구성요소만 조합하게 해서 "LLM이 실행 루프에서 직접 매매 결정"하거나 "LLM이 코드를 통째로 작성"할 때 생기는 오류(시계열/타임프레임 혼동, 재사용성 부족 등)를 줄이는 것입니다. 주식 트레이드에 적용하려면 Keel 자체의 데이터 소스·거래소 연동 범위를 먼저 확인해야 합니다.

## 구현 가능성 — **하**
근거: (1) 원문에 소개된 사례가 전부 암호화폐(Hyperliquid) 기반이며 주식 데이터/브로커 지원 언급이 전혀 없음. (2) Keel의 구현 언어, 설치 방식(패키지 매니저/CLI 존재 여부), 오픈소스 여부, 라이선스 등이 원문에 전혀 명시되어 있지 않아 현재로서는 실제 설치·실행 가능 여부조차 불확실함. (3) "출시 초기 도구로 추정"되며 Points/댓글 수가 매우 적어 커뮤니티 검증 사례도 부족함 [추정].

## 필요 도구
- **Keel 자체 공식 문서/리포지토리**: 접근 경로 [공식 문서 확인 필요] — 현재 확인된 공식 설치 URL 없음, 원문 출처(https://usekeel.io/how-it-works) 페이지에서 추가 정보 확인 필요
- **Hyperliquid API** (원문 명시 사례): 암호화폐 전용으로 보이며 주식 적용 시 대체 불가 가능성 높음 — 비용 무료(거래 수수료 별도)
- **(조건부) 증권사 API/브로커 커넥터**: Keel이 주식을 지원하지 않을 경우 별도로 직접 구축해야 하는 영역이며, 이는 Keel 자체 기능이 아님 [추정] — 예: 국내 증권사 Open API 등은 각 사별 유료/무료 정책 상이, [공식 문서 확인 필요]
- **백테스트 데이터 소스**: 주식 과거 시세 데이터 제공처 (무료/유료 혼재, 종목·주기에 따라 상이) [공식 문서 확인 필요]
- **AI 에이전트(LLM) 연동 환경**: Claude, GPT 등 API 키 발급 필요 — 사용량 기반 유료

## 구현 단계
1. **(필수, 1순위)** Keel 공식 리포지토리/문서를 직접 찾아 다음을 확인: ① 구현 언어(Python/Node/Rust 등), ② 설치 방식(CLI, 패키지, 소스 빌드 등), ③ 주식 데이터·브로커 지원 여부, ④ 라이선스·오픈소스 여부. — 이 단계 결과에 따라 아래 단계 전체가 갈라짐.
2. **(if 주식 미지원)** Keel을 그대로 쓸 수 없으므로, (a) Keel의 DSL 설계 철학(타입 있는 DAG, 자기 서술적 컴포넌트)만 참고해 직접 간단한 전략 스키마를 설계하거나, (b) 유사한 타입 안전 전략 프레임워크를 별도 조사해 대체재를 찾는다.
3. **(if 주식 지원 또는 확장 가능)** 로컬 개발 환경(맥북)에 Keel을 설치하고, Hyperliquid 외 주식 데이터 소스를 연결하는 어댑터/플러그인이 존재하는지 문서에서 확인한다. 없다면 직접 연동 코드를 작성해야 하며 이는 별도 공수가 필요하다.
4. **(공통)** 소규모 단일 전략(예: 단순 이동평균 교차)을 Keel DSL 문법에 맞춰 작성해보고, AI 에이전트(LLM)에게 자연어로 전략을 설명해 DSL 변환을 시도, 결과를 수동 검증한다.
5. **(공통)** 과거 주식 데이터로 백테스트를 돌려 보고, 동일 아티팩트를 실거래(모의투자 계좌 권장)에 연결했을 때의 동작 일치 여부를 확인한다 — 단, 실거래 연동 자체가 Keel 범위 밖일 가능성이 있음을 염두에 둘 것.
6. **(공통)** 실거래 전 반드시 모의투자/소액 계좌로 1~2주 이상 검증 기간을 거친다.

## 예상 공수
- 1단계(공식 자료 조사 및 주식 지원 여부 확인): 2~6시간, 난이도 하 — 단 자료가 부족할 경우 조사만으로 끝날 수도 있음
- 2~3단계(설치/대체재 탐색 또는 어댑터 구축): **선행 조사 결과에 따라 크게 변동** — 주식 미지원 시 직접 구축 범위가 넓어 10~40시간 이상 소요 가능 [추정], 지원 시 2~10시간 수준으로 축소될 가능성 [추정]
- 4~5단계(전략 작성·백테스트): 5~15시간, 난이도 중 [추정]
- 6단계(검증 운영): 지속적(최소 1~2주), 난이도 중
- **전체**: 불확실성이 매우 커서 단일 숫자 제시 지양 — 넓게 잡아 약 15~70시간 범위이며, 특히 주식 미지원으로 판명될 경우 "직접 구축" 비중이 커져 상한에 가까워질 가능성이 높음 [추정]

## 리스크/유의점
- **가장 큰 리스크**: Keel이 실제로 주식 시장을 지원하는지 자체가 확인되지 않았으며, 현재까지 공개된 사례는 암호화폐(Hyperliquid)뿐이므로 프로젝트 착수 전 반드시 공식 자료부터 확인해야 함.
- 도구의 성숙도(출시 초기로 추정, 커뮤니티 피드백 매우 적음)로 인해 문서 부족·API 변경 가능성이 있음 [추정].
- AI가 생성한 전략이라도 타입 검증을 통과했다고 해서 "수익성 있는 전략"을 보장하지는 않음 — 백테스트 과최적화(overfitting) 위험은 별개로 관리해야 함.
- 실거래 자금 투입 전 반드시 모의투자/소액 테스트를 거치고, 증권사 API 이용 약관·비용 구조를 별도로 확인할 것.
- 본 문서의 "구현 단계"는 Keel의 미확인 전제 위에 작성되었으므로, 1단계 조사 결과에 따라 전체 계획이 변경될 수 있음을 반드시 인지할 것.
