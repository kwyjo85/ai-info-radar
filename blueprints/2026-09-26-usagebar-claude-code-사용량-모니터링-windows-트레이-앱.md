# UsageBar – Claude Code 사용량 모니터링 트레이 앱

## 쉽게 말하면
차 계기판에 남은 연료량이 표시되듯, UsageBar는 Windows 작업표시줄 구석에 "이번 달 Claude Code를 얼마나 썼는지"를 숫자로 보여주는 작은 프로그램입니다. Claude Code를 계속 켜놓고 쓰다 보면 한도를 넘기거나 요금이 얼마 나왔는지 감을 잃기 쉬운데, 이 앱은 그걸 항상 눈에 보이게 해줍니다. 다만 이 앱 자체는 Windows 전용이라 사용자의 맥북에는 그대로 설치할 수 없습니다.

## 이걸로 할 수 있는 것
1. Claude Code로 여러 클라이언트 프로젝트(예: Jev 자동화 컨설팅)를 동시에 진행할 때, 프로젝트별/일별 사용량을 실시간으로 확인해 견적·정산 근거 자료로 쓴다.
2. 월 한도에 가까워지면 알림을 받아, 중요한 작업(예: 급한 자동화 배포)을 앞두고 사용량을 아껴 쓸지 판단한다.
3. 클라이언트에게 "이 자동화 작업에 Claude Code 사용량이 얼마나 들었는지"를 투명하게 보여주는 리포트 자료로 활용한다.

## 개요
UsageBar는 Claude Code CLI가 남기는 로컬 사용량/토큰 로그를 주기적으로 읽어 트레이 아이콘에 요약 수치(오늘/이번 달 사용량, 한도 대비 비율 등)를 표시하는 상주 앱입니다. 별도 대시보드를 열지 않아도 상시 모니터링이 가능해, 사용량 기반 요금제에서 예산 관리와 클라이언트 정산 투명성을 높이는 가치가 있습니다. 사용자의 "Jev 기반 자동화로 수익 창출" 흐름에서는, 이 도구 자체보다 "macOS용으로 직접 만들어서 다른 프리랜서/에이전시에 판매"하는 파생 기회가 더 크게 보입니다.

## 구현 가능성
**하 (원본 그대로 설치하는 것 기준) / 중 (macOS 포팅 기준)**
- 근거: UsageBar는 Windows 트레이(시스템 트레이 API, .NET/WinForms 계열)에 종속된 앱이라 macOS(Darwin)에는 실행 자체가 불가능합니다.
- 다만 Claude Code가 로컬에 남기는 사용량/세션 로그 구조를 파악하면, macOS 메뉴바 앱(SwiftBar/xbar 플러그인 또는 Swift 상주 앱)으로 동일한 기능을 직접 재구현하는 것은 난이도가 중간 수준입니다. 이미 유사한 오픈소스 로직(원본 리포지토리의 파싱 로직)을 참고할 수 있어 처음부터 설계할 필요는 없습니다.

## 필요 도구
- SwiftBar 또는 xbar (무료, macOS 메뉴바 플러그인 실행기)
- Claude Code CLI 로컬 사용량/로그 파일 (`~/.claude` 또는 `~/.config/claude` 하위, 무료·이미 보유)
- Python 3 또는 Swift/Node 스크립트 (무료, 로그 파싱용)
- UsageBar 원본 소스 (github.com/hsnsdt/usagebar, 파싱 로직 참고용, 무료·오픈소스 라이선스 확인 필요)
- (선택) macOS 알림센터 연동용 `terminal-notifier` (무료)
- (선택, 배포까지 고려 시) Apple Developer 계정 (연 99달러, 코드사이닝·공증용)

## 구현 단계
1. UsageBar 리포지토리를 클론해 사용량 로그를 어디서 읽는지(로그 파일 경로, 파싱 정규식) 코드 리뷰로 파악한다.
2. 로컬 맥북에서 Claude Code 실행 후 생성되는 로그/세션 파일 위치를 확인하고, 토큰·비용·한도 관련 필드가 있는지 직접 대조한다.
3. Python 또는 셸 스크립트로 해당 로그를 파싱해 "오늘 사용량 / 이번 달 사용량 / 한도 대비 %" 수치를 출력하는 CLI 프로토타입을 만든다.
4. SwiftBar용 플러그인 스크립트(1분 주기 실행, stdout 포맷 규칙)로 3단계 스크립트를 감싸 맥 메뉴바에 표시되게 한다.
5. 한도 임계치(예: 80%) 초과 시 `terminal-notifier`로 알림을 띄우는 로직을 추가한다.
6. 클라이언트별/프로젝트별 사용량을 구분하고 싶다면, 세션 시작 시 프로젝트명을 태깅하는 방식(예: 작업 디렉터리 기준 매핑)을 추가해 리포트 CSV로 뽑을 수 있게 한다.
7. 개인 사용을 넘어 판매를 고려한다면, SwiftBar 플러그인을 독립 macOS 메뉴바 앱(Swift/SwiftUI)으로 재작성하고 GitHub에 공개해 원 저자에게 크레딧을 남기며 커뮤니티 반응을 확인한다.

## 예상 공수
- 로그 파싱 프로토타입(1~3단계): 2~4시간, 난이도 하
- SwiftBar 연동 + 알림(4~5단계): 2~3시간, 난이도 중
- 프로젝트별 태깅/리포트 기능(6단계): 3~5시간, 난이도 중
- 독립 앱화 및 배포 준비(7단계): 최소 1~2일, 난이도 상 (Swift 앱 개발 경험 필요)

## 리스크/유의점
- Claude Code의 로컬 로그 포맷은 버전업마다 바뀔 수 있어, 파싱 로직이 깨질 위험이 있다.
- 원본 UsageBar가 공식 API가 아닌 로컬 파일을 읽는 방식이라면, 실제 청구 금액과는 오차가 있을 수 있으므로 "참고용 추정치"임을 명시해야 한다.
- 오픈소스 라이선스(원본 리포지토리)를 확인하지 않고 코드를 그대로 복제·재배포하면 라이선스 위반 소지가 있다.
- 판매/배포까지 갈 경우 Apple 공증 절차를 거치지 않으면 macOS Gatekeeper 경고로 사용자 신뢰도가 떨어진다.
