# 백테스트 룩어헤드 편향 문제 해결법

## 쉽게 말하면
백테스트에서 "어제 종가에 샀다"고 가정했는데, 실전에서는 "오늘 아침 시가에 산다"면 — 이건 마치 어제 마감된 경매가로 물건을 샀다고 계산했는데 실제로는 다음날 아침 가격으로 결제하는 것과 같습니다. 계산과 현실의 시점이 어긋나면서 전략의 실제 수익률이 백테스트와 크게 달라지는 현상이 바로 룩어헤드 편향(look-ahead bias)입니다.

## 이걸로 할 수 있는 것
1. 본인이 만든 추세추종 자동매매 전략의 백테스트 수익률과 실전 수익률 간 괴리 원인을 코드 레벨에서 찾아낼 수 있다.
2. 신호 발생 시점과 체결 시점을 명확히 분리한 백테스트 프레임워크를 구축해 향후 모든 전략에 재사용할 수 있다.
3. AI(바이브코딩)로 새 전략을 생성할 때마다 룩어헤드 편향 여부를 자동으로 점검하는 체크리스트/스크립트를 만들어 반복 검증할 수 있다.

## 개요
이 블루프린트는 AI로 생성한 주식 자동매매 전략의 백테스트 로직을 점검·수정하여, 신호가 발생한 캔들(봉)의 종가가 아닌 "다음 봉의 시가"로 체결하도록 구조를 바로잡는 작업을 자동화/표준화하는 것이다. 이를 통해 백테스트 성과와 실전 성과의 괴리를 줄이고, AI로 전략을 짤 때마다 반복되는 흔한 함정을 재발 방지 체크리스트로 관리할 수 있다는 점에서 가치가 있다.

## 구현 가능성
**상** — 근거: 문제 자체가 "신호 발생 봉"과 "체결 봉" 사이에 1봉의 시차를 두는 것으로, 백테스트 코드에서 인덱스를 한 칸 shift하는 수준의 수정이면 해결 가능하다. 원문의 [첫 단계]에서도 "신호 발생 다음 봉의 시가로 체결" 로직 수정을 제시하고 있어 구현 난이도가 높지 않다. 다만 기존 전략 전체를 재검증해야 하는 범위는 전략 개수에 따라 달라진다.

## 필요 도구
- **Python** (무료) — 백테스트 스크립트 수정 및 재실행
- **pandas, numpy** (무료, 오픈소스) — 시가/종가 shift 로직 구현
- **backtesting.py 또는 Backtrader 등 백테스트 프레임워크** (무료, 오픈소스) — 체결 가정 방식 확인 및 기본 체크리스트 통합 [공식 문서 확인 필요: 각 프레임워크의 기본 체결 가정(종가 vs 시가)이 버전별로 다를 수 있음]
- **한국투자증권(KIS) Open API** (무료, 증권계좌 연동 필요) — 실전 체결 데이터 및 일봉/시가 데이터 비교용 [공식 문서 확인 필요: 정확한 API 명칭 및 엔드포인트는 KIS Developers 사이트 확인 필요]
- **Jupyter Notebook / VS Code** (무료) — 로컬(맥북)에서 코드 검증 및 시각화
- **Git** (무료) — 백테스트 코드 버전 관리, 수정 전후 비교

## 구현 단계
1. 기존 백테스트 코드에서 "신호 발생 봉"과 "매수/매도 체결 봉"이 동일한 행(row)으로 계산되는지 확인한다 (예: `df.loc[i, 'close']`로 진입가를 쓰고 있다면 룩어헤드 편향 가능성이 높다).
2. 신호가 발생한 봉의 인덱스를 `i`라고 할 때, 체결가는 `df.loc[i+1, 'open']`(다음 봉의 시가)을 참조하도록 코드를 수정한다.
3. 수정 후 동일한 10년치 일봉 데이터로 백테스트를 재실행하고, 수정 전/후 수익률·승률·MDD를 비교해 괴리폭을 확인한다.
4. 룩어헤드 편향 점검 항목(신호-체결 시차, 지표 계산에 미래 데이터 포함 여부, 슬리피지/수수료 반영 여부 등)을 체크리스트로 문서화해 백테스트 프레임워크 진입 전 필수 확인 단계로 고정한다.
5. KIS Open API(또는 사용 중인 증권사 API) 샘플 코드의 체결 가정 방식(시가 체결 vs 종가 체결)을 확인하여 백테스트 로직과 실전 주문 로직이 일치하는지 교차 검증한다 [공식 문서 확인 필요].
6. 실전 소액 매매(페이퍼 트레이딩 또는 최소 단위 실거래)로 1~2주간 체결가 비교 로그를 쌓아, 백테스트 대비 괴리가 허용 범위 내로 줄었는지 재검증한다.
7. 맥북 환경에서 cron 또는 launchd를 이용해 매일 장 마감 후 백테스트를 자동 재실행하고, 괴리 지표를 로그 파일로 쌓아 모니터링한다 [추정: 실행 주기는 전략 특성에 따라 조정 필요].

## 예상 공수
- 기존 백테스트 코드 룩어헤드 편향 진단 및 수정: 2~4시간
- 체크리스트 문서화 및 프레임워크 통합: 1~2시간
- KIS API 샘플과 체결 로직 교차 검증: 2~3시간 (API 신청/승인 대기 시간 별도)
- 실전 검증(소액/페이퍼 트레이딩) 로그 수집: 1~2주 소요 (작업 시간 자체는 일 10~15분 모니터링 수준)
- **난이도: 중** — 코드 수정 자체는 쉬우나, 기존 전략 전체를 재검증하고 실전 데이터로 괴리를 확인하는 과정에 시간이 걸림.

## 리스크/유의점
- 신호-체결 시차를 1봉 뒤로 미루는 수정만으로는 슬리피지, 거래량 부족, 갭 상승/하락 등 다른 괴리 요인을 모두 해결하지 못할 수 있다 [추정].
- 일봉 단위 백테스트는 봉 내부의 가격 변동(고가/저가 터치 순서)을 알 수 없어 손절/익절 로직에서도 별도의 룩어헤드 편향이 숨어 있을 수 있으므로 봉 내부 체결 가정도 함께 점검해야 한다.
- KIS 등 증권사 API의 실전 체결 방식과 백테스트 가정이 완전히 일치하지 않을 수 있으므로, 반드시 소액 실매매 또는 모의투자로 최종 검증하기 전에는 자동매매를 본 자금으로 확대하지 않는다.
- 백테스트 프레임워크(backtesting.py, Backtrader 등)마다 기본 체결 가정이 다를 수 있으므로 사용 중인 프레임워크의 공식 문서를 반드시 확인한다 [공식 문서 확인 필요].
- 과거 데이터 기반 백테스트 개선이 미래 수익을 보장하지 않으며, 본 작업은 "백테스트 신뢰도 향상"이지 "수익률 보장"이 아님을 유의한다.
