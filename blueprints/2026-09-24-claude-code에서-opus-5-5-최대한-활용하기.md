# Claude Code에서 상위 모델(Opus) 최대한 활용하기

## 쉽게 말하면
Claude Code에서 어떤 모델을 쓰느냐에 따라 "일 시키는 방식"도 달라져야 합니다. 비유하자면 신입 인턴에게는 세세하게 지시해야 하지만, 경력 많은 수석 엔지니어에게는 목표와 맥락만 던져주고 알아서 판단하게 두는 게 더 효율적인 것과 같습니다. 이 글은 가장 똑똑한 모델(Opus 계열)을 Claude Code에서 쓸 때 어떻게 지시하고, 어떤 작업에 배정해야 비용 대비 결과가 최대화되는지를 다룹니다.

## 이걸로 할 수 있는 것
1. ai-info-radar의 채점(haiku)·블루프린트 생성(sonnet) 역할 분담처럼, 반복 단순 작업은 저가 모델에 맡기고 설계·리뷰·복잡한 리팩토링만 Opus급에 위임해 구독/API 비용을 줄일 수 있습니다.
2. 클라이언트 외주에서 "복잡한 버그 원인 분석"이나 "레거시 코드 아키텍처 재설계" 같은 고난도 작업에만 Opus를 투입해, 같은 구독으로 더 어려운(더 비싼) 프로젝트를 수주할 수 있습니다.
3. Claude Code의 서브에이전트(Agent) 구성에서 "설계·검토는 Opus, 단순 탐색·코드 검색은 Explore/Haiku"로 역할을 나눠, 개인 자동화 파이프라인의 품질과 속도를 동시에 개선할 수 있습니다.

## 개요
이 정보는 Claude Code 안에서 최상위 모델을 어떤 프롬프트 스타일·작업 분배 전략으로 써야 성능을 최대로 끌어내는지에 관한 실무 팁입니다. 핵심 가치는 "무조건 최고 모델을 쓰는 것"이 아니라, 모델별 강점에 맞춰 작업을 배정하고 지시 방식을 바꾸는 것만으로 같은 구독 비용에서 더 높은 완성도와 더 빠른 처리 속도를 동시에 얻을 수 있다는 점입니다. 사용자의 관심사인 "Jev 포함 AI 업무 자동화·Claude Code 활용 수익화" 관점에서는, 이 최적화 노하우 자체가 외주·컨설팅에서 팔 수 있는 "AI 자동화 설계 역량"이 됩니다.

## 구현 가능성: 상
- 사용자는 이미 claude CLI 헤드리스 모드로 haiku(채점)/sonnet(블루프린트) 역할 분담을 운영 중이라, 모델 배정 전략을 여기에 한 단계(Opus 추가) 얹는 것은 기존 구조를 확장하는 수준입니다.
- 별도 신규 인프라나 API 계약 없이, 기존 Claude 구독/설정 파일(.env, launchd plist) 수정만으로 적용 가능합니다.
- 다만 원본 블로그 글 자체는 HN 반응이 거의 없어(포인트 3, 댓글 0) 구체적 기법의 신뢰도는 직접 검증이 필요합니다.

## 필요 도구
- **Claude Code CLI** — 무료(기존 Anthropic 구독 재사용), 모델 지정 옵션(`--model`) 활용
- **Claude API 키** (선택) — 유료, 헤드리스 대량 실행 시 구독 한도 초과 대비 및 모델별 과금 분리 관리용
- **`.claude/agents/*.md` 서브에이전트 정의 파일** — 무료, 역할별 모델 지정(Opus/Sonnet/Haiku) 설정용
- **CLAUDE.md / .claude/settings.json** — 무료, 프로젝트별 기본 모델·권한 정책 명시용
- **사용량 모니터링 스크립트(자체 제작)** — 무료, 모델별 토큰·비용 추적용

## 구현 단계
1. 현재 ai-info-radar에서 Claude Code가 수행 중인 작업(수집 스크립트 수정, 블루프린트 생성, 대시보드 배포 디버깅 등)을 "단순 반복" vs "설계·판단 필요"로 분류한다.
2. `.claude/agents/` 아래 서브에이전트별로 모델을 명시적으로 지정한다 — 예: 코드 탐색용 Explore는 Haiku/Sonnet, 아키텍처 리뷰·복잡한 버그 분석용 에이전트는 Opus로 model frontmatter 설정.
3. Opus에게 작업을 맡길 때는 세부 절차를 나열하지 말고 "목표 + 제약 조건 + 성공 기준"만 전달하는 프롬프트 스타일로 바꿔, 모델이 스스로 계획을 세우게 한다(예: "이 버그를 고쳐라" 대신 "N개월간 재현 안 되던 이 경합 조건 버그의 근본 원인을 찾고, 재발 방지책까지 제안하라").
4. launchd 30분 사이클 중 "채점"은 Haiku, "블루프린트 생성"은 Sonnet을 유지하되, 주 1회 정도 "이번 주 파이프라인 개선점 검토" 같은 고난도 작업만 Opus로 헤드리스 실행하는 파일럿을 추가한다.
5. 모델별 실행 시간·토큰 사용량·결과 품질(수동 평가)을 1~2주 기록해, 어떤 작업 유형에서 Opus 승급이 실제로 값어치를 하는지 데이터로 확인한다.
6. 검증된 "작업 유형별 모델 배정 + 프롬프트 스타일" 노하우를 체크리스트/템플릿으로 정리해, Claude Code 도입 컨설팅 서비스의 차별화 포인트(비용 최적화 노하우)로 패키징한다.

## 예상 공수
- 1~2단계(작업 분류, 서브에이전트 모델 지정): 2~3시간, 난이도 낮음 — 기존 `.claude/agents/` 구조 활용
- 3단계(프롬프트 스타일 전환 연습): 1~2시간, 난이도 낮음~중간 — 시행착오로 감을 잡는 과정
- 4~5단계(파일럿 운영 및 데이터 기록): 1~2주 관찰 기간, 실작업 시간은 2~3시간, 난이도 중간
- 6단계(컨설팅 자료화): 3~4시간, 난이도 중간 — 기술보다 정리·문서화 비중

## 리스크/유의점
- Opus급 모델은 토큰당 비용이 높으므로, 작업 분류 없이 모든 사이클에 적용하면 구독 한도 초과나 API 과금 급증으로 이어질 수 있습니다.
- 원본 글의 구체적 기법(프롬프트 문구, 파라미터 설정 등)이 HN에서 검증되지 않은 상태(댓글 0)이므로, 그대로 맹신하지 말고 소규모 파일럿으로 직접 효과를 확인한 뒤 확대해야 합니다.
- 자동 헤드리스 실행에서 Opus에게 넓은 재량(계획 수립·자율 판단)을 주는 만큼, 쓰기 권한 범위를 좁게 유지하고 예상 밖의 대규모 변경(파일 삭제, force-push 등)이 없는지 결과를 반드시 검토해야 합니다.
