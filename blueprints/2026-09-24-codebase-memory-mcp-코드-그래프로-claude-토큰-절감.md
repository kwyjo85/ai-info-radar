# codebase-memory-mcp – 코드 그래프로 Claude 토큰 절감

## 쉽게 말하면
내 코드 전체를 미리 "지도"로 만들어두고, Claude가 코드에 대해 물어볼 때마다 전체 파일을 다시 읽는 대신 그 지도만 빠르게 훑어보게 하는 도구입니다. 마치 매번 도서관 전체를 뒤지는 대신, 미리 만들어둔 색인 카드를 보고 원하는 책 위치를 바로 찾아가는 것과 같습니다. 결과적으로 같은 질문을 훨씬 적은 토큰(=비용)과 시간으로 처리할 수 있습니다.

## 이걸로 할 수 있는 것
1. ig-dashboard 프로젝트에서 "collector.js의 scrapePost 함수를 어디서 호출하는지" 같은 질문을 Claude Code에 던졌을 때 전체 파일을 다 읽지 않고 즉시 답을 받는다.
2. 고객사 코드 리뷰·유지보수 대행 작업 시, 매번 프로젝트 전체를 Claude에 붙여넣지 않아도 되어 API 비용을 줄이고 응답 속도를 높여 더 많은 건을 처리한다(=시간당 처리량 증가 → 수익성 개선).
3. 여러 클라이언트의 대형 레거시 코드베이스를 분석·리팩터링해주는 "AI 코드 컨설팅" 서비스를 제공할 때, 토큰 절감분을 원가 경쟁력으로 활용해 견적을 낮추거나 마진을 높인다.

## 개요
로컬 코드베이스(JS, Python 등 158개 언어 지원)를 파싱해 함수·호출관계·의존성을 그래프 DB 형태로 인덱싱하고, 이를 MCP 서버로 노출해 Claude Code가 코드 질문 시 전체 파일 대신 그래프 조회 결과만 받아가게 합니다. 핵심 가치는 "토큰/비용 절감"과 "응답 속도 향상"이며, 특히 Claude Code를 이용한 유료 코드 작업(외주, 컨설팅, 유지보수 리테이너)을 하는 사용자에게는 처리 건수당 원가를 낮춰 수익률을 직접 개선하는 효과가 있습니다.

## 구현 가능성 — 중
- 단일 정적 바이너리 + MIT 라이선스라 설치 자체는 쉽고(상), Claude Code의 `claude mcp add` 명령으로 표준적인 MCP 등록이 가능해 통합 난이도는 낮음.
- 다만 "99% 토큰 절감", "sub-ms 쿼리" 등 핵심 수치가 README에 벤치마크 방법론 없이 제시되어 있어(인스타 대시보드 평가에서도 "과장 3"으로 지적) 실제 효과는 프로젝트 규모·언어에 따라 편차가 클 수 있음. 소규모 개인 프로젝트(ig-dashboard 수준)에서는 체감 절감폭이 마케팅 수치보다 작을 가능성 있음.
- ★44,556에 오늘 +190 증가라는 빠른 성장세는 커뮤니티 검증이 진행 중임을 시사하나, 아직 신생 프로젝트라 엣지케이스(대형 모노레포, 비표준 언어 조합)에서의 안정성은 미검증.

## 필요 도구
- **codebase-memory-mcp 바이너리** (GitHub Releases, 무료·MIT 라이선스)
- **Claude Code CLI** (이미 보유, `claude mcp add` 명령 사용 — 무료)
- **macOS 터미널** (다운로드한 바이너리 실행 권한 설정용, 무료)
- (선택) **hyperfine 또는 간단한 쉘 스크립트** — 도입 전후 토큰 사용량·응답 시간 비교용 (무료)
- (선택) **Claude API 사용량 대시보드** (console.anthropic.com) — 토큰 절감 효과를 실측 확인 (무료, 기존 계정)

## 구현 단계
1. https://github.com/DeusData/codebase-memory-mcp 의 Releases 페이지에서 macOS(darwin, arm64) 정적 바이너리를 다운로드한다.
2. 다운로드한 바이너리에 `chmod +x`로 실행 권한을 부여하고 `/usr/local/bin` 또는 개인 bin 디렉터리에 배치한다.
3. `claude mcp add codebase-memory <바이너리 경로>` 명령으로 Claude Code에 MCP 서버로 등록한다.
4. ai-info-radar 저장소(현재 프로젝트) 루트에서 인덱싱 명령을 실행해 collector.js, server.js 등 JS 파일들을 지식 그래프로 변환한다.
5. Claude Code 세션에서 "collector.js의 scrapePost 함수는 어디서 호출되는가?" 같은 실제 질문을 던져 응답 속도와 정확도를 기존(파일 전체 읽기) 방식과 비교한다.
6. Claude 콘솔의 사용량 대시보드에서 인덱싱 전/후 동일 유형 질문의 토큰 소비량을 기록해 실제 절감률을 계산한다(마케팅 수치인 99%를 그대로 믿지 않고 직접 검증).
7. 절감 효과가 확인되면, 현재 진행 중이거나 예정된 외주·컨설팅 프로젝트(특히 대형 레거시 코드베이스)에 동일하게 적용해 처리 속도·원가 개선을 실제 견적/납기에 반영한다.
8. 여러 클라이언트 프로젝트를 동시에 다룰 경우, 프로젝트별로 별도 인덱스를 유지하도록 설정해 그래프가 섞이지 않게 관리한다.

## 예상 공수
- 설치·MCP 등록: 30분~1시간 (난이도: 하)
- ai-info-radar 인덱싱 및 1차 체감 테스트: 1~2시간 (난이도: 하)
- 토큰 절감 실측 비교(전/후 데이터 수집·분석): 2~3시간 (난이도: 중)
- 총 예상 공수: 반나절(4~6시간), 전체 난이도: 중하

## 리스크/유의점
- 핵심 셀링포인트인 "99% 토큰 절감" 수치는 미검증 벤치마크이므로, 이를 근거로 고객에게 비용 절감을 먼저 약속하지 말고 직접 측정 후 보수적으로 안내할 것.
- 신생 프로젝트(단일 개발사, C 언어 구현)라 유지보수 중단·호환성 붕괴 리스크가 있으므로, 클라이언트 프로젝트의 핵심 워크플로우를 이 도구에 전적으로 의존시키지 말고 fallback(기존 파일 읽기 방식)을 남겨둘 것.
- 코드 그래프에 클라이언트의 민감한 소스코드가 로컬에 인덱싱되므로, 여러 고객사 프로젝트를 다룰 때 인덱스 파일이 서로 섞이거나 유출되지 않도록 프로젝트별 디렉터리 격리와 삭제 정책을 명확히 할 것.
