# "LLM은 교정만, 문장은 사람이" — 프루프리딩 도구로 jev 카피 품질관리 서비스 상품화

## 개요
Thomas Ptacek는 LLM에게 문장을 통째로 맡기지 말고 오탈자·문법·사실관계만 지적하게 하는 "교정 전용" 사용법을 제안하며, 공개 프루프리딩 프롬프트와 시스템 프롬프트까지 공유했다. jev에서 글쓰기·카피라이팅 관련 외주를 받는 입장에서, 이 원칙을 구현한 로컬 도구를 만들면 "AI 특유의 문체 냄새 없이 사람이 직접 쓴 글의 품질만 높여주는" 차별화된 교정·감수 서비스를 상품화할 수 있다.

## 구현 가능성 — 상
- Simon Willison의 프루프리딩 프롬프트와 Ptacek의 시스템 프롬프트가 모두 원문/HN 댓글에 공개되어 있어 별도 리서치 없이 바로 재료로 쓸 수 있음.
- Claude API + Python SDK 조합만으로 로컬에서 완결되는 구조라 서버 인프라나 복잡한 배포가 불필요함(근거: 텍스트 입력 → API 호출 → 구조화된 응답 출력이라는 단순 파이프라인).
- 핵심 난이도는 "문장을 재작성하지 않고 지적만 하게 강제하는" 프롬프트/출력 형식 설계뿐이며, 이는 프롬프트 엔지니어링 수준의 작업이라 기술적 장벽이 낮음.

## 필요 도구
- **Anthropic Claude API (Claude Sonnet 5)** — 교정 로직의 핵심 엔진, 유료(토큰 사용량 과금)
- **Python 3 + anthropic SDK** — 로컬 CLI 스크립트 작성, 무료
- **Simon Willison 프루프리딩 프롬프트**(https://simonwillison.net/guides/agentic-engineering-patterns/prompts/#proofreader) — 공개 자료, 무료
- **Thomas Ptacek 시스템 프롬프트**(HN 댓글 공개, https://news.ycombinator.com/item?id=49747070#49753616) — 공개 자료, 무료
- **difflib(표준 라이브러리) 또는 diff-match-patch** — 원문 대비 지적 위치 하이라이트, 무료
- **(선택) Streamlit** — 클라이언트에게 보여줄 간단한 웹 리포트 UI, 무료
- **jev 계정** — 서비스 판매 채널, 가입 무료·거래 시 수수료 발생

## 구현 단계
1. Simon Willison의 프루프리딩 프롬프트와 Thomas Ptacek의 시스템 프롬프트 원문을 가져와 비교·통합하고, "원문 문장을 대신 재작성하지 말고 위치·문제유형·제안만 구조화해 출력하라"는 제약을 명시적으로 추가한 교정 전용 프롬프트 초안을 작성한다.
2. `anthropic` SDK로 로컬 CLI 스크립트(`proofread.py`)를 작성한다. 입력은 텍스트/마크다운 파일, 출력은 `{위치, 문제유형(오탈자/문법/사실오류/어색한 표현), 지적 내용}` 형태의 JSON으로 강제해 LLM이 문장을 통째로 뱉지 못하게 스키마를 고정한다.
3. `difflib`로 원문에서 지적된 구간을 찾아 터미널 컬러 출력 또는 간단한 HTML 리포트로 하이라이트하는 기능을 추가한다 — "도구가 대신 써주지 않고 짚어만 준다"는 걸 클라이언트가 눈으로 확인할 수 있게 한다.
4. 본인이 과거에 쓴 블로그 글이나 원고 3~5건으로 파일럿을 돌려 오탐률과 실제 오류 발견율을 확인하고, 2단계 프롬프트를 반복 튜닝한다.
5. jev에 "AI 문체 없는 글쓰기 교정/카피 감수 서비스"로 상품 페이지를 개설한다. 차별점(LLM은 지적만 하고 문장은 100% 사람이 직접 쓴다는 원칙)을 홍보 문구의 핵심으로 명시한다.
6. 실제 의뢰가 들어오면 CLI 리포트를 뽑아 사람이 최종 반영 여부를 판단한 뒤, "교정 리포트 + 수정 반영본"을 함께 납품해 신뢰도와 재구매율을 높인다.

## 예상 공수
- 프롬프트 통합·출력 스키마 설계: 3~4시간 (난이도 중)
- CLI 스크립트 + diff 하이라이트 기능: 2~3시간 (난이도 중)
- 파일럿 테스트 및 프롬프트 튜닝: 2~3시간 (난이도 중)
- jev 상품 페이지 개설·홍보 문구 작성: 1~2시간 (난이도 하)
- 총 8~12시간

## 리스크/유의점
- Claude API 비용은 텍스트 길이에 비례해 누적되므로, 장문 원고(출판물·보고서) 의뢰 시 사전에 토큰 기준 원가를 계산해 견적 단가에 반영해야 마진이 남는다.
- "교정 과정에 LLM이 관여한다"는 사실을 클라이언트에게 고지할지 여부는 업종(출판·학술 등)별 민감도가 다르므로 계약 전 명확히 짚고 넘어가야 한다.
- LLM 교정도 오탐·누락이 발생할 수 있어, 최종 책임은 사람 검수자에게 있다는 점을 서비스 약관에 명시해 분쟁 소지를 줄일 것.
- Ptacek의 공개 프롬프트를 상업 서비스에 재사용할 때는 원저자 출처를 남기는 등 최소한의 윤리적 관행을 지키는 것이 좋다.
- jev 같은 프리랜서 플랫폼은 카테고리별로 "AI 활용 서비스"에 대한 별도 정책·수수료 구조가 있을 수 있으므로 상품 등록 전 확인이 필요하다.
