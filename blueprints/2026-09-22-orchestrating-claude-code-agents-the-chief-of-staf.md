#클로드 코드 에이전트 오케스트레이션: Chief of Staff 패턴 구현

## 개요
여러 개의 Claude Code 세션(에이전트)을 하나의 "수석보좌관(Chief of Staff)" 세션이 조율하여, 작업 배분·진행 모니터링·결과 취합을 자동화하는 패턴입니다. 개인 MacBook에서는 여러 저장소/작업을 동시에 처리하거나, 반복적인 조사·리뷰·수집 작업을 백그라운드 에이전트에 위임하고 하나의 창구에서 관리하는 데 활용할 수 있습니다. AI Info Radar 프로젝트처럼 수집→처리→요약 파이프라인이 있는 경우, 각 단계를 서브에이전트로 분리하고 상위 세션이 스케줄링과 예외처리를 담당하는 구조로 확장 가능합니다.

## 구현 가능성 — 상
- Claude Code는 이미 Agent(서브에이전트), SendMessage(세션 간 통신), tmux/백그라운드 세션 관리를 네이티브로 지원합니다.
- 개인 MacBook만으로 launchd/cron + 터미널 멀티플렉서(tmux)로 상시 오케스트레이터를 띄울 수 있어 별도 서버·클라우드 인프라가 필요 없습니다.
- 이 저장소에는 이미 `scripts/radar_cycle.sh`, `launchd/` 디렉토리가 존재해 유사한 주기적 자동화 패턴이 이미 구축되어 있어, 확장 난이도가 낮습니다.

## 필요 도구
- **Claude Code CLI** (이미 사용 중, 유료 — Anthropic API/구독 필요)
- **tmux** (무료, macOS `brew install tmux`) — 여러 세션을 백그라운드에서 유지
- **launchd** (macOS 내장, 무료) — 정기 실행 스케줄링 (이미 `launchd/` 디렉토리 존재)
- **Claude Code Agent SDK / Agent 툴** (CLI 내장, 별도 비용 없음, API 토큰 비용만 발생)
- **jq** (무료) — 에이전트 출력 JSON 파싱
- **SQLite** (이미 프로젝트에서 사용 중, 무료) — 에이전트 작업 상태·결과 로그 저장
- (선택) **ntfy.sh 또는 macOS 알림센터 연동 스크립트** — 오케스트레이터가 작업 완료 시 알림 (무료)

## 구현 단계
1. **역할 정의**: "Chief of Staff" 세션이 수행할 조율 작업 목록화 — 예: (a) 수집기 실행 트리거, (b) 처리기 결과 검수, (c) 실패 시 재시도 지시, (d) 일일 요약 브리핑 생성.
2. **작업 큐 스키마 설계**: 기존 SQLite DB에 `tasks` 테이블 추가 (`id, type, status, assigned_agent, created_at, result_path`). 상태값: `pending/running/done/failed`.
3. **서브에이전트 프롬프트 템플릿 작성**: 수집기/처리기/요약기 각각에 대한 독립 실행 가능한 프롬프트를 `.claude/agents/` 또는 스크립트 형태로 고정.
4. **오케스트레이터 스크립트 작성**: `scripts/chief_of_staff.sh` — SQLite에서 pending 작업을 읽고, Claude Code CLI를 `--print` 또는 headless 모드로 호출해 서브에이전트를 실행, 결과를 DB에 기록.
5. **tmux 세션 관리**: 오케스트레이터를 tmux 세션(`radar-chief`)에서 상시 구동하거나, launchd plist로 5~10분 간격 폴링 실행 (`launchd/` 기존 plist 참고해 신규 plist 추가).
6. **실패 처리 로직**: 3회 재시도 후 실패 상태로 마킹하고, 텔레그램 봇(기존 4단계 구현)을 통해 사람에게 알림.
7. **일일 브리핑 자동화**: 모든 작업 완료 후 Chief of Staff가 결과를 취합해 Streamlit 대시보드(기존 5단계)에 요약 카드로 반영, 동시에 텔레그램으로 다이제스트 전송.
8. **로그/관측**: 각 서브에이전트 실행 로그를 `logs/YYYY-MM-DD/` 형태로 저장, 오케스트레이터가 이상 패턴(무한 재시도, 응답 없음) 감지 시 자체 중단.
9. **테스트**: 수동으로 pending 작업 3~5개 넣고 1회 사이클 실행, 상태 전이와 알림이 정상 작동하는지 검증 후 launchd 등록.

## 예상 공수
- 설계 및 스키마 작업: 2~3시간 (난이도: 하)
- 오케스트레이터 스크립트 + tmux/launchd 연동: 4~6시간 (난이도: 중)
- 서브에이전트 프롬프트 템플릿화 및 headless 호출 검증: 3~4시간 (난이도: 중, Claude Code CLI의 non-interactive 모드 옵션 파악 필요)
- 알림/대시보드 연동: 2~3시간 (난이도: 하, 기존 텔레그램·Streamlit 코드 재사용)
- 전체 통합 테스트 및 안정화: 2~3시간 (난이도: 중)
- **총합: 약 13~19시간 (2~3일 분량 작업)**

## 리스크/유의점
- **API 비용 누적**: 오케스트레이터가 폴링 주기마다 서브에이전트를 호출하면 토큰 사용량이 빠르게 증가할 수 있음 — 폴링 간격과 작업 배치 크기를 보수적으로 설정.
- **무한 루프/과다 재시도**: 실패한 작업이 반복 재시도되며 API 호출을 낭비하지 않도록 최대 재시도 횟수와 백오프를 반드시 구현.
- **동시성 문제**: SQLite는 다중 프로세스 동시 쓰기에 취약하므로 WAL 모드 활성화 및 트랜잭션 처리 필요.
- **headless 모드 안정성**: Claude Code CLI를 스크립트에서 비대화형으로 호출할 때 세션 타임아웃, 인증 만료(macOS 로그인 세션 종료 시 launchd 실행 제약) 문제를 사전에 점검.
- **보안**: API 키/텔레그램 토큰이 스크립트나 로그에 평문 노출되지 않도록 환경변수 또는 macOS Keychain 사용 권장.
- **디버깅 난이도**: 다중 에이전트 체인에서 오류 발생 시 어느 단계에서 실패했는지 추적이 어려울 수 있으므로 단계별 로깅을 처음부터 상세히 설계할 것.
