# MCP 서버 인증 실패로 디렉토리 노출 안 되는 문제 — 진단 도구화

## 개요
MCP(Model Context Protocol) 서버가 initialize 요청에서 401을 반환하면 Claude/Anthropic 디렉토리나 다른 클라이언트가 해당 서버의 tool 목록을 읽지 못해 "보이지 않는" 상태가 된다. 이는 자신이 만든 MCP 서버(예: Jev 연동, 사내 API 래퍼)를 배포할 때 흔히 겪는 함정으로, 이 문제를 진단·검증해주는 간단한 CLI/체크리스트 도구를 만들어 MCP 서버 개발자들에게 판매하거나 컨설팅 자료로 활용할 수 있다.

## 구현 가능성 — 중
MCP initialize 핸드셰이크와 인증 헤더 처리는 사양이 명확해 로컬에서 재현·검증 스크립트 작성은 어렵지 않다(상 수준 난이도). 다만 "제품화"해서 수익을 내려면 대상 고객(MCP 서버 개발자) 확보와 배포 채널이 필요해 시장 검증 난이도가 있어 전체는 "중"으로 평가.

## 필요 도구
- Claude Code (무료 사용 중 도구) — 진단 스크립트/CLI 작성
- Node.js 또는 Python (무료) — MCP 클라이언트 시뮬레이터 구현
- `@modelcontextprotocol/sdk` (무료, npm) — MCP 프로토콜 표준 구현체
- ngrok 또는 Cloudflare Tunnel (무료 티어) — 로컬 MCP 서버를 임시 공개 URL로 노출해 테스트
- Jev API (구독/사용료 발생 가능) — 진단 결과 요약, 리포트 문구 자동 생성에 활용
- GitHub (무료) — 오픈소스 CLI 공개, 신뢰도/포트폴리오 확보용
- Gumroad 또는 Stripe Payment Link (무료 가입, 거래 수수료) — 유료 진단 리포트/컨설팅 판매

## 구현 단계
1. MacBook에 Node.js 환경에서 `@modelcontextprotocol/sdk`로 최소 MCP 클라이언트를 작성, `initialize` 요청을 보내고 응답 상태 코드(401/403/200)와 헤더를 로깅하는 스크립트(`mcp-doctor.js`) 제작.
2. 원문 블로그(useanima.sh)에 설명된 401 발생 시나리오(인증 헤더 누락, OAuth 플로우 미스매치, 세션 토큰 미갱신 등)를 재현하는 테스트 케이스 3~5개를 로컬 mock 서버로 구성.
3. Claude Code로 `mcp-doctor.js`를 CLI 도구화 — `npx mcp-doctor <server-url>` 형태로 실행하면 (a) initialize 성공 여부, (b) 401 발생 시 원인 추정(헤더 누락/토큰 만료/CORS 등), (c) 수정 가이드를 콘솔에 출력하도록 구현.
4. Jev API를 연동해 진단 결과(JSON)를 입력받아 비개발자도 이해할 수 있는 한국어/영어 리포트 문장을 자동 생성하는 기능 추가(선택 사항, 리포트 판매 상품화 시 유용).
5. GitHub에 오픈소스로 공개 + README에 "왜 이 문제가 디렉토리 노출을 막는가" 설명 작성, HN/Reddit r/mcp 등에 공유해 초기 사용자 확보.
6. 무료 도구 사용자 중 "직접 진단해줄 사람"이 필요한 경우를 위해 Gumroad에 "MCP 서버 인증 진단 + 수정 컨설팅 (1회, 유료)" 상품 페이지 개설.
7. 실제 의뢰가 들어오면 Claude Code를 활용해 고객 서버 코드를 분석하고 401 원인을 찾아 PR 형태로 수정안 제공, 시간당 또는 건당 요금 청구.

## 예상 공수
- CLI 진단 도구 MVP: 4~6시간 (난이도: 중)
- 오픈소스 공개 + README/배포: 2~3시간 (난이도: 하)
- Jev 연동 리포트 생성 기능: 2~3시간 (난이도: 중)
- Gumroad 상품 페이지 및 판매 채널 셋업: 1~2시간 (난이도: 하)
- 총합: 약 9~14시간 (초기 MVP 기준, 수익화까지는 마케팅 별도 소요)

## 리스크/유의점
- 원본 기사는 포인트 1, 댓글 0개로 화제성이 낮아 시장 수요가 검증되지 않음 — MVP 공개 후 반응을 먼저 확인하고 유료화는 나중에 결정할 것.
- MCP 프로토콜/디렉토리 정책이 빠르게 변화 중이라(2026년 초 기준) 진단 로직이 금방 구식화될 수 있음 — 유지보수 비용 고려.
- 실제 고객 서버를 진단할 때 인증 토큰·API 키 등 민감정보를 다루게 되므로, 로그에 시크릿이 남지 않도록 마스킹 처리 필수.
- 컨설팅 영업까지 이어지려면 별도의 홍보/네트워킹이 필요해 "도구 제작"만으로는 수익 창출이 제한적임.
