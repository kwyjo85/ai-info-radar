# AI 보조역할 자동매매 설계로 API 비용 절감

## 쉽게 말하면
자동매매를 "AI가 매번 알아서 사고팔라"고 맡기면 똑똑한 비서를 매 순간 불러서 물어보는 것과 같아서 비용이 많이 듭니다. 대신 정해진 규칙(퀀트 로직)을 기본 판단 기준으로 삼고, AI는 가끔 "이거 맞는지 한번 봐줘" 하는 보조 역할로만 쓰면 비용을 크게 줄이면서도 판단의 질을 어느 정도 유지할 수 있습니다.

## 이걸로 할 수 있는 것
1. 매일 장 시작 전 보유 종목에 대해 미리 정해둔 매매 규칙이 자동으로 매수/매도 신호를 계산하게 한다.
2. 규칙이 애매한 상황(신호가 경계선에 걸치는 경우 등)에만 AI를 호출해 보조 판단이나 설명을 받는다.
3. 재무정보 데이터를 자동으로 가져와 매매 판단 화면에 함께 표시해 사람이 최종 확인할 때 참고하게 한다.

## 개요
이 블루프린트는 "AI가 매매를 전부 결정"하는 구조를 "사용자가 정의한 매매 규칙이 기본 판단, AI는 보조 설명/검토"로 바꾸는 자동화를 다룹니다. 핵심 가치는 실시간 AI 호출 빈도를 줄여 API 비용을 절감하면서도, 규칙만으로 놓칠 수 있는 애매한 상황에서 AI의 보조 판단을 선택적으로 활용하는 것입니다.

## 구현 가능성: 중
- 매매 규칙 자체를 코드로 작성하고 백테스트/모의투자로 검증하는 작업은 개인 환경에서도 가능하지만, 전략 설계·검증에 상당한 시행착오가 필요합니다.
- 증권사 Open API 연동, 실시간 데이터 수신, 실계좌 자동매매까지 가면 계좌 인증·주문 처리·예외 상황 대응 등 운영 난이도가 올라갑니다.
- 원문 사례도 "수익률은 쏘쏘"라고 밝혔듯, 구현 자체는 가능해도 수익성까지 보장되는 것은 아닙니다.

## 필요 도구
- 증권사 Open API(택1, 무료/유료 조건은 각 증권사 정책 확인 필요) — 시세 조회 및 주문 실행용 [공식 문서 확인 필요]
- 재무정보 데이터 소스(원문에서는 Dartlab 사용, 유사한 재무정보 제공 서비스로 대체 가능, 비용 여부는 서비스별 상이)
- AI API(원문은 Gemini 사용, 유사 LLM API로 대체 가능, 호출량에 따라 과금)
- 프로그래밍 환경(개인 PC에서 스크립트 실행 가능한 언어 환경, 특정 언어·버전은 [추정])
- 백테스트 도구(예: 범용 백테스트/시뮬레이션 라이브러리 또는 직접 구현한 검증 스크립트)
- 모의투자 환경(증권사 Open API가 제공하는 경우 활용, 제공 여부는 증권사별 확인 필요)
- 스케줄 실행 수단(정해진 시간에 스크립트를 자동 실행할 방법, 구체 도구는 사용 환경에 맞게 직접 선정)

## 구현 단계
1. 매매 아이디어를 "사용자가 정의한 매매 규칙"으로 명문화한다. 어떤 조건에서 매수/매도/관망할지 규칙을 글로 먼저 적는다.
2. 규칙을 코드로 구현하고, 과거 데이터를 이용해 백테스트 도구(또는 직접 작성한 검증 스크립트)로 규칙의 동작을 확인한다.
3. 재무정보 데이터 소스에서 관심 종목의 재무정보를 가져와 규칙 판단 결과와 함께 보여주는 화면/로그를 만든다.
4. AI는 전체 판단이 아니라 "규칙이 신호를 냈을 때 그 신호를 보조로 검토·설명"하는 역할로 한정해 호출 시점과 빈도를 설계한다.
5. 증권사 Open API 신청 및 인증 절차를 진행하고, 모의투자 계좌로 전체 흐름(데이터 수신 → 규칙 판단 → AI 보조 검토 → 주문)을 연결해 본다.
6. 모의투자 환경에서 충분한 기간 동안 운영하며 규칙의 신호 품질, AI 보조 호출 빈도(및 비용), 오류 상황을 점검한다.
7. 결과를 검토해 규칙을 보완하고, 안정성이 확인된 이후에만 소액으로 실계좌 적용을 검토한다.

## 예상 공수
프로젝트 규모와 매매 규칙의 복잡도에 따라 상이하므로 직접 산정이 필요합니다. 증권사 API 연동과 규칙 설계·백테스트, 모의투자 검증까지 포함하면 개인 프로젝트 기준으로 상당한 시간이 소요될 수 있으며, 난이도는 중~상 수준으로 보는 것이 합리적입니다.

## 리스크/유의점
- 실계좌 자동매매는 금전적 손실로 직결되므로, 충분한 모의투자 검증 없이 실계좌에 바로 적용하지 않아야 한다.
- AI 보조 호출이라도 호출 빈도 설계가 잘못되면 비용 절감 효과가 크지 않을 수 있으므로 호출 조건을 명확히 정의해야 한다.
- 증권사 Open API의 정책(이용 조건, 요청 제한, 비용 구조 등)은 수시로 바뀔 수 있어 사용 전 반드시 공식 문서를 확인해야 한다.
- 재무정보 데이터 소스나 AI API의 서비스 약관·가격 정책도 변경될 수 있으므로 지속적인 확인이 필요하다.
- 원문 작성자도 "수익률은 쏘쏘"라고 밝혔듯, 이 구조가 수익성을 보장하지 않으며 어디까지나 비용 절감 및 운영 구조 개선 사례로 이해해야 한다.
