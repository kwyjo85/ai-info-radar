# Jev-mice — Jev와 결정론적 엔진으로 만든 마우스 시뮬레이션

## 쉽게 말하면
이 프로젝트는 "AI가 게임 속 캐릭터(마우스)의 행동을 스스로 판단하게 만들면 어떻게 될까?"를 실험한 데모입니다. 기존에는 정해진 규칙(if-then 코드)이나 작은 전용 AI 모델이 마우스의 움직임을 결정했는데, 여기서는 최신 AI 모델(Jev)에게 "지금 상황에서 뭘 할지 판단해줘"라고 물어보고 그 답을 그대로 게임 엔진에 반영합니다. 자동차 내비게이션이 미리 정해진 지도 대신 매 순간 사람에게 길을 물어보며 운전하는 것과 비슷합니다.

## 이걸로 할 수 있는 것
1. 고객사의 "룰 기반 의사결정 로직"(재고 배분, 알림 우선순위, 고객 응대 분기 등)을 Jev API 판단으로 대체하는 PoC를 하루 만에 만들어 견적을 낸다.
2. Claude Code로 이 "결정론적 엔진 + LLM 판단" 패턴을 재사용 가능한 템플릿으로 만들어, 이후 유사 자동화 프로젝트 수주 시 착수 시간을 단축한다.
3. 블로그/포트폴리오용으로 "AI 의사결정 에이전트 데모"를 직접 만들어 Jev·Claude Code 활용 컨설팅 영업 자료로 쓴다.

## 개요
이 항목이 자동화하는 것은 "상태를 관찰 → AI에게 다음 행동을 묻기 → 그 행동을 결정론적 엔진에 반영"하는 루프입니다. 핵심 가치는 로컬 분류기(작은 전용 모델)를 유지·재학습하는 대신, 범용 LLM(Jev) 호출 하나로 판단 로직을 대체할 수 있다는 검증입니다. 이 패턴은 게임뿐 아니라 반복적 판단이 필요한 모든 업무 자동화(재고 관리, 콜센터 라우팅, 이상거래 탐지 등)에 그대로 옮겨 쓸 수 있어, 수익화 관점에서는 "AI 판단 대체 PoC"를 빠르게 만들어 파는 역량 증명 자료가 됩니다.

## 구현 가능성 — 중
- 근거 (상방 요인): 원본 프로젝트가 이미 공개 데모+repo로 존재해 재구현이 아니라 "읽고 응용"만 하면 됨. Claude Code로 유사 구조(상태 관찰 → LLM 호출 → 엔진 반영)를 빠르게 스캐폴딩 가능.
- 근거 (하방 요인): Jev는 2026-09 출시 모델로 Claude(당신)의 학습 데이터 컷오프 이후 모델이라 API 스펙·요금·SDK를 실시간으로 조사해야 함(문서 확인 필수). 또한 "결정론적 엔진"과 LLM 호출을 매 틱(tick)마다 연동하면 지연시간(latency) 문제가 실제 업무 자동화에 그대로 옮겨질 때 병목이 될 수 있음.

## 필요 도구
- **Jev API 접근 권한** (유료, 호출당 과금 — 정확한 요금은 공식 문서 확인 필요, 컷오프 이후 모델이라 사전 지식 없음)
- **Claude Code** (기보유, 스캐폴딩·리팩터링용)
- 원본 repo 클론 (데모 페이지 링크 경유 확인 — 무료, 오픈소스로 추정되나 라이선스 확인 필요)
- Python 또는 JS 기반 게임/시뮬레이션 엔진 (예: Pygame, 혹은 웹이면 Canvas/Phaser — 무료)
- 로컬 실행용 macOS 터미널 환경 (기보유)
- (선택) 로깅/관찰용 대시보드 — 기존 ai-info-radar 프로젝트의 GitHub Pages 배포 방식 재사용 가능 (무료)

## 구현 단계
1. Hacker News 코멘트 링크와 데모 페이지(mice.jev.carsonsweet.com)에 접속해 설계 글(write-up)과 repo 링크를 확보한다.
2. repo를 로컬 `~/Documents/cocobaby/` 하위에 별도 실험 폴더로 클론한다.
3. Jev API 키 발급 절차와 요금 체계를 공식 문서에서 확인하고, 최소 호출(1회)로 "Hello Jev" 테스트를 먼저 수행한다.
4. Claude Code에게 repo 구조를 요약시키고, "결정론적 엔진 ↔ Jev 호출" 경계가 어디인지(어떤 함수가 판단을 위임하는지) 파악한다.
5. 로컬에서 실행해 원본 데모와 동일하게 동작하는지 확인한다(마우스가 움직이고 판단이 로그로 남는지).
6. 판단 로직 부분만 떼어내어, 업무 자동화 PoC용 템플릿(예: "이 상황 입력 → Jev가 행동 결정 → 결과 출력")으로 일반화한 미니 버전을 별도로 만든다.
7. 이 미니 버전을 활용해 "AI 판단 대체" 데모 1개(예: 간단한 재고 배분 시뮬레이션)를 추가로 제작, 포트폴리오/견적 자료로 정리한다.
8. 로컬 분류기 대비 Jev 방식의 장단점(속도, 비용, 일관성)을 표로 정리해 블루프린트 문서로 남긴다.

## 예상 공수
- repo 파악 + 로컬 실행: 1~2시간 (난이도: 하)
- Jev API 연동·테스트: 2~3시간 (난이도: 중, API 스펙이 낯설어 문서 탐색 시간 포함)
- 업무 자동화용 미니 PoC 일반화: 3~5시간 (난이도: 중~상, 원본 게임 로직에서 범용 패턴 추출 필요)
- 포트폴리오 정리: 1시간 (난이도: 하)
- **총합: 약 7~11시간**

## 리스크/유의점
- Jev는 출시 직후 모델이라 API 안정성·요금 정책이 변동 가능성이 있으므로, 고객 대상 상용 PoC에 바로 쓰기보다는 내부 실험/영업 자료용으로 먼저 검증할 것.
- 결정론적 엔진에 매 틱마다 LLM을 호출하는 구조는 실제 업무 자동화에서 지연시간·비용이 누적될 수 있어, "판단이 자주 필요한지 vs 가끔 필요한지"를 먼저 따져 Jev 호출 빈도를 설계해야 함.
- 원본 프로젝트의 라이선스(오픈소스 여부)를 확인하지 않고 코드를 그대로 상업적으로 재활용하면 문제가 될 수 있음 — 참고·학습용으로만 쓰고 자체 구현으로 재작성 권장.
