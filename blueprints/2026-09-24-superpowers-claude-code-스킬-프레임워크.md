# superpowers – Claude Code를 "정해진 개발 방법론"으로 무장시키는 스킬 프레임워크

## 쉽게 말하면
Claude Code에게 "이번엔 이렇게 해줘"를 매번 설명하는 대신, 유능한 시니어 개발자의 작업 매뉴얼(스펙 먼저 쓰기 → 테스트부터 짜기 → 커밋 규칙 지키기 → 코드리뷰 체크리스트)을 한 번 설치해두는 것입니다. 그러면 어떤 프로젝트를 맡기든 에이전트가 매번 같은 품질 기준으로 알아서 작업합니다.

## 이걸로 할 수 있는 것
1. Jev 관련 자동화 스크립트를 여러 클라이언트에게 납품할 때, 프로젝트마다 다시 설명하지 않아도 동일한 코드 품질·커밋 규칙이 자동으로 유지됩니다.
2. ai-info-radar 같은 개인 프로젝트의 collector.js·routine 프롬프트 수정 작업에 코드리뷰 스킬을 붙여, 혼자 작업해도 리뷰 누락 없이 커밋할 수 있습니다.
3. "검증된 개발 방법론이 탑재된 Claude Code 자동화"를 세일즈 포인트로 삼아, 프리랜서·컨설팅 형태로 자동화 구축 서비스를 팔 때 신뢰도를 높이는 근거로 쓸 수 있습니다.

## 개요
Claude Code(및 Antigravity, Codex, Cursor, Devin 등)에 조합 가능한 스킬 세트와 초기 지침을 설치해, 스펙 작성 → TDD → 커밋 규칙 → 코드리뷰 같은 소프트웨어 개발 프로세스를 강제로 따르게 만드는 오픈소스 프레임워크입니다. 개인이 여러 자동화 프로젝트를 동시에 돌릴 때 발생하는 "에이전트마다 결과물 품질이 들쭉날쭉한" 문제를 표준화된 프로세스로 줄여주는 데 가치가 있습니다.

## 구현 가능성: 상
- 스타 29만 개(오늘 +474)로 큰 규모의 커뮤니티 검증을 받은 실제 프로젝트임
- Claude Code를 포함한 다수 코딩 에이전트를 공식 지원해 문서화 수준이 높고 설치 경로가 명확함(스킬/플러그인 마켓플레이스)
- 다만 "Commercial Services" 섹션 존재로 일부 기능이 유료일 가능성이 있어 설치 전 범위 확인이 필요함

## 필요 도구
- Claude Code CLI (무료 사용 가능, 별도로 Claude 구독/API 사용료 발생)
- git, GitHub CLI (무료)
- obra/superpowers 저장소 클론 또는 plugin marketplace 등록 (무료, 단 Commercial Services 섹션 유료 가능성 있음 — 확인 필요)
- 테스트용 별도 sandbox 저장소 (무료, 로컬 디스크만 필요)

## 구현 단계
1. GitHub obra/superpowers README에서 "Claude Code" 섹션을 찾아 설치 명령(plugin marketplace 등록 또는 `.claude/skills` 복사 방식)을 확인한다.
2. README의 "Commercial Services" 섹션을 읽고 유료로 전환되는 기능/서비스를 구분해, 무료 범위의 스킬 목록만 별도로 메모한다.
3. ai-info-radar를 직접 건드리기 전에, 별도의 빈 테스트 저장소를 만들어 superpowers를 설치하고 정상 동작(스킬 목록 인식, 초기 지침 로드)을 먼저 확인한다.
4. 전체 방법론 중 코드리뷰 규칙과 커밋 메시지 규칙 스킬만 우선 활성화하고, 나머지(TDD 강제, 스펙 문서 강제 등)는 비활성 상태로 둔다.
5. ai-info-radar의 collector.js 또는 블루프린트 생성 로직에 작은 수정 건 하나를 골라, superpowers가 적용된 워크플로우로 커밋해보고 기존 방식과 결과물 품질·소요 시간을 비교한다.
6. 문제가 없으면 Jev 관련 클라이언트 자동화 프로젝트에 점진적으로 적용하고, 적용된 개발 프로세스를 문서화해 이후 영업/제안 자료에 "검증된 방법론 적용" 근거로 활용한다.

## 예상 공수
- 설치 및 1차 동작 확인: 1~2시간
- 스킬 선별(불필요한 항목 끄기) 및 Commercial Services 범위 확인: 1시간
- ai-info-radar 시범 적용 및 품질 비교: 반나절
- 클라이언트 프로젝트 실전 적용: 프로젝트당 1일 내외
- 난이도: 하~중 (설치 자체는 쉬우나, 강제되는 프로세스가 기존 작업 습관과 맞는지 판단하는 데 시간이 걸림)

## 리스크/유의점
- "Commercial Services" 섹션의 유료 기능을 모르고 사용하면 예상치 못한 과금이 발생할 수 있으므로 설치 전 반드시 범위를 확인해야 함
- 스펙 문서화·TDD 강제 같은 규칙이 빠른 프로토타이핑 위주의 개인 작업 스타일과 충돌해 오히려 속도가 느려질 수 있음
- 스타 수가 많다는 것이 보안성을 보장하지는 않으므로, 설치되는 셸 스크립트/훅의 내용을 직접 검토해 공급망 리스크를 확인할 필요가 있음
- 클라이언트 코드베이스에 적용할 경우, 오픈소스 도구 사용 사실을 계약서상 고지해야 할 수도 있음
