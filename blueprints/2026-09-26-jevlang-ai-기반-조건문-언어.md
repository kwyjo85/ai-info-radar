# Jevlang — AI 기반 조건문 언어

## 쉽게 말하면
Jevlang은 프로그램의 "if 조건문"을 딱딱한 참/거짓 코드 대신, 사람이 쓴 문장 그대로를 AI가 판단하게 만드는 실험적 프로그래밍 도구입니다. 비유하자면 기존 코드는 "나이 >= 18이면" 같은 숫자 비교만 할 수 있었는데, Jevlang은 "이 문장이 화난 것처럼 들리면" 같은 애매한 조건도 AI 심사위원에게 물어봐서 분기 처리를 하게 해주는 셈입니다. 즉 코드 안의 갈림길마다 작은 판단 담당 AI를 하나씩 심어두는 방식입니다.

## 이걸로 할 수 있는 것
1. ai-info-radar 수집 파이프라인에서 "이 기사가 블루프린트로 만들 가치가 있는가" 같은 애매한 채점 분기를 자연어 if문 하나로 단순화.
2. 인스타 대시보드(IG_DATA) 게시물·댓글 필터링 스크립트에서 "이 댓글이 스팸/광고성으로 보이면 건너뛰기" 같은 조건을 코드 대신 자연어로 작성.
3. 외주 자동화 납품(소상공인 챗봇, 문의 라우팅 봇)에서 "고객 문의가 환불 요청처럼 보이면 → 담당팀으로 라우팅" 같은 규칙을 빠르게 자연어로 작성해 개발 시간을 줄이고, 이를 상품 차별점으로 제시.

## 개요
Jevlang은 프로그램의 조건 분기(if/switch)를 자연어 서술로 대체하고, 내부적으로 LLM 호출로 참/거짓을 판정하는 실험적 언어(또는 라이브러리)로 보입니다. "규칙을 코드로 정교하게 짜기 어려운 애매한 판단"을 빠르게 프로토타이핑하는 데 목적이 있으며, 개발 속도(자연어로 조건 작성)를 얻는 대신 실행 비용(LLM 호출)·지연시간·비결정성이라는 대가를 치르는 구조입니다. 프로덕션 코드에 바로 넣기보다, 프로토타입이나 휴리스틱 필터 단계에서 규칙을 빠르게 실험하는 용도로 유용할 가능성이 큽니다.

## 구현 가능성 — 중
- 근거(가능 요인): 개념 자체는 "LLM as a judge" 패턴으로 이미 흔히 쓰이며, 언어 문법이 없어도 Claude Code로 함수 하나(자연어 조건 문자열 → LLM 호출 → bool 반환)를 만들어 즉시 재현 가능. 사용자가 이미 launchd·API 연동 자동화 경험이 있어 통합 난이도는 낮음.
- 근거(제약 요인): HN 포인트 3점·댓글 0개로 검증 사례가 사실상 없고, 저장소가 실제 문법·컴파일러를 갖춘 "언어"인지 단순 라이브러리 수준인지 성숙도가 불명확. 이번 확인 과정에서 저장소 접근이 승인되지 않아 README 기반 상세 검증은 하지 못함.

## 필요 도구
- Jevlang 저장소 (github.com/RoyWiggins/jevlang) — 라이선스·성숙도 확인 필요, 추정 무료(오픈소스)
- Claude API 또는 로컬 LLM(Ollama 등) — 조건 판정용 호출 백엔드; Claude API는 사용량 기준 과금
- Python 또는 Node.js 런타임 — 저장소 요구사항에 따라 결정, 무료
- Claude Code — 개념 검증(PoC) 및 자체 대체 구현 작성용, 기존 사용 중(무료)

## 구현 단계
1. 저장소를 클론해 README·예제 코드로 실제 문법, 런타임 요구사항, 백엔드 LLM 연동 방식(자체 API 키 필요 여부)을 확인.
2. 간단한 예제(예: "이 텍스트가 긍정적이면 A, 아니면 B")를 실행해 응답 지연시간과 판정 정확도를 직접 체감.
3. 검증 가치가 있으면 ai-info-radar 수집 스크립트의 채점 분기 하나를 Jevlang 스타일 조건으로 치환해 기존 로직과 A/B 비교.
4. 저장소 자체가 미성숙하면, Claude Code로 동일 개념의 최소 래퍼 함수(자연어 조건 → Claude API 호출 → true/false)를 직접 작성해 대체.
5. 실제 운영 파이프라인(launchd 스크립트)에 넣기 전, 오탐/누락률과 호출당 API 비용을 최소 1주일 로그로 측정.
6. 결과가 안정적이면 외주 자동화 제안서에 "자연어 규칙 기반 분기 처리" 기능으로 포함해 견적에 반영.

## 예상 공수
- 저장소 확인·PoC 실행: 1~2시간 (난이도: 하)
- 자체 대체 구현(Claude API 래퍼) 작성: 2~3시간 (난이도: 하)
- 파이프라인 통합 및 A/B 비교: 3~5시간 (난이도: 중)
- 총합: 약 6~10시간, 전체 난이도 하~중

## 리스크/유의점
- HN 반응(포인트 3, 댓글 0)이 거의 없어 실전 검증된 프로젝트가 아님 — 데모·장난 수준일 가능성을 배제하지 말 것.
- LLM 기반 조건 판정은 비결정적이라, 동일 입력에도 다른 결과가 나올 수 있어 프로덕션 분기 로직에 그대로 쓰면 버그 재현이 어려워짐.
- 조건 판정마다 API 호출이 발생하면 반복 실행되는 파이프라인(launchd 매일 실행 등)에서 비용이 누적될 수 있음 — 캐싱 또는 로컬 모델 병행을 고려.
- "Jevlang"이라는 이름과 사용자가 쓰는 Jev(TypeSafe AI System One) 모델은 무관한 별개 프로젝트이므로 혼동하지 말 것.
