# Ollaya — 로컬에서 돌리는 오픈소스 Jev(TypeSafe) 대체 모델

## 쉽게 말하면
Jev(TypeSafe)가 "질문에 초 단위로 답해주는 유료 클라우드 판단 서비스"라면, Ollaya는 그 판단 능력을 내 맥북 안에 통째로 내려받아 공짜로, 인터넷 없이, 더 빠르게 돌리는 도구입니다. 마치 매번 배달시켜 먹던 음식을 집에 가스레인지를 놓고 직접 만들어 먹는 것과 비슷하며, 심지어 배달보다 더 빨리 나옵니다(220ms대 → 10ms대).

## 이걸로 할 수 있는 것
1. Claude Code 에이전트가 파일을 수정·삭제·push하기 전에 "이거 위험한 작업인가?"를 Ollaya에 0.01초 만에 물어보고 자동 차단/승인하게 만들기
2. 인스타 대시보드나 ai-info-radar가 수집한 글/댓글을 "긍정/부정/스팸/문의" 등으로 대량 자동 분류해서 브리핑 자료를 자동 정리하기
3. 고객 문의 메일이나 카톡 문구를 로컬에서 즉시 "환불 요청/인보이스 요청/기타"로 판별해 자동 라우팅하는 소규모 자동화 상품을 만들어 외주·SaaS로 판매하기

## 개요
Ollaya는 "예/아니오, 선택형, 점수형" 같은 정형 질문에 대해 신뢰도(확률)까지 포함한 답을 초저지연으로 반환하는 판단 전용 모델 서버로, Jev(TypeSafe)와 동일한 `/v1/systemone` API 형태를 그대로 지원해 SDK 코드를 거의 안 바꾸고 교체할 수 있습니다. 토큰당 과금이 없고 완전히 로컬에서 돌아가므로, 반복적으로 대량 호출되는 판단 로직(에이전트 가드레일, 분류, 라우팅)을 무제한·무비용으로 자동화 파이프라인에 박아 넣을 수 있다는 데 큰 가치가 있습니다.

## 구현 가능성
**상.** macOS(Apple Silicon) 데스크톱 앱/CLI가 공식 지원되고, Homebrew 스타일 설치 스크립트 제공. Apple GPU에서 laya/NLI 모델이 MLX로 가속되며, Docker 이미지도 있어 서버화도 쉽습니다. TypeSafe SDK와 API 호환이라 기존 Jev 연동 코드 구조를 재사용 가능.

## 필요 도구
- **Ollaya 데스크톱 앱 또는 CLI** (macOS Apple Silicon 지원) — 무료, 오픈소스(Apache-2.0)
- **모델 가중치**: laya(322m/421m, 다국어 가장 빠름), decider(0.75b/1.9b, 정확도 우수), qwen3guard(0.6b, 안전성 검사) — 전부 무료, Hugging Face에서 자동 다운로드
- **TypeSafe Python SDK 0.7.1** — 무료, `TYPESAFE_BASE_URL`을 로컬로 바꿔서 그대로 재사용
- **Claude Code / Claude Agent SDK** — 기존 구독으로 사용 (에이전트 훅에서 Ollaya 호출)
- **Python 3.11+, requests/httpx** — 무료
- (선택) **launchd 서비스 등록** — ai-info-radar에서 이미 사용 중인 launchd 방식 재활용, 무료
- (선택) **Docker Desktop** — 서버로 분리 운영 시, 무료(개인용)

## 구현 단계
1. `brew install`류 공식 설치 스크립트로 Ollaya CLI를 맥북에 설치하고 `ollaya serve` 로컬 서버(기본 포트 11435)를 실행한다.
2. `ollaya pull laya:multilingual`, `ollaya pull decider:2b`, `ollaya pull qwen3guard`로 필요한 모델 가중치를 받아 sha256 검증까지 완료한다.
3. 환경변수 `TYPESAFE_BASE_URL=http://localhost:11435`, `TYPESAFE_API_KEY=local`로 설정해 기존에 Jev용으로 짜둔 TypeSafe SDK 호출 코드가 그대로 동작하는지 curl로 먼저 테스트한다.
4. Claude Code의 pre-tool-use 훅(또는 별도 wrapper 스크립트)에서, `git push --force`나 `rm -rf` 같은 위험 명령을 실행하기 전에 Ollaya `decider` preset `agent`에 질문을 던져 `destructive`/`risk` 확률이 임계치 이상이면 자동 실행을 막도록 연결한다.
5. ai-info-radar 파이프라인의 수집 텍스트(뉴스/댓글/인스타 데이터)를 대상으로 `laya:multilingual` 또는 `gliclass`에 "긍정/부정/스팸/광고" 같은 choice 질문을 배치로 던져 자동 태깅 후 JSON에 라벨을 추가한다.
6. 자동 태깅 결과를 기존 launchd 스케줄 브리핑 생성 단계에 병합해, 사람이 보는 최종 브리핑에 "신뢰도 포함 자동 분류" 컬럼을 추가한다.
7. 위 4~6번 구조를 일반화한 "로컬 판단 게이트 + 자동 분류" 템플릿을 정리해, 소규모 사업장/솔로프리너 대상 유료 자동화 셋업 서비스(외주 코드 + 셋업 가이드)로 패키징한다.
8. 정확도 검증이 필요한 경우, 라벨된 자체 데이터로 Modelfile 기반 캘리브레이션 재조정을 시도해 본다.

## 예상 공수
- 설치 + 모델 다운로드 + curl 테스트: **1~2시간** (난이도: 하)
- Claude Code 훅 연동(4단계): **3~5시간** (난이도: 중, 훅 API와 판단 임계치 설계 필요)
- ai-info-radar 자동 분류 파이프라인 통합(5~6단계): **4~8시간** (난이도: 중, 기존 JSON 스키마 수정 포함)
- 외주/상품화 패키징(7단계): **1~2일** (난이도: 중~상, 문서화·데모·가격 설계 필요)

## 리스크/유의점
- Jev(TypeSafe) 공식 API와 "호환"이지만 100% 동일 모델이 아니므로, 의사결정 결과가 미세하게 달라질 수 있어 안전 게이트처럼 중요한 곳은 한동안 병행 검증 필요.
- decider 계열은 정확도 0.591 수준(벤치마크 기준)으로 완벽하지 않아, 파괴적 명령 차단 등 안전 관련 판단에는 단독 신뢰보다 규칙 기반 하드가드(화이트리스트 등)와 병행 권장.
- 로컬 GPU(Apple GPU)가 없는 환경(CPU only)에서는 지연시간이 벤치마크보다 늘어날 수 있음 — 맥북 사양 확인 필요.
- 오픈소스 프로젝트이므로 유지보수·보안 패치 속도가 TypeSafe 공식 서비스보다 늦을 수 있어, 상용 서비스에 넣을 경우 버전 고정과 자체 회귀 테스트 필요.
- 외주 상품화 시 "Jev 대체품"이라는 표현이 상표/브랜드 이슈가 될 수 있으니 고객 문서에는 "로컬 판단 모델" 등 중립적 표현 사용 권장.
