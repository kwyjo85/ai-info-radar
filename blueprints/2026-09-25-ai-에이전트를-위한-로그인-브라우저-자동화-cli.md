# AI 에이전트를 위한 로그인 브라우저 자동화 CLI (BrowserSkill)

## 쉽게 말하면
내가 이미 로그인해둔 크롬 창을 AI 에이전트에게 "잠깐 빌려줄게" 하고 넘겨주는 도구입니다. 계정 비밀번호나 로그인 쿠키를 따로 복사해서 넘길 필요 없이, 지금 켜져 있는 브라우저 탭을 그대로 빌려서 클릭·타이핑·읽기를 대신 시키는 셈입니다. 비유하면, 내 사무실 컴퓨터 화면 앞에 비서를 앉혀놓고 "이 화면 그대로 써서 이거 좀 해줘"라고 시키는 것과 같습니다.

## 이걸로 할 수 있는 것
1. Claude Code에게 "네이버 스마트스토어에 로그인된 상태에서 주문 목록 캡처해서 정리해줘"라고 시키면 별도 로그인 절차 없이 바로 실행.
2. 거래처 사이트나 관공서 포털처럼 2단계 인증이 걸린 곳에서, 내가 로그인해둔 세션을 에이전트가 이어받아 반복 작업(정산 다운로드, 서류 제출 등)을 대행.
3. 여러 AI 에이전트(Claude Code, Cursor, Codex)를 섞어 쓸 때, 로그인 브라우저 대여 기능을 표준화해서 "이 에이전트는 이 사이트 못 쓴다"는 상황을 없앰.

## 개요
BrowserSkill은 CLI + 브라우저 확장 조합으로, 로그인 상태를 유지한 실제 브라우저 세션을 AI 에이전트가 셸 명령을 통해 조작할 수 있게 해줍니다. 자동화 스크립트마다 계정을 새로 로그인하거나 쿠키/토큰을 탈취·복사하는 보안상 부담 없이, "지금 내가 보고 있는 그 화면"을 에이전트가 대신 조작하게 만드는 것이 핵심 가치입니다. 즉, 로그인 장벽이 있는 웹 자동화(관공서, 거래처, 내부 시스템)의 진입 비용을 낮춥니다.

## 구현 가능성: 중
- 근거: 기술적으로는 CLI 설치 + 브라우저 확장 설치만 하면 되므로 진입 장벽은 낮음. 다만 이미 사용자는 Aside를 통해 동일한 "로그인 브라우저 대여" 기능을 쓰고 있어 추가 효과가 제한적이며, 수익화로 이어지려면 "이걸로 무엇을 팔 것인가"라는 별도 기획이 더 필요함. 현재 상태로는 도구 교체/비교 실험 수준.

## 필요 도구
- **bsk CLI** (Tencent/BrowserSkill, 오픈소스 무료, MIT 계열) — 설치: `npm install -g bsk` 또는 저장소 클론
- **BrowserSkill 브라우저 확장** (무료, Chrome/Chromium 계열)
- **Claude Code** (이미 구독 중 — 셸 명령 실행 권한으로 bsk CLI 호출)
- (비교 대상, 선택) **Aside** — 현재 사용 중인 동일 기능 도구, 무료/유료 여부 확인 필요
- (선택) Cursor / Codex — 다른 에이전트에서 동일 CLI를 재사용할 때

## 구현 단계
1. `git clone https://github.com/Tencent/BrowserSkill` 또는 npm 설치 명령으로 bsk CLI를 로컬 맥북에 설치.
2. Chrome에 BrowserSkill 확장을 추가하고, CLI와 페어링(토큰/포트 연결) 확인.
3. 은행·메일 등 민감 사이트는 확장 설정에서 "탭 대여 허용 목록"을 만들어 접근 가능한 탭을 화이트리스트로 제한.
4. 테스트용으로 로그인 필요한 저위험 사이트(예: 개인 블로그 관리자 페이지) 하나를 골라, Claude Code에서 `bsk` 명령을 셸로 실행시켜 페이지 읽기/클릭이 되는지 1차 검증.
5. Aside로 이미 하고 있는 작업 중 하나(예: 특정 사이트 데이터 수집)를 bsk로 동일하게 재현해 결과·속도·안정성을 비교.
6. 비교 결과 Aside 대비 명확한 이점(다른 에이전트 호환성, 셸 통합 편의성 등)이 있으면 실제 반복 업무(정산 다운로드, 거래처 포털 조회 등)에 투입해 시간 절약을 수익화 지표로 환산.
7. 이점이 없으면 보류하고, "Claude Code/Cursor 등 여러 에이전트를 동시에 쓸 때만 재검토" 조건을 메모에 남겨 첫 단계 지시대로 후순위 처리.

## 예상 공수
- CLI/확장 설치 및 기본 연동 테스트: 1~2시간
- 민감 사이트 접근 제한 설정: 30분
- Aside와의 실사용 비교(1개 워크플로 기준): 2~3시간
- 난이도: 하~중 (설치는 쉽지만, Aside와의 실질적 차별점을 찾는 비교 작업이 시간 소모)

## 리스크/유의점
- 로그인된 실제 브라우저를 에이전트가 조작하므로, 은행·메일 등 민감 사이트는 반드시 대여 범위를 명시적으로 제한해야 함 (첫 단계 지시 그대로).
- 이미 Aside로 동일 기능을 쓰고 있어, 단순 도입만으로는 추가 수익 효과가 없음 — "여러 에이전트 호환"이라는 차별점이 실제로 필요할 때만 투자 가치가 생김.
- 오픈소스 프로젝트(스타 급증 중)라 아직 검증 기간이 짧음 — 확장이 브라우저 권한을 얼마나 광범위하게 요구하는지 설치 전 권한 목록을 확인할 것.
- 관공서/거래처 포털은 자동화 탐지 정책이 있을 수 있으므로, 약관 위반 여부를 사전에 확인.
