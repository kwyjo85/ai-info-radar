# GPS 러닝 루프 자동 생성 — Nominatim·Overpass·Claude로 jev 맞춤 러닝 코스 상품화

## 개요
Simon Willison이 ChatGPT Work(GPT-6 Astra)로 시연한 "집 주소 기반 5K/10K 러닝 루프 자동 생성"은 Nominatim(주소→좌표), Overpass(도로망 데이터), 로컬 경로 계산이라는 공개 API·오픈소스 조합만으로 재현 가능한 파이프라인이다. jev에서 "맞춤 러닝/워킹 코스 설계" 또는 "여행지 로컬 러닝 코스 추천" 상품을 만들면, 주문마다 주소와 목표 거리만 받아 GPX 파일·지도 시각화·코스 설명을 자동 생성해 납품하는 저원가·반자동 서비스로 수익화할 수 있다.

## 구현 가능성 — 상
- Nominatim(지오코딩)과 Overpass(OSM 도로망 다운로드)는 모두 무료 공개 API이며, 이를 감싼 Python 라이브러리 `osmnx`가 성숙해 있어 직접 HTTP 호출을 구현할 필요가 없음.
- "그래프에서 목표 거리에 근접한 폐루프 찾기"는 `networkx` 기반 그래프 탐색 문제로 이미 여러 오픈소스 구현체(예: loop-route generator 스크립트)가 존재해 참고 가능.
- ChatGPT Work가 27분 걸려 처리한 작업의 핵심은 "주소 해석 → 도로망 다운로드 → 루프 계산 → GPX/지도 출력"이라는 명확한 4단계 파이프라인이라, macOS 로컬 환경에서 Python 스크립트로 그대로 재현 가능(코드 비공개 문제도 자체 구현하면 해소됨).

## 필요 도구
- **Python 3 (macOS 기본 또는 pyenv)** — 무료
- **osmnx** (Nominatim 지오코딩 + Overpass 도로망 다운로드 + networkx 그래프 변환 래퍼) — 무료, 오픈소스
- **networkx** — 루프 경로 탐색 그래프 알고리즘 — 무료
- **gpxpy** — GPX 파일 생성 — 무료
- **folium** 또는 **plotly** — 지도 시각화 HTML 생성(ChatGPT의 visualize skill 대체) — 무료
- **Anthropic Claude API (Sonnet 5)** — 생성된 루프의 랜드마크·지형·난이도를 설명하는 코스 소개 문구 자동 작성 — 유료(토큰 과금, 사용량 적어 비용 미미)
- **(선택) Streamlit** — 주소/목표거리 입력 → 결과 자동 생성하는 간단 로컬 웹앱 UI — 무료
- **jev 계정** — 서비스 판매 채널 — 가입 무료·거래 시 수수료 발생

## 구현 단계
1. `pip install osmnx networkx gpxpy folium anthropic streamlit`로 로컬 환경을 구성한다.
2. `osmnx.geocode()`로 주소→좌표 변환을 테스트하고, `osmnx.graph_from_point(좌표, dist=목표거리*1.5, network_type="walk")`로 반경 내 보행/도로 그래프를 다운로드해본다 — 우선 본인 동네 주소로 확인.
3. 목표 거리(5K/10K)에 맞는 폐루프 탐색 로직을 구현한다: 시작 노드에서 외곽 방향 노드를 후보로 골라 최단경로(왕복)와 실제 도로 우회 경로 중 목표 거리 오차(±10% 이내)를 만족하는 조합을 `networkx.shortest_path` 반복 탐색으로 찾는다. 도로가 성긴 지역(막다른 길, 고속도로 인접)에서는 후보 확장 반경을 넓히는 예외 처리를 넣는다.
4. 계산된 루프 좌표열을 `gpxpy`로 GPX 파일로 저장하고, `folium`으로 경로선 + 랜드마크 마커가 표시된 인터랙티브 지도 HTML을 생성한다.
5. Claude API에 루프의 도로명·주변 시설(OSM 태그에서 추출한 공원/해안/상점 등)을 프롬프트로 넘겨 "코스 소개 문구"(난이도, 경치 포인트, 주의구간)를 자동 생성한다.
6. 주소·목표거리·요청사항(예: "공원 위주", "언덕 없는 평지")을 입력받아 2~5단계를 순차 실행하는 스크립트를 하나로 묶고, Streamlit으로 간단한 로컬 UI를 만들어 본인이 수동 실행 없이 결과물(GPX+지도 HTML+설명 텍스트)을 한 번에 뽑도록 한다.
7. 본인이 아는 지역 5곳 이상(도심/외곽/해안 등 지형 다양화)으로 파일럿을 돌려 루프 품질(과도한 우회, 위험 도로 포함 여부)을 육안 검증하고 3단계 탐색 로직을 튜닝한다.
8. jev에 "주소 기반 맞춤 러닝/워킹 코스 설계" 상품 페이지를 개설한다 — 결과물(GPX+지도+코스설명)과 소요시간(자동화로 1건당 수 분 내 생성 가능)을 강조해 가격 책정한다.

## 예상 공수
- 환경 구성 및 Nominatim/Overpass 연동 테스트: 2~3시간 (난이도 하)
- 루프 탐색 알고리즘 구현·튜닝: 4~6시간 (난이도 상 — 그래프 탐색·거리 오차 보정이 핵심 난관)
- GPX/지도 출력 + Claude 코스 설명 생성 연동: 2~3시간 (난이도 중)
- Streamlit 로컬 UI 구성: 1~2시간 (난이도 하)
- 파일럿 테스트 및 알고리즘 재조정: 2~3시간 (난이도 중)
- jev 상품 페이지 개설·가격 설계: 1~2시간 (난이도 하)
- 총 12~19시간, 전체 난이도: 중~상

## 리스크/유의점
- OSM 데이터는 지역별 커버리지 편차가 커서, 특히 한국 소도시나 등산로·강변 산책로는 도로망 태깅이 부실할 수 있어 결과 품질이 지역에 따라 크게 달라질 수 있음 — 서비스 지역을 데이터 품질이 검증된 곳(대도시 위주)으로 한정하는 것이 안전.
- Nominatim/Overpass 공개 API는 요청 빈도 제한(초당 1건 수준)이 있어, 상업적으로 대량 주문을 처리하려면 자체 캐싱 서버 구축이나 유료 플랜(예: Geoapify, LocationIQ) 전환을 검토해야 함.
- OSM 데이터는 ODbL 라이선스이므로 상업적 재사용 시 "지도 데이터 © OpenStreetMap contributors" 출처 표기 의무를 지도/GPX 산출물에 반드시 포함해야 함.
- 루프 탐색 로직이 완벽하지 않으면 위험한 도로(고속도로 갓길, 보행로 없는 구간)를 포함할 수 있어, 납품 전 생성된 경로를 육안으로 재확인하는 수동 검수 단계를 서비스 프로세스에 반드시 유지할 것.
- 고객 자택 주소를 다루는 서비스이므로 주문 데이터(주소) 보관·폐기 정책을 명확히 하고, jev 채널 외부로 주소 정보가 노출되지 않도록 로컬 처리 후 즉시 삭제하는 방식을 권장.
