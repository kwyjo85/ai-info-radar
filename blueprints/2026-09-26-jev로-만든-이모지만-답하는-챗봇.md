#이모지 전용 챗봇 (Jev 기반) — Claude Code로 만드는 니치 AI 토이 앱

## 쉽게 말하면
말은 다 알아듣지만 대답은 오직 이모지로만 하는 챗봇입니다. 마치 외국어를 완벽히 이해하지만 손짓·발짓으로만 대답하는 사람처럼, "출력 형식을 강제로 제한"하는 기법을 보여주는 작은 데모입니다. 기술 자체는 단순하지만 "AI가 딱 정해진 형태로만 답하게 만들기"라는, 실제 업무 자동화에서 자주 쓰이는 패턴을 아주 쉽게 눈으로 보여줍니다.

## 이걸로 할 수 있는 것
1. 고객 피드백이나 리뷰 댓글을 이모지 3개로 요약해 대시보드에 감정 상태를 한눈에 보여주는 미니 도구를 만든다.
2. Slack/카카오톡 봇이 팀 공지에 반응 이모지로만 응답하게 해서 "재미있는 사내 봇" 포트폴리오 데모로 클라이언트 영업에 활용한다.
3. 이런 니치 토이 앱을 Claude Code로 하루 만에 뚝딱 만들어 SNS/제작 과정 콘텐츠(유튜브·블로그)로 올려 "AI 자동화 외주 가능"을 홍보하는 리드 제너레이션 수단으로 쓴다.

## 개요
이 서비스는 LLM(Jev)에게 "응답은 이모지만 사용하라"는 강한 출력 제약을 걸어 대화를 처리합니다. 핵심 가치는 챗봇 자체가 아니라 **"구조화·제약된 출력을 안정적으로 뽑아내는 프롬프트/검증 패턴"**이며, 이는 실제 업무 자동화(감정 분석 태깅, 분류 라벨링, 고정 포맷 리포트 생성)에 그대로 재사용 가능합니다. 개인 맥북에서 Claude Code로 클론 수준의 데모를 만들고, 이를 "AI 자동화 역량 증명용 쇼케이스"로 포지셔닝해 수익화(외주 리드, 콘텐츠 트래픽)로 연결하는 것이 목표입니다.

## 구현 가능성 — 상
- 개인 맥북 + Claude Code만으로 프론트엔드(정적 웹) + LLM API 호출 구조는 하루 안에 완성 가능한 난이도.
- Jev는 2026-09 출시된 모델로 Claude의 학습 컷오프(2026-01) 이후 모델이라 API 스펙을 사용자가 직접 확인해줘야 하지만, 없더라도 Claude/OpenAI 등 기존 모델로 동일한 "이모지 강제 출력" 기법은 완전히 대체 구현 가능.
- 이미 참고할 실물 서비스(jev.chat)가 존재해 UX/기능 범위를 그대로 벤치마킹할 수 있음.

## 필요 도구
- **Claude Code** (유료 구독, 이미 보유) — 코드 생성·리팩터링 자동화
- **LLM API**: Jev API(신규, 요금제 확인 필요) 또는 대체로 **Claude API**(claude-sonnet-5, 유료 종량제) / **OpenAI API**(유료 종량제)
- **정적 호스팅**: GitHub Pages(무료) 또는 Vercel(무료 티어)
- **프론트엔드**: 순수 HTML/JS 또는 React + Vite(무료, 오픈소스)
- **이모지 검증 라이브러리**: `emoji-regex`(npm, 무료) — 출력이 실제 이모지로만 구성됐는지 검증
- (선택) **분석/트래킹**: Plausible/GA4(무료~저가) — 콘텐츠 마케팅 목적일 경우 방문자 추적

## 구현 단계
1. Claude Code로 새 리포지토리 생성 후 `npx create-vite` 등으로 최소 프론트엔드 스캐폴드 구성.
2. 시스템 프롬프트 작성: "사용자의 모든 메시지에 대해 오직 이모지 시퀀스(1~5개)로만 응답하라. 텍스트, 숫자, 특수문자 금지." + few-shot 예시 3~5개 포함.
3. 백엔드 없이 클라이언트에서 직접 API 호출하면 키가 노출되므로, Vercel Edge Function 또는 Cloudflare Worker로 API 키를 서버 사이드에 숨기는 프록시 엔드포인트 하나 작성(Claude Code로 boilerplate 생성).
4. 응답 후처리 단계에서 `emoji-regex`로 이모지 외 문자가 섞였는지 검증하고, 실패 시 1회 재시도 로직 추가(제약 위반 시 자동 재요청).
5. 간단한 채팅 UI(입력창 + 말풍선) 제작, 모바일 반응형까지 Claude Code로 빠르게 마무리.
6. GitHub Pages 또는 Vercel에 배포하고 커스텀 도메인(선택) 연결.
7. 같은 "제약 출력" 패턴을 실제 업무용으로 변형: 예를 들어 리뷰 텍스트 → 감정 이모지 3개 요약 API를 별도로 만들어 실제 클라이언트에게 제안할 수 있는 데모 페이지로 확장.
8. 제작 과정을 짧은 블로그/영상으로 정리해 "Claude Code로 하루 만에 만든 AI 토이"로 포트폴리오·리드 채널에 게시.

## 예상 공수
- 기본 데모(1~7단계): **4~6시간**, 난이도 **하** (Claude Code 활용 시 대부분 자동 생성)
- 실무형 확장(감정 요약 API 등, 7단계): 추가 **3~5시간**, 난이도 **중**
- 콘텐츠화(8단계): 추가 **2~3시간**

## 리스크/유의점
- Jev는 신규 모델이라 API 요금·레이트리밋·정책이 아직 불확실 — 초기엔 Claude/OpenAI로 대체 구현 후 Jev API 공개 문서 확인되면 스위치하는 편이 안전.
- LLM이 이모지 제약을 100% 지키지 못할 수 있어(가끔 텍스트 섞임) 후처리 검증·재시도 로직 없이는 제품 품질이 떨어짐.
- 순수 토이 앱은 직접적 매출보다는 "포트폴리오/리드 제너레이션" 성격이 강하므로, 수익화하려면 반드시 7단계(실무형 확장)까지 연결해 실제 클라이언트 문제(리뷰 분석, 고객 응대 자동화 등)에 적용하는 스토리로 마무리해야 함.
- API 키를 클라이언트 코드에 직접 넣지 않도록 프록시 서버 구조를 반드시 유지(비용 남용·크레딧 도용 방지).
