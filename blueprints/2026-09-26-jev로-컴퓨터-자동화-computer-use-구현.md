# Jev로 컴퓨터 자동화(Computer Use) 구현

## 쉽게 말하면
Jev는 글을 길게 쓰는 대신 "이 버튼을 누를까 말까"를 순식간에 답해주는 초고속 판단 엔진입니다. 마치 느리지만 신중한 상담사(일반 LLM) 대신, 정해진 선택지 중 하나를 눈 깜짝할 사이에 골라주는 스톱워치 든 조수를 컴퓨터 조작 루프에 앉혀두는 것과 같습니다. 이 판단 속도를 이용하면 마우스·키보드를 대신 움직여 반복 업무를 처리하는 "컴퓨터 사용(Computer Use)" 자동화를 훨씬 저렴하고 빠르게 돌릴 수 있습니다.

## 이걸로 할 수 있는 것
1. 매일 반복하는 웹사이트 클릭·양식 입력(정산 시스템 로그인 후 다운로드 등)을 화면을 보며 대신 눌러주는 봇을 돌린다.
2. 인스타 대시보드나 사내 툴에서 특정 조건(재고 부족, 신규 문의)을 화면으로 감지해 다음 행동(캡처→저장→알림)을 즉시 결정하게 한다.
3. Claude Code로 만든 자동화 스크립트에 "이 화면에서 지금 어떤 버튼을 눌러야 하나"를 초저지연·저비용으로 판단하는 서브 모듈로 Jev를 끼워 넣어, LLM 호출 비용을 줄이면서 프리랜서 클라이언트에게 "화면 자동조작 서비스"를 상품화한다.

## 개요
Claude 같은 비전 LLM이 화면을 보고 다음 행동을 매번 문장으로 추론하는 대신, Jev가 "클릭/스크롤/대기/종료" 같은 미리 정의된 선택지 + 확신도를 즉시 반환하게 하여 컴퓨터 자동화 루프의 속도와 비용을 개선합니다. 반복적이고 선택지가 명확한 판단 구간(다음 동작 결정)을 Jev로, 화면 이해나 예외 처리처럼 유연한 판단이 필요한 구간은 Claude로 분리하는 하이브리드 구조가 핵심 가치입니다.

## 구현 가능성 — 중
Jev는 2026-09-15 출시된 한정 early access 제품으로 공식 문서·SDK 성숙도가 아직 낮고, 화면 인식(OCR/비전) 자체는 Jev의 역할이 아니라 별도 비전 모델이 필요해 통합 설계가 요구됩니다. 다만 macOS에서 화면 캡처·마우스 제어 자체는 성숙한 오픈소스 도구로 가능하고, Jev는 "다음 행동 선택" 구간만 대체하면 되므로 전체를 새로 만드는 것보다는 기존 Claude Code 자동화 파이프라인에 얹는 형태로 접근 가능합니다.

## 필요 도구
- Jev API (TypeSafe AI, `TYPESAFE_API_KEY`) — 유료, early access 신청 필요
- Claude Code CLI (구독, 화면 이해·예외 처리·스크립트 생성용) — 이미 보유
- Python 3 + `pyautogui`, `mss`(화면 캡처), `pynput`(키보드/마우스 제어) — 무료 오픈소스
- macOS `screencapture` 커맨드 / Accessibility 권한 — 무료(OS 내장)
- (선택) Claude vision API — 화면 요소 인식용, 유료(토큰 과금)
- launchd — 정해진 주기로 자동화 루프 실행, 무료(OS 내장)

## 구현 단계
1. TypeSafe AI에 Jev early access 신청, `TYPESAFE_API_KEY` 발급 후 `.env`에 저장.
2. macOS 시스템 설정 > 개인정보 보호 > 손쉬운 사용에서 터미널/Python에 화면 제어 권한 부여.
3. `mss`로 화면을 주기적으로 캡처하고, Claude vision(또는 로컬 OCR)으로 화면 내 버튼·텍스트 좌표를 추출하는 파이썬 모듈 작성.
4. 추출된 화면 상태를 Jev API에 전달해 "클릭/스크롤/대기/종료" 등 사전 정의된 행동 타입 + 확신도를 반환받는 판단 함수 작성.
5. 확신도가 낮으면 Claude Code(문장 추론)로 폴백하는 하이브리드 로직 추가해 정확도 안전망 확보.
6. `pyautogui`로 Jev가 고른 행동(클릭 좌표, 키 입력)을 실제로 실행하는 액션 실행기 연결.
7. 특정 반복 업무(예: 정산 파일 다운로드) 한 가지를 골라 end-to-end 시나리오로 먼저 테스트.
8. 성공 시 launchd plist로 주기 실행 등록, 실패 로그는 별도 파일로 남겨 디버깅 가능하게 구성.
9. 안정화되면 이 자동화 모듈을 템플릿화해 다른 반복 업무(클라이언트 프로젝트)에 재사용/판매 가능하도록 문서화.

## 예상 공수
- Jev early access 승인 대기: 수일~수주(통제 불가 변수)
- 화면 캡처+행동 실행 기본 파이프라인: 4~6시간
- Jev 연동 및 하이브리드 폴백 로직: 3~5시간
- 첫 실전 시나리오 테스트·디버깅: 3~4시간
- 난이도: 중~상 (macOS 권한/좌표 처리는 익숙하면 쉽지만, Jev API 스펙이 아직 불안정해 시행착오 가능성 높음)

## 리스크/유의점
- Jev가 early access 단계라 API 스펙·요금이 변경될 수 있고, 문서 부족으로 통합에 예상보다 시간이 더 걸릴 수 있음.
- 화면 좌표 기반 자동화는 해상도/창 크기/테마 변경에 취약해 운영 환경이 조금만 바뀌어도 깨질 수 있음 — 좌표보다 요소 인식 기반 설계 권장.
- 자동 마우스/키보드 제어는 되돌리기 어려운 실수(잘못된 클릭으로 데이터 삭제·전송 등)를 일으킬 수 있으므로, 실행 전 확인 단계(dry-run/스크린샷 로그)를 반드시 둘 것.
- 클라이언트 업무에 적용 시 민감 정보(로그인 정보, 화면 내용)가 외부 API(Jev, Claude vision)로 전송되므로 보안·개인정보 처리 방침 확인 필요.
