# MCP·API·스킬 조합, 역할 분리로 완주

## 쉽게 말하면
MCP는 AI가 외부 데이터나 프로그램에 "연결"하는 통로이고, 스킬(SKILL.md)은 그 연결된 데이터를 "어떻게 처리할지" 정해주는 규칙서입니다. 비유하면 MCP는 창고 문을 열어주는 열쇠, 스킬은 창고 안 물건을 정리하는 매뉴얼입니다. 열쇠만 있으면 물건을 마음대로 쌓아두고, 매뉴얼만 있으면 창고 문을 못 열어 아무것도 못 합니다 — 둘 다 있어야 일이 끝납니다.

## 이걸로 할 수 있는 것
1. 카드 문자·이메일 영수증을 자동으로 읽어 가계부·경비 시트에 내가 정한 분류 규칙대로 정리한다.
2. Claude Code로 만든 개인 자동화(예: 인스타 대시보드 수집기)에 "판정 규칙"을 SKILL.md로 분리해 외주·유료 제공 시 재현성 있는 결과물로 판다.
3. 클라이언트마다 다른 분류 기준(업종별 회계 항목, 팀별 보고 양식)을 같은 MCP 연결에 스킬만 갈아끼워 대응해, 자동화 컨설팅 상품을 여러 고객에 재사용한다.

## 개요
같은 작업(카드 문자 24통 → 가계부 입력)을 API 문서만, MCP만, 스킬만, MCP+스킬 네 조합으로 비교한 실험으로, "연결"과 "규칙"이 분리된 개념임을 실증한다. MCP+스킬 조합만 21건을 우리 기준 6분류로 정확히 완주했고, 나머지 세 조합은 분류가 제멋대로거나 아예 저장에 실패했다. 이는 현재 만들고 있는 개인 자동화(인스타 대시보드, 정보 레이더 등)를 "이번 것도 연결만 있고 규칙이 없는 건 아닌가"라는 틀로 점검하고, 나아가 자동화를 수익화할 때 스킬 파일을 상품의 핵심 자산으로 삼을 수 있다는 근거를 준다.

## 구현 가능성 — 상
- 스킬은 SKILL.md 한 파일에 한국어로 규칙을 적는 방식이라 코딩 불필요, Claude Code에서 바로 적용 가능.
- MCP는 이미 공식 표준(로컬 실행형·원격 URL형)으로 정착되어 있고, 이 프로젝트(ai-info-radar)는 이미 Claude Code 기반 자동화 파이프라인을 운영 중이라 스킬 분리 작업만 추가하면 됨.
- 근거 영상이 실제 실험(4조건 비교, 동일 입력 24건)으로 결과 차이를 증명해 재현 가능성이 높음.

## 필요 도구
- Claude Code (이미 사용 중, 무료 사용량 내)
- SKILL.md 작성 — 추가 비용 없음, 텍스트 파일
- MCP 서버 — 이미 연결된 것 재사용 가능(예: GitHub, 파일시스템 MCP), 신규 연결 시 서버별 무료/유료 확인 필요
- (선택) 가계부/경비 자동화 실험용 소규모 MCP 서버 — 직접 만들 경우 Node/Python 스크립트, 무료
- 참고 자료: modelcontextprotocol.io(무료), claude.com/blog/skills-explained(무료), 오픈카톡 '방구석모각코' 배포 규칙 파일(무료)

## 구현 단계
1. 영상 9분 시청 후, 현재 운영 중인 ai-info-radar 수집 루틴(인스타 대시보드 데이터 가져오기, 정보 채점 등) 중 "MCP/API 연결은 있는데 판정 규칙이 코드 안에 하드코딩되어 있는" 부분을 목록화한다.
2. 그중 하나(예: 정보 항목 채점 기준, 주제 분류 기준)를 골라 현재 로직에서 "규칙" 부분만 분리해 `SKILL.md` 초안을 작성한다 — 분류 기준, 우선순위, 예외 처리를 한국어 문장으로 명시.
3. Claude Code에 해당 MCP 연결(또는 기존 스크립트 실행 방식)은 그대로 두고, SKILL.md만 붙여 같은 입력으로 전/후 결과를 비교 테스트한다.
4. 결과가 개선되면(분류 일관성, 완주율) 같은 패턴을 다른 자동화 파이프라인에도 적용하고, 이 SKILL.md 자체를 "재사용 가능한 규칙 자산"으로 문서화해 향후 고객 맞춤 자동화 상품(예: 소상공인 경비 정리 자동화)의 판매 단위로 만든다.
5. 오픈카톡 '방구석모각코'에서 배포하는 정리표·판정표·가계부 규칙 파일을 받아 SKILL.md 작성 템플릿으로 참고한다.

## 예상 공수
- 1단계(시청+점검): 30분, 난이도 하
- 2~3단계(SKILL.md 작성+테스트): 1~2시간, 난이도 중 (기존 로직 파악이 관건)
- 4~5단계(다른 파이프라인 확장+상품화 문서화): 반나절~1일, 난이도 중상 (이 단계부터 수익화 관점의 설계 판단 필요)

## 리스크/유의점
- 영상 실험은 조건별 1회 실행이라 반복 재현성은 검증되지 않음 — 자신의 파이프라인에 적용할 때는 여러 번 테스트해서 일관성 확인 필요.
- 남이 만든 MCP 서버를 가져다 쓸 경우 출처(운영 주체, 코드 공개 여부)를 반드시 확인 — 카드 문자·가계부처럼 민감한 개인 금융 데이터를 다루는 MCP는 신뢰 검증 없이 연결하면 위험.
- MCP 연결이 늘어날수록 컨텍스트/비용 부담이 커진다는 언급(영상 4:00) — 자동화 상품화 시 필요한 MCP만 선별해 붙일 것.
