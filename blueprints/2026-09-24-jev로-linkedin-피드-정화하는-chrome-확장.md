# Jev로 LinkedIn 피드 정화하는 Chrome 확장

## 쉽게 말하면
LinkedIn 피드에 있는 "성공 자랑", "감동 스토리 척", AI가 대충 쓴 것 같은 광고성 글들을 브라우저가 자동으로 걸러주는 도구입니다. 스팸 메일함이 스팸을 걸러주듯, 이 확장은 Jev(AI 모델)에게 각 게시물을 보여주고 "이거 진짜 알맹이 있는 글이야, 아니면 슬롭(잡동사니)이야?"를 판단시켜 화면에서 지우거나 흐리게 만듭니다.

## 이걸로 할 수 있는 것
1. 출근길에 LinkedIn을 열었을 때 "10년 전 실패담이 지금의 저를 만들었습니다" 류의 감성팔이 게시물이 자동으로 사라져 있습니다.
2. 채용 담당자로서 후보자 소싱 중 피드를 스크롤할 때, AI가 생성한 티 나는 "인사이트 5가지" 카드뉴스형 포스트가 자동 필터링되어 시간을 아낍니다.
3. 이 필터링 엔진 자체를 "LinkedIn 피드 클리너 Pro"로 패키징해, 유료 크롬 확장(예: 월 3,900원 구독)으로 출시해 부수입을 만듭니다.

## 개요
LinkedIn 웹페이지의 DOM에서 게시물 텍스트를 추출한 뒤, Jev API로 "슬롭 여부/유형"을 분류시켜 낮은 품질로 판정된 게시물의 표시 방식(숨김/흐림/접기)을 자동 조정하는 Chrome 확장입니다. 반복적인 스크롤·수동 필터링 노동을 없애고, 이후 이 파이프라인을 다른 SNS(X, 인스타)로 확장하거나 유료 제품화할 수 있는 재사용 가능한 "AI 콘텐츠 필터 엔진"을 만드는 것이 핵심 가치입니다.

## 구현 가능성 — 상
- Chrome 확장(Manifest V3)은 표준 기술이며 DOM 스크래핑·MutationObserver로 무한 스크롤 대응이 잘 확립된 패턴입니다.
- Jev가 텍스트 분류(짧은 글 → 카테고리 라벨) 작업에 적합한 용도이며, 개인 MacBook에서 별도 서버 없이 확장 자체에서 API 호출만으로 완결됩니다.
- 원본(slopmop.lol)이 이미 유사 컨셉의 존재를 증명했으므로 기술적 리스크는 낮고, 나머지는 UX/배포 작업입니다.

## 필요 도구
- Chrome Extension (Manifest V3, JS/TS) — 무료
- Jev API (텍스트 분류용 호출) — 사용량 과금, 게시물당 토큰 소량이라 저비용
- Claude Code — 확장 코드/매니페스트/배포 스크립트 생성용, 기존 구독 활용
- IndexedDB 또는 chrome.storage.local — 판정 결과 캐싱(같은 글 재호출 방지), 무료
- (선택) Chrome Web Store 개발자 계정 — 최초 1회 $5
- (선택, 유료화 시) Stripe 또는 Gumroad — 구독 결제, 거래 수수료만 발생

## 구현 단계
1. `manifest.json` 작성: `content_scripts`로 linkedin.com/feed 매칭, `storage`·`activeTab` 권한 설정.
2. content script에서 LinkedIn 피드 DOM 셀렉터(게시물 카드 단위) 식별 후 텍스트 추출 함수 작성 (Claude Code로 LinkedIn 실제 페이지 HTML 구조 분석 요청).
3. 추출한 텍스트를 background service worker로 전달, Jev API에 배치 호출 (예: "이 게시물이 진짜 정보/경험인지, AI 생성 슬롭/자랑 콘텐츠인지 분류하라" 프롬프트).
4. 판정 결과를 게시물 DOM 요소별로 매핑해 `display:none` 또는 반투명 접힘 UI 적용, 클릭 시 "그래도 보기" 버튼 제공.
5. chrome.storage.local에 (게시물 해시 → 판정) 캐시 저장해 스크롤 재방문 시 중복 API 호출 방지.
6. 팝업 UI(확장 아이콘 클릭 시)에서 필터 강도 슬라이더(관대/보통/엄격) 및 오늘 걸러낸 게시물 수 통계 표시.
7. 개인 사용으로 1주일 테스트 후 오탐/미탐 프롬프트 튜닝.
8. 제품화 결정 시: 라이선스 키 발급 로직 + Stripe 결제 페이지 연동, Chrome Web Store 등록·심사 제출.

## 예상 공수
- 개인 사용 MVP: 8~12시간 (난이도: 중 — DOM 셀렉터가 LinkedIn UI 변경에 취약해 삽질 가능성 있음)
- 제품화(결제·배포 포함): 추가 15~20시간 (난이도: 중상 — 크롬 스토어 심사, 결제 연동, 라이선스 검증)

## 리스크/유의점
- LinkedIn은 이용약관상 자동화 스크래핑을 명시적으로 금지하므로, 서버로 데이터를 전송·수집·재판매하지 않고 순수 클라이언트 사이드 필터링(사용자 로컬 판단)에 그치는 것이 중요합니다.
- LinkedIn이 주기적으로 DOM 구조를 바꾸므로 셀렉터 유지보수가 지속적으로 필요합니다.
- 제품화 시 "타인의 게시물을 AI로 판정해 숨긴다"는 특성상 오탐(좋은 글을 슬롭으로 오판)에 대한 사용자 불만 가능성이 있어, 판정 근거를 툴팁으로 보여주는 투명성 장치가 필요합니다.
- 대량 게시물에 대해 매번 API 호출 시 비용이 누적되므로 캐싱·배치 호출 설계가 필수입니다.
