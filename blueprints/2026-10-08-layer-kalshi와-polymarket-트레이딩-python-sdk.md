# Layer – Kalshi와 Polymarket 트레이딩 Python SDK

## 쉽게 말하면
Layer는 "미래 사건에 베팅하는 시장"인 Kalshi와 Polymarket을 파이썬 코드로 거래할 수 있게 해주는 도구입니다. 마치 두 개의 다른 주식거래소에 각각 로그인하는 대신, 하나의 공통 리모컨으로 두 곳 모두를 조작하는 것과 비슷합니다. 기본값이 "모의투자 모드"라서 실제 돈을 쓰기 전에 전략을 안전하게 테스트해볼 수 있습니다.

## 이걸로 할 수 있는 것
1. 매일 아침 특정 이벤트(금리 발표, 선거 결과 등) 예측시장 가격을 자동으로 스캔해서 이상 징후를 알림받기
2. 같은 베팅이 Kalshi와 Polymarket에 동시에 걸려 있을 때, 수수료까지 계산해서 더 싼 쪽에 자동 주문 넣기
3. 실제 돈 없이 "페이퍼 모드"로 몇 주간 전략을 돌려보고 성과를 기록해, 실거래 전환 여부를 데이터로 판단하기

## 개요
이 SDK는 "예측시장(prediction market)에서의 주문 생성·가격 조회·수수료 계산·리스크 관리"를 자동화하는 파이썬 라이브러리입니다. 두 거래소(Kalshi, Polymarket US)의 서로 다른 API를 하나의 주문 형식으로 통일해주고, 모의거래(paper)·실거래(live)·백테스트 세 모드를 지원해 전략 검증부터 실행까지 한 코드베이스로 처리할 수 있다는 점에서 개인 트레이더에게 실질적 가치가 있습니다.

## 구현 가능성: 상
- 근거: `pip install`로 설치 가능한 순수 파이썬 패키지이며, 로컬 맥북에서 바로 실행되는 구조(venue 키도 로컬에서 서명)로 서버 인프라가 필요 없습니다. 원문에 Python 3.11+ 요구사항과 설치 코드가 명시되어 있어 재현 가능성이 높습니다.
- 다만 실거래 전환 시 Kalshi/Polymarket 계정 승인 및 API 키 발급 절차가 외부 의존이라 그 부분은 사용자 통제 밖입니다.

## 필요 도구
- **Python 3.11 이상** (무료) — 원문 명시
- **uselayer 패키지** (`pip install uselayer`, 무료, MIT 라이선스) — 원문 명시
- **Kalshi 계정 및 API 키** (실거래 시 필요, 거래소 자체 가입/승인 절차 — 비용 구조는 [공식 문서 확인 필요])
- **Polymarket US 계정 및 API 키** (실거래 시 필요, 비용 구조는 [공식 문서 확인 필요])
- **Layer API 키** (선택, `matches()`·`buy_best()` 등 크로스 베뉴 기능 사용 시 필요 — 무료/유료 여부는 원문에 명시 없음, [공식 문서 확인 필요])
- **텍스트 에디터 또는 Jupyter 노트북** (무료, 전략 코드 작성용 — [추정])
- **cron 또는 launchd** (맥북 내장, 무료 — 정기 실행 스케줄링용, [추정])

## 구현 단계
1. 맥북에 Python 3.11+ 설치 확인 (`python3 --version`) 후 가상환경 생성 (`python3 -m venv venv && source venv/bin/activate`).
2. `pip install uselayer`로 패키지 설치.
3. `python/README.md`와 `python/examples/`의 예제 코드를 받아 로컬에서 실행해보며 `Client()` 기본 동작(페이퍼 모드) 확인.
4. `client.markets(limit=20)`으로 Polymarket US의 공개 시장 목록을 조회해 관심 있는 이벤트(예: 특정 경제지표 발표) 필터링 로직 작성.
5. 관심 시장에 대해 `client.book()`으로 호가창을 가져오고, 원하는 전략 조건(가격 임계값 등)을 코드로 정의.
6. `client.preview(order)`로 수수료·체결 예상 결과를 먼저 확인한 뒤, 페이퍼 모드에서 `client.send(order)`로 모의 주문 실행.
7. 크로스 베뉴 차익거래를 원한다면 Layer API 키를 발급받아 `client.matches()`와 `buy_best()` 또는 `quote()`/`trade()` 함수로 두 거래소 가격 비교 로직 구성.
8. 포지션 크기, 일일 손실 한도, 손절/익절 등 가드레일 파라미터를 설정해 리스크 관리 규칙 적용.
9. 일정 기간 페이퍼 모드로 운영하며 결과를 로그 파일 또는 CSV로 기록해 전략 성과 검증.
10. 검증 완료 후 Kalshi/Polymarket 실제 API 키를 발급받아 `live` 모드로 전환, 소액부터 실거래 시작.
11. cron 또는 launchd로 스크립트를 주기 실행(예: 매일 1회)하도록 자동화 스케줄 등록.

## 예상 공수
- 설치 및 예제 실행: 1~2시간 (난이도: 하)
- 페이퍼 모드로 기본 전략 작성 및 테스트: 4~8시간 (난이도: 중)
- 크로스 베뉴 차익거래 로직(Layer 키 연동) 구현: 추가 4~6시간 (난이도: 중~상)
- 실거래 전환 및 가드레일 세팅, 모니터링 자동화: 추가 3~5시간 (난이도: 중)
- 총합: 약 12~21시간 [추정]

## 리스크/유의점
- 예측시장 거래는 실제 금전적 손실로 이어질 수 있으므로, 페이퍼 모드에서 충분히 검증한 후 실거래로 전환해야 합니다.
- Kalshi·Polymarket의 거래 가능 여부는 거주 지역·법적 규제에 따라 다를 수 있어, 실거래 전 각 거래소의 이용 약관과 거주국 규제를 반드시 확인해야 합니다 [공식 문서 확인 필요].
- Layer API 키 사용 시 "검색 필터와 마켓 ID만 전송되고 가격·주문·포지션·거래소 키는 전송되지 않는다"고 원문에 명시되어 있으나, 이는 Layer 측의 주장이므로 민감한 전략 정보를 다루기 전에 개인정보 처리 방침을 직접 확인하는 것이 안전합니다.
- 수수료 계산 로직(`fee-golden.json` 기반 테스트)이 각 거래소의 최신 수수료 체계 변경을 실시간 반영하는지는 원문에 구체적 업데이트 주기가 없어 [공식 문서 확인 필요] 상태입니다.
- 가드레일(포지션 크기, 손절매 등) 기능이 존재하더라도, 그 파라미터를 본인이 직접 보수적으로 설정하지 않으면 리스크 관리 효과가 떨어질 수 있습니다.
