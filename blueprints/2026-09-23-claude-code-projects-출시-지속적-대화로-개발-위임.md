# Claude Code Projects로 "상시 대기 개발 위임" 수익화하기

## 쉽게 말하면
Claude Code Projects는 하나의 대화방에 프로젝트 전체 맥락을 기억시켜 두고, 마치 상주 개발자에게 일을 맡기듯 "이거 해줘"라고 던져두면 알아서 진행 상황을 기억하며 계속 작업하게 하는 기능입니다. 매번 처음부터 설명할 필요 없이, 어제 하던 일의 이어서 지시만 추가하면 되는 셈입니다.

## 이걸로 할 수 있는 것
1. 코코베이비 앱의 반복 버그 수정이나 소소한 기능 추가를 하나의 Project에 몰아넣고, 출근 전 스마트폰으로 지시만 남기면 낮 동안 진행되게 한다.
2. 클라이언트별로 Project를 하나씩 만들어 각 프로젝트의 코드 스타일·요구사항을 기억시켜두고, 반복 설명 없이 외주 개발을 대행해주는 서비스로 판매한다.
3. ai-info-radar 같은 개인 자동화 도구의 유지보수(크론 수정, 파서 개선 등)를 Project에 위임해 본업 시간을 빼앗기지 않고 사이드 프로젝트를 굴린다.

## 개요
Claude Code Projects는 "매번 컨텍스트를 새로 주입"해야 했던 장기 작업의 마찰을 없애고, 지속적 대화 하나가 프로젝트의 상태·이력·의도를 계속 들고 있게 만든다. 개인 개발자/1인 컨설턴트 입장에서는 여러 클라이언트 프로젝트를 동시에 "위임 상태"로 굴릴 수 있어, 실제 코딩 시간을 줄이면서 처리 가능한 프로젝트 수를 늘리는 것이 핵심 가치다.

## 구현 가능성
**상** — 별도 개발 없이 Claude Code를 설치하고 Projects 기능을 켜기만 하면 바로 사용 가능하며, 이미 이 환경(맥북 + Claude Code CLI)에서 매일 쓰고 있는 도구의 연장선이라 학습 곡선이 거의 없다.

## 필요 도구
- Claude Code CLI (Anthropic 구독 필요, Pro/Max 플랜 — 유료)
- Claude Code Projects 기능 (CLI 내장, 별도 비용 없음, 구독에 포함)
- 기존 git 저장소 (코코베이비 앱, ai-info-radar 등 — 무료)
- (선택) 텔레그램 봇 연동 — 이미 구축된 브리핑 봇 인프라 재사용해 Project 진행 상황 알림 받기 (무료, 기존 인프라)
- (선택, 외주 서비스화 시) 클라이언트별 별도 GitHub 저장소/권한 관리 — 무료~소액

## 구현 단계
1. Claude Code에서 Projects 기능이 활성화되어 있는지 `/config` 또는 설정 화면에서 확인한다.
2. 코코베이비 앱 저장소에 Project 하나를 생성하고, CLAUDE.md에 "이 프로젝트의 반복 규칙"(코딩 컨벤션, 테스트 방법, 배포 절차)을 미리 기록해 매번 재설명하지 않도록 한다.
3. 하루 시작 시 "오늘 처리할 일" 목록을 Project 대화에 짧게 던지고, 낮 동안은 진행 상황만 확인하는 루틴을 1주일간 시험 운영한다.
4. 진행 알림을 텔레그램 봇으로 받도록 연동해(기존 브리핑 봇 인프라 활용), 맥북 앞에 있지 않아도 승인/추가 지시가 가능하게 만든다.
5. 외주·컨설팅 판매를 고려한다면, 신규 클라이언트 온보딩용 Project 템플릿(CLAUDE.md + 초기 프롬프트 세트)을 만들어 계약 1건당 셋업 시간을 30분 이내로 줄인다.
6. 한 달 시험 운영 후 "위임으로 절약된 시간 대비 검토·수정에 든 시간"을 기록해, 어떤 유형의 작업이 위임에 적합한지 기준을 정리한다.

## 예상 공수
- 기본 셋업 및 1개 프로젝트 시험 운영: 2~3시간, 난이도 하
- 텔레그램 알림 연동 (기존 봇 재사용): 1~2시간, 난이도 중
- 외주 판매용 템플릿화 및 다중 클라이언트 운영 체계: 4~6시간, 난이도 중

## 리스크/유의점
- 위임한 작업의 결과를 매번 검토하지 않으면 프로덕션 코드(코코베이비 앱)에 조용히 결함이 누적될 수 있어, 중요 변경은 반드시 diff 리뷰 후 병합해야 한다.
- 여러 프로젝트를 동시에 "상시 대기"시키면 구독 사용량(토큰/시간)이 예상보다 빨리 소진될 수 있으므로 초반에는 1~2개 프로젝트로 제한해 비용 감을 잡는 것이 안전하다.
- 클라이언트 코드를 다루는 외주 서비스로 확장할 경우, 각 프로젝트 간 컨텍스트/자격정보가 섞이지 않도록 Project 분리와 접근 권한 관리를 명확히 해야 한다.
