# Public Browser — Chrome MCP 서버로 브라우저 자동화 툴콜 40% 절감

## 쉽게 말하면
Claude 같은 AI가 웹사이트를 대신 조작(클릭, 입력, 스크롤)하게 하려면 보통 "화면 보기 → 클릭 → 화면 보기 → 클릭"을 반복하며 API 호출을 엄청 많이 씁니다. Public Browser는 이 왔다갔다를 줄여서 같은 작업을 더 적은 호출로 끝내주는 "크롬 리모컨" 같은 도구입니다. 택배기사가 한 번에 여러 집 배달 동선을 짜듯, AI가 브라우저 조작 명령을 더 똑똑하게 묶어서 처리하는 셈입니다.

## 이걸로 할 수 있는 것
1. Jev나 클로드가 로그인이 필요한 사이트(인스타 대시보드, 사내 어드민 등)를 대신 순회하며 데이터를 긁어오는 자동화를 더 저렴하게 돌릴 수 있습니다.
2. 고객사에게 "웹사이트 자동 모니터링/데이터 수집 봇"을 만들어주는 외주·SaaS 상품의 API 비용을 줄여 마진을 높일 수 있습니다.
3. 반복적인 웹 리서치(경쟁사 가격 조사, 뉴스 스크래핑)를 Claude Code 에이전트에 붙여 자동 실행시키고, 그 결과를 사용자의 정보 레이더 파이프라인처럼 리포트화할 수 있습니다.

## 개요
이 도구는 MCP(Model Context Protocol) 프로토콜로 Claude가 크롬 브라우저를 직접 조작하게 해주는 서버로, 기존 브라우저 자동화 MCP보다 툴 호출 횟수를 약 40% 줄여 토큰·API 비용을 절감합니다. 브라우저 기반 자동화(웹 스크래핑, 폼 제출, UI 테스트, 리서치 에이전트)를 만들 때 실행 속도와 비용 효율을 동시에 개선하는 인프라 레이어로서 가치가 있습니다.

## 구현 가능성 — 상
- Chrome MCP 서버는 Claude Code/Claude Desktop의 `mcp` 설정에 그대로 등록 가능한 표준 방식이라 별도 인프라 구축이 거의 불필요합니다.
- 사용자는 이미 Claude Code로 자동 파이프라인(사이클 산출, gh-pages 배포)을 운영 중이라 MCP 서버 연동 경험이 있어 진입장벽이 낮습니다.
- 다만 저장소가 신규(Show HN, 포인트 2점)라 문서화·안정성이 검증되지 않아 초기 트러블슈팅 시간이 필요할 수 있습니다.

## 필요 도구
- **Public Browser MCP 서버** (GitHub: Silbercue/public-browser) — 무료, 오픈소스
- **Node.js / npm** — 무료, 설치 필요
- **Chrome 브라우저** — 무료
- **Claude Code CLI** (이미 사용 중) — 사용자의 기존 구독/API 요금제
- **Claude API 키 (Anthropic)** — 사용량 기반 과금, 툴콜 감소분만큼 절감 효과
- (선택) **PM2 또는 launchd** — 맥에서 백그라운드 상시 구동용, 무료

## 구현 단계
1. `git clone https://github.com/Silbercue/public-browser`로 저장소를 받고 README의 설치 요구사항(Node 버전 등)을 확인합니다.
2. `npm install` 후 로컬에서 MCP 서버를 실행해 정상 기동되는지(포트, 로그) 확인합니다.
3. Claude Code의 MCP 설정 파일(`~/.claude/mcp_servers.json` 또는 `.mcp.json`)에 이 서버를 등록하고, `claude mcp list`로 연결을 확인합니다.
4. 간단한 테스트 태스크(예: 특정 페이지 방문 후 텍스트 추출)를 시켜서 기존 브라우저 MCP(예: Playwright MCP) 대비 툴콜 수와 응답 속도를 비교 측정합니다.
5. 검증되면 기존 인스타 대시보드 크롤링([[ig-dashboard-source]] 관련 흐름)이나 새로운 리서치 자동화 스크립트에 이 MCP를 붙여 실제 반복 작업에 투입합니다.
6. 안정화 후, 이 자동화를 활용한 "웹 모니터링 자동화" 서비스를 소규모로 패키징해 외주/구독형 상품으로 검토합니다.

## 예상 공수
- 설치 및 로컬 테스트: 1~2시간
- Claude Code MCP 연동 및 검증: 1~2시간
- 기존 자동화 파이프라인에 통합: 2~4시간
- 난이도: 중 (신규 오픈소스라 문서 부족 가능성, MCP 설정 경험이 있으면 수월)

## 리스크/유의점
- Show HN 포인트가 2점으로 매우 초기 단계이며, 커뮤니티 검증(버그, 보안 이슈)이 부족합니다.
- 브라우저 자동화는 로그인 세션·쿠키 등 민감 정보를 다루므로, 어드민/인스타 계정 자동화에 쓸 경우 자격증명 보관 방식을 반드시 점검해야 합니다.
- "40% 툴콜 감소"는 저장소 측 자체 주장으로, 실제 사용 시나리오에서 재현되는지 직접 벤치마크 후 도입 여부를 결정해야 합니다.
- 유지보수자가 1인 프로젝트일 가능성이 높아, 장기 의존 시 포크해 직접 관리할 준비가 필요합니다.
