# Jev로 관련성 판단 자동화 — LLM 대신 System One 분류기 붙이기

## 쉽게 말하면
Jev는 ChatGPT처럼 대화를 나누는 AI가 아니라, "이건 A야 B야?" 같은 즉각적 판단만 아주 빠르고 싸게 내리는 전용 AI다. 비유하자면 LLM이 신중하게 보고서를 쓰는 컨설턴트라면, Jev는 컨베이어벨트 앞에서 순식간에 불량품을 골라내는 검수원이다.

## 이걸로 할 수 있는 것
1. 지금 인스타 대시보드에서 캡션을 보고 "AI 관련/무관"을 판단하는 작업을 Jev로 대체해 속도·비용 절감
2. 매일 쌓이는 뉴스레터·트렌드 텍스트를 실시간 분류해 알림 우선순위를 매기는 미니 서비스 운영
3. Claude Code로 만든 자동화 파이프라인 중간에 Jev 분류 단계를 끼워 넣어 "이 항목은 사람 검토 필요/불필요"를 즉시 결정

## 개요
현재 관련성 판단(캡션 → AI 관련/무관)에 LLM을 쓰고 있다면 이는 비용·지연 면에서 과잉스펙이다. Jev는 이런 이진/다중 분류형 "빠른 판단"에 특화된 모델이라 같은 작업을 더 싸고 빠르게 처리할 수 있어, 자동화 파이프라인의 비용 구조 자체를 바꿀 잠재력이 있다.

## 구현 가능성: 중
Jev는 2026-09 출시된 신생 모델로 API 안정성·문서·한국어 지원 여부가 아직 검증되지 않았다(모델 지식 컷오프 이후 출시). 무료 티어 존재 여부, API 스펙, 요금 체계를 실제 가입 후 확인해야 실현 가능성이 확정된다. 다만 개념 자체(경량 분류기로 교체)는 기술적으로 단순해 진입 장벽은 낮다.

## 필요 도구
- Jev API (TypeSafe AI, console.typesafe.ai 가입 필요 — 무료 티어 여부·요금 미확정, 확인 필요)
- 기존 ai-info-radar 저장소의 캡션 데이터 (data/ig_export.json 등, 비용 없음)
- Claude Code (자동화 스크립트 작성·테스트, 이미 보유·비용 없음)
- Python 또는 Node 스크립트 (API 호출용, 비용 없음)
- (선택) 기존 LLM 분류 결과 로그 — A/B 비교 베이스라인, 비용 없음

## 구현 단계
1. YouTube 영상(7분) 시청하며 Jev의 입출력 형태(확률분포 출력 등) 메모
2. console.typesafe.ai 가입, 무료 티어 한도·API 키 발급 여부 확인
3. Jev API 문서에서 분류(classification) 태스크 호출 방식 확인 — 입력: 텍스트, 출력: 카테고리+확신도 형태 지원 여부 체크
4. ai-info-radar 저장소에서 기존 관련성 판단 로직(현재 LLM 프롬프트) 위치 파악
5. 캡션 20~30개 샘플 추출해 기존 LLM 결과와 Jev 결과를 나란히 비교하는 테스트 스크립트 작성
6. 두 결과의 일치율·오차 케이스 확인, Jev 확신도 임계값 설정
7. 일치율이 충분히 높으면(예: 90%+) 관련성 판단 단계를 Jev 호출로 교체, 낮으면 폴백으로 LLM 유지(하이브리드 구조)
8. 실제 파이프라인(launchd 스케줄)에 통합 후 1주일 운영하며 오분류 사례 수집·조정

## 예상 공수
- 영상 시청 + 가입/문서 확인: 30분
- 테스트 스크립트 작성 및 비교 실험: 2~3시간
- 파이프라인 통합 및 검증: 1~2시간
- 총 약 4~6시간, 난이도: 중 (신규 API 학습 곡선이 변수)

## 리스크/유의점
- Jev는 출시 초기 모델이라 API 스펙·요금제가 급변할 수 있음 — 프로덕션 의존 전 무료 티어로 충분히 검증 필요
- "확률분포 출력"이라는 특성상 기존 LLM처럼 명확한 텍스트 답변이 아닐 수 있어 별도 파싱 로직 설계 필요
- 캡션이 한국어 위주라면 Jev의 한국어 성능이 검증되지 않은 상태 — 초기 실험에서 반드시 확인
- 이 영상은 스폰서(#ad) 포함 콘텐츠이므로 실제 성능 주장은 별도 벤치마크로 검증할 것
