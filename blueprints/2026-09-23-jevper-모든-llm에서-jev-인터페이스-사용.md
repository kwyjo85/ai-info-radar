# Jevper: 모든 LLM에서 Jev 인터페이스 사용

## 쉽게 말하면
Jevper는 "Jev"라는 AI 도우미의 화면과 사용법은 그대로 두고, 뒤에서 실제로 답변을 만드는 두뇌(모델)만 원하는 것으로 갈아 끼울 수 있게 해주는 어댑터입니다. 리모컨(Jev 인터페이스)은 그대로 쓰면서 TV(모델)만 다른 회사 제품으로 바꿔 끼우는 것과 비슷합니다.

## 이걸로 할 수 있는 것
1. 이미 계약해 쓰고 있는 Claude Code나 다른 LLM API를 그대로 활용해 Jev와 동일한 작업 흐름(프롬프트·자동화 스크립트)을 재사용한다.
2. 비용이 비싼 모델 대신 저렴한 로컬 모델로 Jev 인터페이스를 구동해 반복 업무(보고서 작성, 정보 수집 등) 자동화 비용을 낮춘다.
3. 같은 자동화 스크립트를 Claude·GPT·로컬 모델 등 여러 백엔드로 돌려보며 가장 저렴하거나 정확한 조합을 찾아 외주·컨설팅 상품으로 판매한다.

## 개요
Jevper는 Jev의 사용자 인터페이스/워크플로우 레이어와 실제 추론을 수행하는 LLM 백엔드를 분리하는 오픈소스 도구로, 특정 모델에 종속되지 않고 원하는 모델(로컬, API, Claude 등)로 자유롭게 교체할 수 있게 한다. 기존에 Jev용으로 만들어둔 자동화 자산을 그대로 재사용하면서 비용·성능을 최적화할 수 있다는 데 가치가 있다.

## 구현 가능성: 중
- GitHub 오픈소스 프로젝트라 코드는 확인 가능하지만, Jev 자체가 2026-09에 막 출시된 신생 모델이라 생태계·문서가 아직 부족할 가능성이 큼 (근거: HN 포인트 7·댓글 1로 초기 단계 프로젝트임을 시사)
- MacBook에서 CLI 도구로 설치하는 것 자체는 어렵지 않을 것으로 보이나, Jev API 스펙 문서화 상태를 먼저 확인해야 함

## 필요 도구
- jevper (GitHub, 무료·오픈소스)
- Python 또는 Node.js 런타임 (저장소 확인 필요, 무료)
- Claude Code CLI (이미 사용 중, API 사용량만큼 유료)
- Ollama 등 로컬 LLM 실행 도구 (무료, 선택)
- Jev API 키 (출시 초기라 무료/유료 여부 확인 필요)

## 구현 단계
1. `git clone https://github.com/zhulinchng/jevper`로 저장소를 받고 README·설치 가이드를 확인한다.
2. macOS에 필요한 런타임(Python/Node)과 의존성을 설치한다.
3. 보유한 LLM 접근 수단(Claude Code API 키, Ollama 로컬 모델 등)을 jevper 설정 파일에 등록한다.
4. 기존에 Jev용으로 만들어둔 프롬프트·워크플로우를 jevper 경유로 Claude나 로컬 모델에 돌려보고 결과를 비교한다.
5. ai-info-radar 같은 반복 자동화 파이프라인 하나를 골라 모델을 바꿔가며 비용·속도·품질을 기록한다.
6. 가장 효율적인 모델 조합을 확정해 실제 업무(콘텐츠 생성, 고객 대응 자동화 등)에 적용하고 수익화 가능성을 검증한다.

## 예상 공수
- 설치 및 기본 연동: 1~2시간, 난이도 하
- 기존 워크플로우 이식 및 모델 비교 테스트: 3~5시간, 난이도 중
- 실제 수익화 파이프라인 적용: 추가 1~2일, 난이도 중상 (프로젝트 성숙도에 따라 변동)

## 리스크/유의점
- 출시 초기 프로젝트라 문서·커뮤니티 지원이 부족해 트러블슈팅에 시간이 더 들 수 있음
- Jev 인터페이스와 대체 모델 간 프롬프트 호환성이 완벽하지 않아 품질이 떨어질 수 있음
- API 키·인증 정보를 jevper 설정에 저장할 때 로컬 파일 권한 관리에 주의(민감정보 노출 방지)
