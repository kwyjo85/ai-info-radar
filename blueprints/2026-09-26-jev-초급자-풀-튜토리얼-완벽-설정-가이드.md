# Jev 초급자 풀 튜토리얼: 완벽 설정 가이드

## 쉽게 말하면
Jev는 AI에게 긴 글을 쓰게 하는 대신 "예/아니오", "점수 몇 점", "이 중 어느 것" 같은 짧고 명확한 결정 하나만 아주 빠르게(0.5초 이내) 내려주는 전용 엔진입니다. 마치 긴 보고서를 써주는 비서 대신, 옆에서 "이거 맞아 틀려?"만 초스피드로 판정해주는 검수관을 따로 두는 것과 비슷합니다. Claude 같은 범용 LLM은 여전히 글쓰기·요약·코딩에 쓰고, "이건 관련 있나/없나" 같은 반복적 판정만 Jev로 빼서 속도와 비용을 동시에 줄이는 조합 전략입니다.

## 이걸로 할 수 있는 것
1. ai-info-radar 대시보드에서 매일 수집되는 유튜브/인스타 항목 중 "이 주제와 관련 있는가"를 Claude 풀 호출 없이 Jev로 1차 스크리닝해 API 비용을 줄인다.
2. 대시보드의 초기 채점(흥미/실현/효과/난이도/과장) 중 단순 True/False나 0~10점 스코어링 항목을 Jev의 Score/Choice 프리미티브로 대체해 채점 속도를 높인다.
3. 고객 문의·이력서·콘텐츠 검수 같은 반복 판정 업무를 맡는 외부 클라이언트에게 "초저지연 자동 분류 시스템"을 만들어주고 컨설팅/구축 비용을 받는 부업 아이템으로 활용한다.

## 개요
이 영상은 Jev(Typesafe)를 처음부터 설정하고, 이력서 스크리닝·고객 티켓 분류·콘텐츠 모더레이션 3가지 실전 예제를 콘솔 Playground에서 직접 만들어보는 초급자용 튜토리얼입니다. 핵심 가치는 "문단이 아니라 결정 하나만 필요한 지점"을 골라내 그 부분만 Jev로 옮기면, 토큰 생성 없이 확률 기반 답을 반환하므로 지연시간과 비용이 크게 줄어든다는 점입니다.

## 구현 가능성
**상** — 근거: 영상이 실제 API 사용법과 콘솔 UI를 단계별로 보여주는 실용적 가이드 형식이며(대시보드 평가상으로도 과장 지수 3으로 낮음), Jev 공식 SDK(Python/JS)와 Playground가 이미 존재해 개인 맥북에서 별도 인프라 구축 없이 바로 시험 가능. ai-info-radar가 이미 Node/Python 기반 파이프라인과 LLM 호출 구조를 갖추고 있어 특정 판정 지점만 교체하면 되는 국소적 통합.

## 필요 도구
- **Typesafe Jev**: typesafe.ai 웨이팅리스트 가입 후 얼리 액세스 필요, 무료 티어 존재 여부 확인 필요 (사용량 기반 과금 예상)
- **Jev SDK (Python 또는 JS/TS)**: 무료 오픈소스 클라이언트 라이브러리
- **Jev API Key**: 콘솔 대시보드에서 발급, 사용량 과금
- 기존 ai-info-radar 파이프라인 (Node.js 기반, Claude API 연동 부분) — 무료(기존 인프라)
- (선택) Mikey No Code의 무료 마스터클래스/체크리스트 — 마케팅성 자료라 실무엔 선택적

## 구현 단계
1. typesafe.ai에서 얼리 액세스 신청 및 승인 대기 (승인 즉시 진행 가능).
2. 콘솔 Playground에서 State 필드(입력 데이터)와 Questions 패널(판정 질문) 구조를 익히고, Null/Score/Choice 3가지 프리미티브 각각으로 테스트 질문 1개씩 만들어본다.
3. ai-info-radar의 현재 채점 로직(data/ig_export.json 처리 또는 유튜브 항목 분류 스크립트)에서 "관련성 판단(관련/무관)"처럼 이진 판정에 해당하는 지점을 코드에서 찾아 목록화한다.
4. 해당 지점 1곳을 골라 Jev Choice 프리미티브로 대체하는 프로토타입을 Python SDK로 작성 — 기존 Claude 호출 결과와 Jev 결과를 병렬로 비교(A/B) 로그를 남긴다.
5. 정확도가 기존 Claude 판정과 90% 이상 일치하면, 해당 판정 지점의 실제 파이프라인 코드를 Jev 호출로 전환하고 Claude는 서머리/브리핑 생성 등 문단 생성 작업에만 남긴다.
6. 지연시간·비용 절감치를 측정해 기록(예: 항목당 처리 시간, API 비용 변화)하고, 이 결과를 "AI 자동화 비용 절감 사례"로 문서화 — 추후 외부 컨설팅 영업자료로 재사용.
7. (수익화 확장) 이력서 스크리닝/티켓 분류 등 영상 속 예제를 템플릿화해, 소규모 업체 대상 "초저지연 자동 분류 시스템 구축" 패키지 상품을 설계한다.

## 예상 공수
- 얼리 액세스 대기 + 기본 Playground 익히기: 1~2시간 (난이도 하)
- 기존 파이프라인 판정 지점 식별 + 프로토타입 1건 구현: 3~5시간 (난이도 중)
- A/B 비교 및 실제 전환: 2~3시간 (난이도 중)
- 외부 판매용 템플릿화(선택): 별도 8~15시간 (난이도 중상, 영업/문서화 포함)

## 리스크/유의점
- 얼리 액세스/웨이팅리스트 단계라 서비스 안정성·SLA·정식 요금제가 아직 불확실 — 프로덕션 핵심 경로에 바로 투입하기보다 실험적 병행 운영 권장.
- 확률 기반 출력이라 애매한 경계 사례(영상에서 언급된 "borderline content")는 여전히 사람 검토나 Claude 재확인이 필요해 완전 자동화는 아님.
- 신생 스타트업 서비스 특성상 API 스펙 변경 가능성이 있어 SDK 버전 고정 및 변경 로그 모니터링 필요.
- 외부 고객 대상 상품화 시, Jev의 서비스 약관(재판매/화이트라벨 허용 여부)을 사전에 확인해야 함.
