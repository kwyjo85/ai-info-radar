# Jeeva – Jev 기반 중주기 트레이딩 엔진

## 쉽게 말하면
Jeeva는 "AI 자동 매매 로봇"을 직접 조종석에 앉히는 대신, 계기판(대시보드)만 보고 필요할 때 스위치를 켜고 끄는 시스템입니다. AI(Jev)가 시장 데이터를 요약해서 보고 "오를 것 같다/내릴 것 같다/모르겠다"를 판단하면, 엔진이 그 판단대로 자동으로 포지션을 열고 닫아줍니다. 처음엔 가짜 돈(모의투자)으로 안전하게 돌려보다가, 확신이 생기면 스위치 하나로 실거래 전환이 가능합니다.

## 이걸로 할 수 있는 것
1. 퇴근 후에도 Jev가 비트코인/이더리움 등 무기한 선물 시장을 몇 시간~며칠 주기로 계속 관찰하며 자동으로 롱/숏/청산 판단을 내리게 둔다.
2. 새로운 매매 전략 아이디어가 떠오르면 실제 자산을 걸지 않고 모의(mock) 모드로 먼저 몇 주간 백테스트하듯 실전에서 검증해본다.
3. 출근길 지하철에서 휴대폰으로 대시보드만 열어 지난밤 AI가 내린 매매 결정과 손익을 확인하고, 이상하면 즉시 해당 종목 트레이딩을 꺼버린다.

## 개요
이 시스템은 Hyperliquid 거래소의 무기한 선물 시장 데이터 수집 → AI 판단 요청 → 주문 실행 → 로그 기록까지의 전 과정을 자동화합니다. 사람이 매 순간 차트를 보며 판단할 필요 없이, AI가 정해진 주기(예: 1시간~1일)마다 시장 상태를 요약해 판단하고 그 결과에 따라 자동으로 매매하며, 5회 연속 실패 시 자동 청산하는 안전장치까지 갖추고 있어 "AI 활용 주식(선물) 트레이드"를 개인 맥북에서 24시간 무인 운영하는 실질적인 실험대가 됩니다.

## 구현 가능성 — 중
근거: 코드가 오픈소스로 공개되어 있고 구조(Rust 엔진 + Express API + Next.js 대시보드 + MongoDB + TimescaleDB)가 명확하지만, ① Rust/Node/Postgres/Docker를 동시에 다뤄야 하는 풀스택 인프라이고 ② Jev 모델 API 키 발급 및 요금제 확인이 필요하며 ③ Hyperliquid 실계좌 연동 시 자금 리스크 관리가 추가로 필요해, 개인 환경에서 "동작"까지는 가능하나 "안전하게 실거래"까지 가려면 상당한 검증 기간이 필요함.

- **Node.js 18+ / npm** (무료) — frontend, api 빌드
- **MongoDB** (Docker 이미지, 무료) — PERP 설정/엔진 모드 저장
- **TimescaleDB(Postgres 확장)** (Docker 이미지, 무료) — 시세/결정/포지션 히스토리
- **Jev API 키** (TypeSafe AI System One, 직접 API 또는 OpenRouter 경유) — 유료(사용량 과금, 요금 확인 필요)
- **OpenRouter 계정** (선택, Jev 대체 접근 경로) — 유료(크레딧 충전식)
- **Hyperliquid 계정 + API 지갑** — 실거래 시 자금 필요(거래 수수료 발생), 모의모드는 무료
- **ngrok 또는 Cloudflare Tunnel** (선택, 외부에서 대시보드 접속용) — 무료 티어 존재

## 구현 단계
1. `git clone`으로 저장소를 받고 README에 명시된 `.env` 예시 파일을 복사해 MongoDB/Postgres 연결 문자열, Jev API 키를 채운다.
2. `docker compose up`(또는 저장소 제공 compose 파일)으로 MongoDB, TimescaleDB 컨테이너를 먼저 띄우고 정상 기동을 확인한다.
3. `engine/` 디렉토리에서 `cargo build --release`로 Rust 엔진을 빌드하고, `.env`에 `MARKET_DATA_TTL_DAYS` 등 기본값을 확인한다.
4. `api/`에서 `npm install && npm run start`로 Express API를 구동해 MongoDB/Postgres와 연결되는지 확인한다.
5. `frontend/`에서 `npm install && npm run build && npm start`로 대시보드를 띄우고, `API_URL` 환경변수가 로컬 API를 가리키도록 설정한다.
6. 대시보드에서 BTC-PERP 등 1개 종목만 "샘플링만 켜기"로 활성화해 시세 데이터가 TimescaleDB에 쌓이는지 며칠간 관찰한다.
7. 문제없으면 해당 종목 "트레이딩 활성화" + DecisionMaker로 "Jev"를 선택하고, 엔진 전체 모드가 **mock**인지 반드시 재확인 후 저장한다.
8. 최소 1~2주간 모의 모드로 운영하며 대시보드에서 결정 로그·손익(PnL)·실패율을 매일 점검한다.
9. 결과가 납득할 만하면 소액 실거래 지갑을 Hyperliquid에 연결하고, 엔진 모드를 market-wide로 **live** 전환(처음엔 최소 레버리지·최소 노셔널로).
10. launchd(맥) 또는 Docker `restart: always`로 엔진/컨테이너가 재부팅 후에도 자동 기동되도록 등록한다.

## 예상 공수
- 초기 셋업(클론~로컬 구동 확인): 4~8시간, 난이도 **중~상** (Rust/Docker/DB 스택 동시 이해 필요)
- 모의 모드 검증 기간: 1~2주 (매일 점검 10~20분)
- 실거래 전환 및 안정화: 추가 4~6시간 작업 + 최소 2주 관찰
- 전체 체감 난이도: **중상급** (개발 경험 있는 개인 기준, 인프라 조합 경험이 관건)

## 리스크/유의점
- **자금 손실 리스크**: live 모드 전환 시 AI 판단 오류나 API 장애가 직접적인 손실로 이어짐 — 반드시 소액·저레버리지로 시작.
- **Jev 모델 신뢰성 검증 부족**: 컷오프 이후 출시된 신모델이라 실제 트레이딩 판단 품질에 대한 외부 검증 데이터가 부족함.
- **API 비용 누적**: 종목 수 × 판단 주기가 늘어나면 Jev/OpenRouter 호출 비용이 예상보다 빠르게 증가할 수 있음.
- **인프라 유지보수 부담**: MongoDB/TimescaleDB/Docker를 개인 맥북에서 24시간 돌리면 전력·발열·디스크 사용량 관리가 필요.
- **거래소 API 정책 변경**: Hyperliquid 측 API 스펙이 바뀌면 ExecutionAdapter 코드 수정이 필요할 수 있음.
- **보안**: 실지갑 프라이빗키/API 키가 `.env`에 평문 저장되므로 파일 권한·백업 관리에 각별히 주의.
