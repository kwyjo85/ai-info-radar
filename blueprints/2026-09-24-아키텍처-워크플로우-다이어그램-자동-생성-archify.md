# 아키텍처·워크플로우 다이어그램 자동 생성: Archify

## 쉽게 말하면
말로 설명하면 그림으로 그려주는 화이트보드 조수라고 생각하면 됩니다. "인스타 데이터 가져와서 암호화하고 깃허브에 올리는 과정을 그려줘"라고 Claude Code에 말하면, 화살표와 박스가 움직이는 예쁜 웹페이지 한 장이 뚝딱 나옵니다. 발표 자료 만들 때마다 파워포인트로 도형 그리던 시간을 없애주는 도구입니다.

## 이걸로 할 수 있는 것
1. "AI 정보 레이더" 파이프라인(수집→채점→암호화→배포)을 한 장의 흐름도로 만들어 README나 노션 문서에 붙여넣기
2. 클라이언트에게 "AI 비서 자동화" 제안서를 보낼 때, 텍스트 설명 대신 인터랙티브 워크플로우 다이어그램을 첨부해 이해도와 신뢰도 높이기
3. Jev나 Claude Code로 만든 복잡한 다단계 자동화(예: 크론+스크립트+API 연동)를 팀원에게 설명할 때 시퀀스 다이어그램으로 즉시 시각화

## 개요
Archify는 Claude Code 등 에이전트에게 자연어로 설명만 하면 아키텍처/워크플로우/시퀀스/데이터흐름 다이어그램을 움직임 효과가 있는 자체완결형 HTML로 만들어주는 "에이전트 스킬"입니다. 별도 설치 명령만으로 Claude Code에 추가되며, 이후 텍스트 지시만으로 도식이 나옵니다. 핵심 가치는 "설명 문서를 시각 자료로 변환하는 시간"을 거의 0으로 줄여준다는 점이며, 특히 AI 자동화 컨설팅/제안 업무에서 결과물의 완성도를 눈에 띄게 높여줍니다.

## 구현 가능성: 상
- Claude Code 스킬 설치 방식이라 별도 인프라나 서버 구축이 필요 없음
- 이미 Claude/Cursor에서 검증된 스킬이며 GitHub 스타 6.9만 개(이달 +5.4만)로 사용자층이 크고 안정성이 검증됨
- 사용자의 현재 작업 환경(MacBook + Claude Code)에 그대로 맞아떨어짐

## 필요 도구
- Claude Code (이미 사용 중, 무료/구독형)
- Archify 스킬 (GitHub 공개 저장소, 무료 — tt-a1i/archify)
- Git (스킬 클론/설치용, 무료, macOS 기본 내장)
- (선택) GitHub Pages 또는 기존 gh-pages 배포 환경 — 생성된 HTML 다이어그램을 웹에 게시할 때, 이미 보유 중이므로 추가 비용 없음

## 구현 단계
1. 터미널에서 `git clone https://github.com/tt-a1i/archify.git` 로 저장소를 받거나, 저장소의 스킬 설치 안내(README)에 따라 Claude Code의 skills 디렉토리에 등록
2. Claude Code 재시작 후 `/skills` 또는 스킬 목록에서 archify가 인식되는지 확인
3. 현재 ai-info-radar 프로젝트에서 "인스타 수집 → 분석 → 채점 → 암호화 → GitHub Pages 배포" 파이프라인을 설명하는 프롬프트를 작성해 archify에게 워크플로우 다이어그램 생성 요청
4. 생성된 HTML 파일을 `docs/` 또는 `diagrams/` 폴더에 저장하고 README에 링크 또는 iframe으로 삽입
5. 실용 판정된 다른 아이디어(예: AI 비서 조합, 다단계 자동화) 중 단계 수가 많은 것을 골라 동일한 방식으로 워크플로우 도식화 → 향후 클라이언트 제안서용 템플릿으로 재사용
6. 결과물을 실제 제안/발표 자료에 1회 이상 사용해보고, 반응이 좋으면 표준 산출물 포맷으로 채택

## 예상 공수
설치 및 첫 다이어그램 생성까지 약 30분~1시간, 난이도는 하(단순 설치+프롬프트 작성 수준). 이후 다이어그램 1건당 추가 생성 시간은 5~10분 내외로 매우 짧음.

## 리스크/유의점
- 스킬이 자주 업데이트되는 초기 단계 프로젝트라 버전 변경 시 프롬프트 문법이나 출력 형식이 바뀔 수 있음 — 사용 전 README 최신 버전 확인 필요
- "효과는 시각화가 필요할 때만" 발휘되므로, 텍스트 설명만으로 충분한 간단한 작업에는 굳이 쓸 필요 없음(과사용 주의)
- 생성된 HTML을 외부(클라이언트, GitHub Pages)에 공개할 경우, 다이어그램에 민감한 내부 로직이나 API 키·경로 등이 노출되지 않도록 프롬프트 작성 시 마스킹 필요
