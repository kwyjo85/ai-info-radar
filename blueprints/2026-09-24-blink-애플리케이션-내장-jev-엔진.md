# Blink: 애플리케이션 내장 Jev 엔진

## 쉽게 말하면
Blink는 무거운 AI 서버 없이도 앱 안에 작은 SQLite 데이터베이스 파일 하나만으로 AI 엔진(Jev)을 통째로 넣어버리는 도구입니다. 마치 스마트폰에 앱을 설치하면 인터넷 없이도 계산기가 바로 작동하듯, Blink를 쓰면 인터넷 연결이나 클라우드 API 호출 없이 내 컴퓨터/앱 안에서 AI가 바로 돌아갑니다. API 키 걱정, 요청당 과금, 네트워크 지연 없이 "내 파일 안에 든 AI"를 쓰는 셈입니다.

## 이걸로 할 수 있는 것
1. 노트북 오프라인 상태에서도 로컬 문서(계약서, 회의록, 코드)를 Jev 엔진으로 즉시 요약·분류하는 개인용 도구를 만든다.
2. 고객에게 납품하는 데스크톱/모바일 앱에 AI 기능을 내장해, "이 앱은 서버 비용 없이 AI가 작동합니다"를 셀링 포인트로 판매한다.
3. 반복적으로 들어오는 인보이스·영수증 PDF를 Claude Code로 자동 파싱하는 파이프라인에서, 민감한 재무 데이터를 외부로 절대 보내지 않는 "완전 로컬" 버전을 만들어 규제 산업(의료·금융) 고객에게 제안한다.

## 개요
Blink는 SQLite 확장 형태로 AI 추론 엔진(Jev)을 데이터베이스 파일 안에 임베드해, 별도 서버·API 호출 없이 애플리케이션 내부에서 직접 AI 추론(요약, 분류, 임베딩 검색 등)을 실행하게 해주는 오픈소스 프로젝트입니다. 핵심 가치는 (1) 오프라인/에지 환경에서의 AI 실행, (2) 토큰당 과금이 없는 원가 절감, (3) 데이터가 외부로 나가지 않는 프라이버시입니다. 이는 "AI 자동화로 수익 창출"이라는 관점에서, 서버 운영비 없이 판매 가능한 AI 내장 제품을 만들 수 있다는 뜻입니다.

## 구현 가능성: 중
- SQLite 확장(로딩 가능한 .so/.dylib) 형태이므로 macOS(개인 MacBook)에서 빌드·설치가 기술적으로는 가능함.
- 다만 (a) 저장소가 이제 막 공개된 신규 프로젝트라 문서·안정성이 검증 중이고, (b) "Jev 엔진"이 구체적으로 어떤 모델 가중치를 내장하는지, macOS(특히 Apple Silicon) 바이너리 지원 여부를 직접 확인해야 함.
- 근거: sqliteai 조직은 기존에도 SQLite용 벡터 검색·AI 확장을 배포한 이력이 있어 macOS 지원 가능성이 높지만, "상"으로 매기기엔 실사용 검증(설치·추론 속도·정확도 테스트)이 먼저 필요.

## 필요 도구
- SQLite3 (macOS 기본 내장, 무료)
- Blink 확장 바이너리 또는 소스 빌드용 Xcode Command Line Tools (무료)
- Homebrew (무료, 빌드 의존성 관리용)
- Claude Code (기존 사용 중, 자동화 스크립트·통합 코드 작성에 활용, 유료 구독)
- (선택) Python `sqlite3` 모듈 또는 Node.js `better-sqlite3` — 확장 로딩 후 앱에서 호출할 언어 바인딩 (무료)
- 테스트용 실제 업무 데이터 샘플 (계약서/인보이스 등, 사용자 보유)

## 구현 단계
1. `git clone https://github.com/sqliteai/blink` 로 저장소를 받고 README에서 macOS(darwin/arm64) 지원 여부와 요구 SQLite 버전을 확인한다.
2. Claude Code에게 빌드 스크립트 검토·실행을 맡겨 로컬 macOS 환경에서 확장 파일(.dylib)을 컴파일하거나, 배포된 사전 빌드 바이너리를 다운로드한다.
3. `sqlite3` CLI에서 `.load ./blink.dylib` 로 확장을 로드하고, README에 나온 샘플 쿼리(예: 텍스트 요약 함수 호출)로 최소 동작을 검증한다.
4. 실제 업무 시나리오 하나(예: 인보이스 PDF 텍스트 → 자동 분류)를 골라, Claude Code로 SQLite에 데이터를 넣고 Blink의 Jev 함수를 호출하는 스크립트(Python 또는 Node)를 작성한다.
5. 추론 속도·정확도를 기존에 쓰던 클라우드 API(예: Claude API 호출) 결과와 비교해 품질 격차를 측정한다.
6. 격차가 허용 범위면, 이 파이프라인을 오프라인 데모 또는 "프라이버시 우선 AI 도구"로 패키징해 잠재 고객(예: 개인정보 민감 업종)에게 제안서를 작성한다.
7. 판매 가능성이 보이면 최소 기능 데스크톱 앱(Electron/Tauri) 형태로 감싸 배포 실험을 진행한다.

## 예상 공수
- 빌드 및 최소 동작 검증: 2~3시간 (난이도: 중, 신규 프로젝트라 문서 공백을 직접 메워야 함)
- 실제 업무 파이프라인 프로토타입 1개: 4~6시간 (난이도: 중)
- 품질 비교 및 제안서 작성: 2~3시간 (난이도: 하)
- 총합: 약 1~2일 집중 작업

## 리스크/유의점
- 신생 프로젝트라 API가 급격히 바뀌거나 유지보수가 중단될 위험이 있음 — 프로덕션 판매 전 반드시 라이선스와 지속 관리 여부 확인.
- "Jev 엔진"의 실제 성능(정확도·속도)이 클라우드 LLM 대비 크게 떨어질 수 있어, 고객에게 성능 기대치를 과장하지 말 것.
- macOS 네이티브 확장 로딩은 보안 설정(Gatekeeper, 코드 서명)에 막힐 수 있어 배포 시 서명·공증 절차가 추가로 필요할 수 있음.
- 민감 데이터를 다루는 만큼, "완전 로컬" 주장을 하려면 실제로 네트워크 호출이 전혀 없는지 코드 레벨에서 검증 필요.
