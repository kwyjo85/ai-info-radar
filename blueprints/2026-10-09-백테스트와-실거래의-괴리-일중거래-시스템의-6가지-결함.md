# 백테스트-실거래 괴리 점검: 개인 일중거래 시스템의 6가지 결함 체크리스트 구현

## 쉽게 말하면
백테스트는 "연습 시합"이고 실거래는 "진짜 시합"인데, 연습 때 쓰는 공과 실제 시합 공이 미묘하게 다르면 연습 성적은 좋아도 실전에서 무너집니다. 이 논문은 한 일중거래 시스템에서 연습(백테스트)과 실전(실거래)이 서로 다른 데이터·코드·설정을 쓰고 있었는데도 요약 성적표만 봐서는 전혀 티가 안 났다는 사례를 보고합니다. 개인 투자자가 AI로 트레이딩 시스템을 짤 때도, 수익률 숫자만 믿지 말고 "두 길이 실제로 같은 곳을 가는지" 검증하는 습관이 필요하다는 이야기입니다.

## 이걸로 할 수 있는 것
1. AI(예: Claude)로 짠 나만의 일중 트레이딩 백테스트 코드가 실거래와 실제로 같은 데이터·로직을 쓰는지 자동으로 비교 검증한다.
2. 배당락일 가격 조정, 타임존 오류, 체결량 왜곡 등 개인이 놓치기 쉬운 데이터 함정을 체크리스트로 만들어 매번 점검한다.
3. 시스템을 실전에 투입하기 전, AI 에이전트에게 코드와 설정 파일을 스캔시켜 "백테스트와 실거래 경로가 어디서 갈라지는지" 보고서를 뽑게 한다.

## 개요
이 논문의 핵심은 "6가지 결함(데이터 3개, 코드 2개, 설정 1개)"과 "10개 체크리스트"를 개인 트레이딩 파이프라인의 품질관리(QA) 규칙으로 흡수하는 것입니다. AI를 활용해 이 체크리스트를 자동 점검 스크립트/프롬프트로 만들면, 전문 퀀트 팀이 아닌 1인 개발자도 "성적은 좋은데 왜 실전은 다르지?"라는 흔한 함정을 줄일 수 있습니다. 즉 자동화 대상은 트레이딩 전략 자체가 아니라 "전략 검증 파이프라인의 신뢰성"입니다.

## 구현 가능성 — 중
전체 논문 원문(8페이지, PDF/SSRN)은 본 정보에 포함되어 있지 않고 초록(abstract)만 확인되었습니다. 초록에 언급된 6가지 결함의 '범주'(데이터 피드 문제, 배당조정 가격, 라이브 전용 다운로드 데이터, 포지션 사이징 한도 초과, UTC/뉴욕시간 혼동, 설정값 미반영)는 구체적 수치·구현 방법 없이도 체크리스트 항목으로 바로 옮겨 적을 수 있어 "원칙 적용"은 상입니다. 다만 10개 체크리스트 전문, 각 결함의 정확한 오차 크기와 재현 코드는 원문 PDF를 확보해야 하므로[공식 문서 확인 필요], 완전한 구현까지는 중간 난이도로 평가합니다.

## 필요 도구
- **원문 PDF**: SSRN 링크(https://doi.org/10.2139/ssrn.7517378) 또는 Zenodo 아카이브 — 무료, 로그인 필요할 수 있음
- **Python** (pandas, numpy) — 무료, 백테스트/실거래 로그 비교 스크립트 작성용
- **증권사 API** (예: Interactive Brokers API, 키움 Open API, 국내 증권사별 API) — 보통 무료, 실거래 데이터 접근용
- **시세 데이터 제공처** (예: Yahoo Finance, Alpha Vantage, Polygon.io) — 무료/유료 티어 혼재, 배당조정 여부 확인 필요
- **Claude Code 또는 AI 코딩 에이전트** — 코드/설정 파일을 읽고 백테스트-실거래 경로 불일치를 자동 탐지하는 데 활용, 유료(API 사용량 기준)
- **pytest 등 테스트 프레임워크** — 무료, 회귀 테스트(regression test) 자동화용
- **로깅/비교 도구** (예: diff, pandas.compare, 또는 자체 스크립트) — 무료

## 구현 단계
1. SSRN 또는 Zenodo에서 원문 PDF 전체를 다운로드해 10개 체크리스트 전문과 6가지 결함의 세부 재현 조건을 확인한다 [공식 문서 확인 필요].
2. 확보한 체크리스트를 바탕으로 데이터 범주(① 시세 피드 거래량 비율, ② 배당조정 가격 사용 여부, ③ 실거래 전용 다운로드 데이터) 3개 항목을 본인의 백테스트/실거래 데이터 파이프라인에 대입해 점검 스크립트를 작성한다.
3. 코드 범주(④ 포지션 사이징 한도, ⑤ 타임존 처리) 2개 항목을 유닛테스트로 만든다 — 예: 모든 타임스탬프가 UTC로 기록되는지, 증권사 계좌 한도를 코드 내 사이징 로직이 초과하지 않는지 pytest로 검증.
4. 설정 범주(⑥ 설정값이 실제 주문 로직까지 도달하는지) 점검을 위해, 설정 파일(config.yaml 등)의 각 플래그가 실제로 주문 함수 호출 경로까지 연결되는지 코드 추적(trace)을 AI 에이전트에게 맡겨 "미사용 설정 변수" 리포트를 자동 생성한다.
5. 백테스트 실행 로그와 실거래(또는 페이퍼 트레이딩) 실행 로그를 날짜별로 나란히 비교하는 스크립트를 만들어, 체결가·체결시각·주문수량 차이를 정량화한다.
6. 위 5단계를 CI(예: GitHub Actions 로컬 대체로 cron + 쉘스크립트)에 넣어, 전략 코드 수정 시마다 자동으로 괴리 리포트를 생성하도록 한다.
7. 소액 또는 페이퍼 트레이딩으로 2~4주 병행 운영하며 괴리 리포트가 "0건"에 수렴하는지 확인한 뒤에만 실거래 자금 규모를 키운다.

## 예상 공수
- 원문 PDF 숙독 및 체크리스트 정리: 2~3시간, 난이도 하
- 데이터 3개 항목 점검 스크립트 작성: 4~6시간, 난이도 중
- 코드 2개 항목 유닛테스트 작성: 3~5시간, 난이도 중
- 설정 추적 자동화(AI 에이전트 활용): 2~4시간, 난이도 중
- 백테스트-실거래 로그 비교 도구 + CI 연동: 6~10시간, 난이도 중상
- 총합: 약 17~28시간 (1인 개발, 주말 2~3회 분량), 전체 난이도 **중**

## 리스크/유의점
- 본 정보에는 논문 초록만 포함되어 있고 10개 체크리스트 전문, 정확한 오차 수치(%), 재현 코드는 확인되지 않았습니다. 실제 구현 전 반드시 원문 PDF를 직접 확인해야 합니다 [공식 문서 확인 필요].
- 저자들은 "이 시스템이 수익성이 있는지에 대해서는 어떤 주장도 하지 않는다"고 명시했습니다. 이 체크리스트는 전략의 수익성을 보장하지 않으며, 순수하게 백테스트-실거래 간 '구현 정합성' 검증 도구입니다.
- 증권사 API별 체결 한도, 타임존 처리 방식, 배당조정 데이터 제공 여부는 공급처마다 다르므로, 본인이 사용하는 API/데이터 제공처의 공식 문서를 별도로 확인해야 합니다 [공식 문서 확인 필요].
- AI 에이전트에게 코드 추적을 맡길 경우, 실제 주문 실행 환경(증권사 계좌, API 키)에는 접근 권한을 주지 말고 읽기 전용 코드 분석에만 활용해야 금전적 리스크를 피할 수 있습니다.
