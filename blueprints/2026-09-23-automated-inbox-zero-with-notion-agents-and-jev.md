# Jev 기반 인박스 제로 자동화 — Notion 연동 수익화 블루프린트

## 개요
Gmail/이메일을 LLM 대신 Jev(TypeSafe AI System One)로 분류해 타입(긴급/스팸/뉴스레터/할일 등)과 확신도를 즉시 받아 Notion DB에 자동 정리하고, 확신도 기반으로 자동 아카이브·알림·답장 초안 생성까지 연결하는 개인용 인박스 제로 파이프라인이다. LLM 분류 대비 100배 빠르고 저렴하다는 Jev의 특성상 대량 이메일을 실시간·상시 처리해도 비용 부담이 거의 없어, 프리랜서·컨설턴트·1인 창업자 대상 "이메일 자동 트리아지 서비스"로 제품화할 수 있다는 점이 핵심 가치다.

## 구현 가능성 — 중
- 개인 MacBook에서 Gmail API, Notion API, 자동화 스크립트 조합은 기존에 검증된 패턴이라 구현 자체 난이도는 낮음.
- 다만 Jev는 2026년 9월 출시된 신생 모델로 SDK/문서 성숙도, 요금제, rate limit, 온디바이스 지원 여부 등이 불확실해 실제 연동 단계에서 변수가 클 수 있음.
- 분류 스키마(타입 정의) 설계와 확신도 임계값 튜닝에 반복 실험이 필요해 "완성도 높은 자동화"까지는 중간 난이도로 평가.

## 필요 도구
- **Jev API (TypeSafe AI System One)** — 이메일 분류/타입 추출 핵심 엔진 (유료, 사용량 기반 과금 예상)
- **Gmail API (OAuth 2.0)** — 이메일 읽기/라벨링/답장 초안 저장 (무료, 쿼터 제한)
- **Notion API** — 분류 결과 저장용 DB, 대시보드 역할 (무료 티어로 충분)
- **n8n(셀프호스팅, 무료) 또는 Make.com(유료 플랜)** — 이메일 폴링 → Jev 호출 → Notion 기록 워크플로 오케스트레이션
- **Python 3.11+ (requests, google-api-python-client, notion-client 라이브러리)** — 커스텀 스크립트 작성 시 (무료)
- **macOS launchd** — 주기적 실행 스케줄러 (무료, OS 내장)
- **(선택) Claude/GPT API** — 확신도 낮은 케이스나 답장 초안 생성용 보조 LLM (유료, 사용량 기반)

## 구현 단계
1. Jev 개발자 계정 가입 후 API 키 발급, curl/Python으로 간단한 텍스트 분류 요청을 보내 응답 형식(타입 값 + 확신도 스코어)을 확인한다.
2. Google Cloud Console에서 Gmail API용 OAuth 클라이언트를 생성하고, 로컬에서 최근 50~100통의 이메일 제목+본문 일부를 읽어오는 스크립트를 작성한다.
3. 이메일 분류 스키마를 정의한다 (예: `URGENT`, `NEEDS_REPLY`, `NEWSLETTER`, `RECEIPT`, `SPAM_LIKE`). 각 타입에 대해 Jev에 few-shot 예시 또는 프롬프트 템플릿을 구성해 분류 정확도를 테스트한다.
4. Notion에 "인박스 트리아지" DB를 만들고 속성(발신자, 제목, 분류 타입, 확신도, 처리 상태, 링크)을 설계한 뒤, Notion API로 이메일별 레코드를 생성하는 함수를 작성한다.
5. 확신도 임계값(예: 0.85 이상)을 기준으로 분기 로직을 만든다 — 임계값 이상이면 자동 Gmail 라벨링·아카이브, 미만이면 Notion에 "검토 필요"로 남겨 사람이 확인하도록 한다.
6. `NEEDS_REPLY`로 분류된 메일 중 확신도 높은 것만 골라 보조 LLM(Claude 등)에 넘겨 답장 초안을 생성하고 Gmail 임시보관함에 저장한다.
7. 전체 파이프라인을 하나의 스크립트(또는 n8n 워크플로)로 묶고, macOS launchd plist를 등록해 15분~1시간 간격으로 자동 실행되게 한다.
8. 1~2주간 실사용하며 오분류 사례를 Notion에서 수집, Jev 프롬프트/스키마를 보정하는 피드백 루프를 만든다.
9. (수익화 단계) 검증된 파이프라인을 Notion 템플릿 + 설정 스크립트로 패키징해 Gumroad/Lemon Squeezy에서 판매하거나, 소규모 컨설턴트 대상 유료 셋업 서비스로 전환한다.

## 예상 공수
- 프로토타입(1~6단계): 15~20시간
- 안정화 및 튜닝(7~8단계): 8~12시간
- 제품화(9단계, 선택): 추가 15~20시간
- 난이도: 중 (API 연동 자체는 쉬우나 Jev 분류 스키마 튜닝과 신생 API 문서 부족이 변수)

## 리스크/유의점
- Jev가 갓 출시된 모델이라 API 스펙 변경, 요금 정책 변동, SLA 미비 가능성이 있어 프로덕션 의존도를 낮게 유지해야 함.
- 오분류로 중요 메일이 자동 아카이브될 위험 — 초기에는 임계값을 보수적으로 잡고 "완전 자동 삭제" 대신 "라벨링만" 하는 안전장치 필요.
- 이메일 본문을 외부 API(Jev, 보조 LLM)로 전송하므로 개인정보/기밀 정보 노출 리스크 존재, 민감 발신자 도메인은 화이트리스트로 제외하는 로직 권장.
- Gmail API 및 Notion API 모두 쿼터 제한이 있어 대량 처리 시 배치/캐싱 전략 필요.
- 제품화 시 사용자별 Jev/LLM 사용량 비용을 어떻게 가격에 반영할지 사전 설계 필요 (구독료 대비 API 원가 마진 계산).
