# Jev 1.13 '능력 지도(Jaggedness Map)' 기반 자동 폴백 라우터로 AI 자동화 신뢰성 판매하기

## 쉽게 말하면
Jev는 사람처럼 말을 만들어내는 AI가 아니라 "정답 후보 + 확신도 숫자"만 순식간에 뱉어주는 판단 기계인데, 어떤 문제에서는 귀신같이 잘 맞히고 어떤 문제에서는 엉뚱하게 틀립니다. 이 가이드는 그 "잘하는 영역/못하는 영역 지도"를 정리한 문서인데, 이를 이용하면 "Jev가 자신 있어 하는 판단은 Jev에게 맡기고, 헷갈려 하는 판단만 골라 Claude 같은 정식 AI에게 다시 물어보는" 자동 분류기를 만들 수 있습니다. 비유하자면 신입 직원(Jev)에게 쉬운 일은 바로 맡기고, 애매한 건만 팀장(Claude)이 검토하게 하는 워크플로우를 자동으로 설계해주는 것입니다.

## 이걸로 할 수 있는 것
1. 고객사의 이메일/티켓 분류 시스템에서 Jev 확신도가 낮은 케이스만 자동으로 Claude Code 파이프라인으로 넘겨 재검증하는 "하이브리드 분류기"를 구축·판매한다.
2. 기존에 만든 jev-router(작업을 Jev로 판단해 가장 싼 모델로 라우팅)에 "이 작업 유형은 Jev가 취약하니 애초에 라우팅하지 마라"는 룰을 추가해 오판율을 낮춘 버전으로 업그레이드해 판매한다.
3. Jev를 도입하려는 다른 개발자/팀에게 "Jev 신뢰도 지도" 리포트(어떤 태스크군에서 정확도가 얼마나 나오는지 실측 벤치마크)를 유료 컨설팅 산출물로 제공한다.

## 개요
Jev 1.13의 공식 능력/한계 문서를 근거로, 어떤 입력 유형에서 Jev의 확신도-정확도가 실제로 일치하는지(=신뢰 가능 영역)와 어긋나는지(=위험 영역)를 실측 벤치마크로 정리하고, 이를 Claude Code 자동화 파이프라인의 "자동 폴백 임계값" 설정에 반영한다. 가치는 두 가지다 — (1) 본인의 Jev 기반 자동화 제품(jev-router 등)의 오판률을 낮춰 신뢰성을 높이고, (2) 이 지도 자체를 다른 Jev 도입 팀에게 판매 가능한 리서치/컨설팅 상품으로 만든다.

## 구현 가능성 — 중
- 근거(가능): Jev API 호출과 결과 로깅, 정답 비교를 통한 정확도 측정은 표준적인 데이터 파이프라인 작업으로 Claude Code로 스크립트화하기 쉽고, 이미 사용자가 jev-router 등 관련 인프라를 보유하고 있어 재사용 가능하다.
- 근거(제약): 원문 문서(docs.typesafe.ai/model-jaggedness/jev-1.13) 접근이 이 세션에서 직접 확인되지 않았고(HN 포인트 3, 댓글 0 — 검증 트래픽 낮음), Jev 1.13의 실제 능력/한계 항목을 1차 문서로 먼저 확인해야 벤치마크 설계가 정확해진다. 또한 "무엇이 정답인가"를 판정할 골드 데이터셋을 직접 구축해야 하는 부분이 시간이 든다.

## 필요 도구
- TypeSafe AI Jev API 키 — 유료, 종량제 (기존 보유 시 재사용)
- Claude Code — 벤치마크 스크립트/자동화 파이프라인 작성, 무료(구독 포함)
- Claude API (Sonnet 5) — 폴백 판단 및 정답 비교용, 유료 종량제
- Python + pandas — 무료, 벤치마크 결과 집계/분석
- Jupyter 또는 스크립트 기반 실험 노트북 — 무료, 태스크 유형별 정확도 실험
- Weights & Biases 또는 단순 CSV/SQLite — 무료(개인 티어), 실험 로그 관리
- Notion 또는 정적 사이트(GitHub Pages) — 무료, "Jev 신뢰도 지도" 리포트 배포용
- Stripe 또는 Gumroad — 컨설팅 리포트/도구 판매 시 결제 연동, 거래 수수료만 발생

## 구현 단계
1. `docs.typesafe.ai/model-jaggedness/jev-1.13` 원문을 WebFetch로 직접 확인해 문서가 제시하는 "강점 카테고리"와 "약점 카테고리"(예: 짧은 분류는 강하지만 다단계 추론이 섞인 판단은 약함 등) 목록을 추출한다.
2. 기존 jev-router가 다루는 실제 작업 로그(Claude Code 세션에서 라우팅된 케이스들)를 문서의 카테고리 기준으로 태깅해, "우리 실사용 케이스 중 몇 %가 Jev 약점 영역에 속하는지" 분포를 낸다.
3. 약점 영역으로 태깅된 케이스 50~100건을 골라 Jev 응답과 Claude(정답 기준)의 응답을 나란히 비교하는 벤치마크 스크립트를 Claude Code로 작성하고 정확도/확신도 상관관계를 계산한다.
4. 결과를 바탕으로 "확신도 임계값 + 카테고리 필터" 규칙을 jev-router 설정에 추가한다 — 예: 특정 카테고리에서는 확신도와 무관하게 항상 Claude로 폴백.
5. 개선 전/후 오판률·비용·지연시간을 비교한 A/B 결과표를 만들어 jev-router README/랜딩페이지에 "신뢰도 개선판" 업데이트로 반영한다.
6. 벤치마크 방법론과 결과를 정리한 "Jev 1.13 신뢰도 지도" 리포트(Notion/정적 페이지)를 만들어, Show HN에 공개하거나 Jev 도입을 검토 중인 팀 대상 유료 컨설팅/리포트 상품으로 제안한다.

## 예상 공수
- 원문 분석 + 카테고리 추출: 2~3시간
- 실사용 로그 태깅 + 분포 분석: 4~6시간
- 벤치마크 스크립트 작성 + 실행: 8~10시간
- 라우터 규칙 반영 + A/B 비교: 4~6시간
- 리포트 작성 + 배포: 4~6시간
- 총 22~31시간 (주말 포함 약 1주), 난이도: 중

## 리스크/유의점
- 원문 문서를 아직 직접 확인하지 못한 상태(HN 포인트 3, 댓글 0으로 외부 검증도 부족)이므로, 1단계에서 실제 내용이 예상과 다를 경우 벤치마크 설계를 다시 잡아야 한다.
- 골드 정답 판정을 사람이 직접 하거나 Claude를 "정답 기준"으로 쓰는 경우 순환 논리(Claude가 틀린 것도 정답으로 오인)가 생길 수 있어, 일부 케이스는 수작업 검수가 필요하다.
- Jev 자체가 빠르게 버전업(1.13 이후)될 경우 능력/한계 지도가 금방 낡을 수 있으므로, 리포트에 "측정 버전과 날짜"를 명시하고 정기 재측정 계획을 포함해야 한다.
- 컨설팅/리포트로 판매 시 벤치마크에 사용한 고객사 실데이터가 포함되지 않도록 익명화하거나 공개용 샘플 데이터로 재구성해야 한다.
