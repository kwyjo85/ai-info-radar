# commit-rewriter 0.1 도입 블루프린트

## 개요
commit-rewriter는 로컬 git 저장소의 커밋 메시지를 웹 UI에서 검토·수정하고, 첫 수정 커밋부터 최신 커밋까지 일괄 rewrite해주는 Python 도구다. 코딩 에이전트가 생성한 지저분한 커밋 메시지나 사내 이슈 번호 같은 민감 정보를 공개 저장소 배포 전에 정리하는 데 유용하며, 자동으로 타임스탬프 백업 브랜치를 만들어 되돌릴 수 있다.

## 구현 가능성 — 상
`uvx commit-rewriter path/to/repo` 한 줄로 실행되는 완성된 배포 패키지이며, macOS에서 uv/uvx만 있으면 별도 빌드나 설정 없이 즉시 동작한다. 로컬 웹 서버 + 브라우저 UI 방식이라 인증/클라우드 연동이 불필요해 개인 환경 도입 장벽이 매우 낮다.

## 필요 도구
- **uv / uvx** — Python 패키지 실행기 (무료, https://docs.astral.sh/uv/ 에서 설치)
- **commit-rewriter** — `uvx`로 실행 시 자동 설치되는 PyPI 패키지 (무료, OSS)
- **git** (macOS 기본 내장 또는 Homebrew로 최신 버전 설치, 무료)
- 웹 브라우저 (Safari/Chrome 등, 기본 제공)
- (선택) **Homebrew** — uv 설치용 (무료)

## 구현 단계
1. `brew install uv` 로 uv를 설치한다 (이미 설치되어 있으면 생략).
2. 정리 대상 저장소를 미리 `git status`로 확인해 커밋되지 않은 변경사항이 없는지 확인한다.
3. 안전을 위해 원격에 푸시하기 전 로컬 브랜치를 하나 더 백업한다: `git branch backup-before-rewrite`.
4. 저장소 디렉토리로 이동 후 `uvx commit-rewriter .` 를 실행한다 (경로 인자 없이 실행하면 현재 디렉토리 대상).
5. 자동으로 열리는 로컬 웹 UI(브라우저)에서 좌측 사이드바로 커밋 목록을 탐색하고, 검색창으로 메시지/작성자/해시 검색, "Edited only" 체크박스로 수정한 커밋만 필터링한다.
6. 각 커밋 카드의 텍스트 영역에서 메시지를 직접 수정한다 (이슈 ID 제거, 에이전트가 남긴 잡음 정리 등). "View full formatted diff" 토글로 실제 변경 내용을 대조하며 편집한다.
7. 상단 툴바에서 대기 중인 수정 건수를 확인하고, 잘못 수정했으면 "Discard drafts"로 초기화 가능.
8. 편집이 끝나면 "Rewrite commit messages" 버튼을 클릭 — 도구가 자동으로 타임스탬프 백업 브랜치를 생성한 뒤 첫 수정 커밋부터 HEAD까지 rewrite를 수행한다.
9. `git log --oneline` 으로 변경된 메시지를 확인하고, `git diff <backup-branch> <원래브랜치>` 로 커밋 내용 자체는 변하지 않았는지 검증한다.
10. 원격 저장소에 이미 푸시된 브랜치라면 `git push --force-with-lease`가 필요함을 인지하고, 공유 브랜치인 경우 팀원에게 먼저 공지한다.

## 예상 공수
- 초기 설치 및 첫 실행: 10~15분
- 저장소당 실제 커밋 메시지 편집/검토: 저장소 크기에 따라 15분~1시간 (예: Datasette 보안 릴리스 규모 기준)
- 난이도: **하** — CLI 한 줄 실행 + 브라우저 UI 조작 수준, 별도 코딩 불필요

## 리스크/유의점
- **히스토리 재작성(rewrite)이므로 이미 공유/푸시된 브랜치에는 신중히 적용**해야 하며, force-push 시 협업자의 로컬 히스토리와 충돌 가능 — 개인 프로젝트나 공개 전 정리 단계에서 사용하는 것이 안전.
- 백업 브랜치는 자동 생성되지만 **로컬에만 존재**하므로, 문제가 생기면 원격 push 전에 반드시 검증할 것.
- 민감 정보(사내 이슈 ID, 토큰 등) 제거 목적이라면, 메시지뿐 아니라 **커밋 diff(코드 내용) 자체에 민감 정보가 없는지도 별도 확인** 필요 (이 도구는 메시지만 다룬다).
- PyPI 신규/저신뢰 패키지이므로 `uvx` 실행 전 GitHub 저장소(simonw/commit-rewriter)의 코드를 한 번 훑어보는 것을 권장.
