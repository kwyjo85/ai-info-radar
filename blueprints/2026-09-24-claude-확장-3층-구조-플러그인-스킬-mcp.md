# Claude 확장 3층 구조: 플러그인·스킬·MCP

## 쉽게 말하면
Claude를 그냥 쓰는 건 빈 사무실에 혼자 앉아 일하는 것과 같습니다. 여기에 플러그인은 "필요할 때 부르는 팀원", 스킬은 "자주 쓰는 서류 양식", MCP는 "옆 부서(노션·슬랙 등) 문으로 직접 들어가는 통로"라고 보면 됩니다. 이 셋을 잘 조합하면 Claude Code가 나만의 업무용 비서 사무실이 됩니다.

## 이걸로 할 수 있는 것
1. 노션에 정리해둔 회의록을 열지 않고도 Claude가 직접 읽어 할 일 목록을 뽑아 노션 DB에 자동으로 채워 넣게 한다.
2. 반복적으로 쓰는 "블로그 글 다듬기", "인스타 대시보드 요약" 같은 작업을 스킬로 등록해 명령어 한 줄로 실행한다.
3. Jev나 Claude Code로 진행하는 외주·컨설팅 작업에서 깃허브 이슈·PR 관리를 MCP로 연결해 클라이언트 보고 시간을 줄인다.

## 개요
Claude Code의 확장 기능을 3층(플러그인/스킬/MCP)으로 구조화해 이해하면, 무작정 여러 도구를 설치하는 대신 "내 작업에 실제로 필요한 것만" 골라 쓸 수 있습니다. 이는 곧 반복 업무 자동화 시간을 줄여 수익화 가능한 작업(콘텐츠 제작, 클라이언트 프로젝트, 데이터 정리 등)에 더 많은 시간을 쓸 수 있게 해주는 가치가 있습니다. 원 게시물의 "24개 필수 설치"는 과장이며, 실제로는 3~5개를 목적에 맞게 선별하는 것이 핵심 전략입니다.

## 구현 가능성 — 상
근거: Claude Code에 `/plugin`(마켓플레이스), 스킬(`.claude/skills`), MCP(공식 서버 다수 공개)가 이미 내장 기능으로 존재하며, 이 저장소(ai-info-radar)에도 이미 스킬/워크플로우 구조가 활용되고 있습니다. 별도의 신규 개발 없이 공식 문서와 마켓플레이스만으로 오늘 바로 시작 가능합니다.

## 필요 도구
- Claude Code (이미 사용 중, 무료/구독 요금제 내 포함)
- Claude Code 공식 플러그인 마켓플레이스 (`/plugin` 명령, 무료)
- Notion MCP 서버 (Notion 공식 제공, 무료 — Notion 계정 필요)
- GitHub MCP 서버 (공식 제공, 무료 — GitHub 계정/토큰 필요)
- Slack MCP 서버 (선택, 무료 — 워크스페이스 관리자 권한 필요할 수 있음)
- `.claude/skills/` 디렉터리 내 커스텀 스킬 정의 (직접 작성, 비용 없음)

## 구현 단계
1. Claude Code에서 `/plugin` 실행해 공식 마켓플레이스를 열고, 현재 하는 일(예: 블로그 자동화, 대시보드 운영)에 딱 맞는 플러그인 1~2개만 설치한다. "일단 다 설치"는 하지 않는다.
2. 실제로 매일 쓰는 외부 도구만 MCP로 연결한다 — 예: 회의/아이디어 메모용 Notion MCP, 코드 관리용 GitHub MCP. Slack은 팀 협업이 실제로 있을 때만 추가한다.
3. MCP 설치 후 `/context` 명령으로 토큰 사용량 증가분을 확인한다. 전체 컨텍스트의 20%를 넘으면 가장 덜 쓰는 MCP 하나를 제거한다.
4. 실제 업무 1건(예: 최근 회의 내용이 담긴 노션 페이지 → 할 일 항목 자동 추출 → 노션 DB에 기록)으로 MCP 동작을 검증한다.
5. 검증되면, 반복되는 그 작업 흐름을 `.claude/skills/`에 스킬로 등록해 다음부터는 명령어 한 줄(`/meeting-todo` 등)로 실행되게 만든다.
6. 이 구조를 외주·컨설팅 서비스 상품화의 기반으로 활용한다 — 예: "노션 회의록 자동 할일화 세팅"을 클라이언트에게 패키지로 제공하는 식으로 확장.

## 예상 공수
- 플러그인 1~2개 설치 및 확인: 15~30분, 난이도 하
- Notion/GitHub MCP 연결 및 토큰 점검: 30분~1시간, 난이도 중 (API 키/권한 설정 포함)
- 실제 업무 1건 검증: 30분~1시간, 난이도 중
- 커스텀 스킬로 등록: 30분~1시간, 난이도 중 (스킬 작성 경험 필요)
- 총합: 약 2~4시간, 전체 난이도 중

## 리스크/유의점
- "24개 필수 설치"류 조언은 역효과 — MCP·플러그인이 많을수록 컨텍스트 토큰을 갉아먹고 서로 충돌할 수 있음. 반드시 "쓰는 것만" 원칙 유지.
- 원 게시물의 DM 링크(설치 목록 24개)는 출처 불명이며 공식 마켓플레이스 밖 링크이므로 클릭·DM 요청하지 않는다. 필요한 정보는 전부 공식 마켓플레이스/문서에서 확인 가능.
- Notion/GitHub/Slack MCP는 API 토큰·접근 권한을 다루므로, 외주 클라이언트 데이터에 연결할 경우 권한 범위를 최소화하고 토큰 관리에 주의.
- 스킬/플러그인을 늘릴 때마다 `/context`로 토큰 점검하는 습관을 들이지 않으면 응답 품질 저하(컨텍스트 희석)로 이어질 수 있음.
