# Handrive 기반 P2P 파일 전송 자동화 — 개인 MacBook MCP 통합 블루프린트

## 개요
Handrive는 서버에 파일을 영구 저장하지 않고 브라우저/클라이언트 간 직접 전송(P2P)으로 파일을 주고받는 무료 서비스로, 40개의 MCP(Model Context Protocol) 툴을 제공해 Claude 같은 AI 에이전트가 파일 업로드·다운로드·공유 링크 생성 등을 자동으로 수행할 수 있게 한다. 개인 MacBook에서는 이를 Claude Desktop/Code의 MCP 서버로 등록해 "이 파일을 만들고 상대방에게 공유 링크로 전달" 같은 작업을 사람 개입 없이 자동화하는 데 활용 가치가 있다.

## 구현 가능성 — 상
- MCP 서버 등록은 `claude_desktop_config.json` 또는 Claude Code `mcp` 설정 파일 편집만으로 끝나는 표준화된 절차라 macOS 로컬 환경에서 특별한 인프라 없이 바로 적용 가능.
- Handrive가 무료 P2P 서비스이고 별도 클라우드 스토리지 계약이나 서버 운영이 필요 없어 개인 환경 제약이 거의 없음.
- 다만 실제 40개 툴의 구체 스펙(인증 방식, WebRTC 시그널링 서버 의존성, Node 버전 요구사항 등)이 HN 게시물만으로는 확인되지 않아, 공식 문서/레포를 먼저 확인하는 선행 조사가 필요함(그래서 "상"이지 "최상"은 아님).

## 필요 도구
- **Handrive MCP 서버** — handrive.ai에서 제공하는 MCP 서버 패키지 (무료, 단 정확한 설치 방법은 공식 사이트/레포 확인 필요)
- **Claude Desktop 또는 Claude Code** — MCP 클라이언트 역할 (무료/유료 플랜에 따라 다름, 이미 보유 중이라 가정)
- **Node.js (LTS, 예: v20+)** — MCP 서버가 npx 기반일 가능성이 높음 (무료, `brew install node`)
- **Homebrew** — Node 설치용 (무료)
- **(선택) ngrok 또는 Tailscale** — P2P 연결이 NAT/방화벽에 막힐 경우 우회용 (무료 티어 존재)

## 구현 단계
1. https://handrive.ai 및 HN 코멘트(https://news.ycombinator.com/item?id=47403882)를 방문해 MCP 서버 설치 명령어(npx 패키지명 또는 GitHub 레포 URL)와 인증 필요 여부를 확인한다.
2. 터미널에서 `node -v`로 Node.js 설치 여부 확인, 없으면 `brew install node`로 설치한다.
3. Handrive MCP 서버를 로컬에서 단독 실행해 정상 동작하는지 테스트한다 (예: `npx handrive-mcp` 형태, 정확한 명령은 1단계에서 확인한 값 사용).
4. `~/Library/Application Support/Claude/claude_desktop_config.json`(Claude Desktop 사용 시) 또는 Claude Code의 `.mcp.json`에 Handrive MCP 서버 항목을 추가한다:
   ```json
   {
     "mcpServers": {
       "handrive": {
         "command": "npx",
         "args": ["-y", "handrive-mcp"]
       }
     }
   }
   ```
5. Claude Desktop/Code를 재시작하고 MCP 도구 목록에 Handrive의 40개 툴(파일 업로드, 다운로드 링크 생성, 전송 상태 조회 등)이 정상적으로 노출되는지 확인한다.
6. 작은 테스트 파일(예: 텍스트 파일)로 실제 P2P 전송을 시도해 링크 생성 → 다른 기기(또는 브라우저 시크릿 창)에서 다운로드까지 end-to-end로 검증한다.
7. 검증되면 실제 자동화 시나리오(예: "매일 생성되는 리포트 파일을 특정 팀원에게 공유 링크로 전달")에 맞춰 Claude에게 반복 작업을 지시하거나 `/loop` 스킬로 주기적 자동화를 구성한다.
8. 방화벽/NAT 환경에서 P2P 연결이 실패할 경우, ngrok 또는 Tailscale을 이용한 우회 경로를 마련한다.

## 예상 공수
- MCP 서버 설치 및 Claude 연동: 30분~1시간
- 실제 전송 테스트 및 방화벽 이슈 대응: 30분~1.5시간 (네트워크 환경에 따라 변동 큼)
- 자동화 워크플로우 구성(반복 작업, 알림 등): 1~2시간
- **총 예상: 2~4.5시간, 난이도: 하~중** (표준 MCP 설정 작업이라 기술적 난이도는 낮으나, P2P 특성상 네트워크 환경 이슈로 디버깅 시간이 늘어날 수 있음)

## 리스크/유의점
- **신뢰성 검증 부족**: HN 포인트 2점, 댓글 1개로 초기 단계 프로젝트이며 아직 커뮤니티 검증이 부족함. 프로덕션 워크플로우에 바로 편입하기보다 개인 테스트 용도로 먼저 검증 권장.
- **P2P 연결 안정성**: NAT/방화벽 환경(회사 네트워크, VPN 등)에서 WebRTC 기반 P2P 연결이 실패할 수 있어 폴백 경로(서버 릴레이) 지원 여부를 확인해야 함.
- **보안/개인정보**: 자동화된 파일 공유는 의도치 않은 파일 노출 위험이 있으므로, AI 에이전트가 어떤 파일을 어떤 조건에서 공유할지 명확한 가드레일(허용 디렉토리, 승인 절차) 설정 필요.
- **MCP 서버 신뢰 체인**: npx로 원격 패키지를 그대로 실행하는 구조라면 서드파티 코드 실행 리스크가 있으므로, 공식 GitHub 레포의 소스코드를 사전 검토하는 것을 권장.
- **서비스 지속성**: 무료 P2P 서비스는 운영 주체의 지속 가능성이 불확실할 수 있어, 중요 파일 전송의 유일한 경로로 의존하지 않는 것이 안전.
