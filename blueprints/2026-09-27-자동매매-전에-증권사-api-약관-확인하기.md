# 증권사 API 자동매매 전, 약관부터 확인하기

## 쉽게 말하면
자동매매 프로그램을 만드는 건 자동차를 만드는 것과 비슷한데, 증권사 API 약관은 그 자동차를 몰 수 있는 "도로교통법"입니다. 아무리 성능 좋은 차를 만들어도 법을 어기면 압수당하듯, 코드를 아무리 잘 짜도 약관을 어기면 API 접근이 차단되거나 계좌가 제한될 수 있습니다.

## 이걸로 할 수 있는 것
1. 토스증권/키움/KIS 중 어떤 API를 쓸지 정하기 전에 각 사의 약관 조항(법인 금지, 재배포 금지, 개인 목적 한정)을 자동으로 비교·정리한 체크리스트를 받아본다.
2. 내가 만들려는 자동매매 시스템 설계(예: 시세를 대시보드에 표시)가 약관 위반 소지가 있는지 사전에 셀프 점검한다.
3. 약관 변경이나 신규 공지가 뜨면 알림을 받아, 서비스 운영 중 갑자기 API가 차단되는 사고를 예방한다.

## 개요
이 항목은 코드를 자동화하는 것이 아니라 "법적/정책적 리스크를 조사하고 체크리스트화하는 리서치 자동화"입니다. 개인 MacBook에서 노션/마크다운 문서로 각 증권사 API 약관 핵심 조항을 정리하고, 본인의 자동매매 설계와 대조하는 워크플로를 구축하는 것이 핵심 가치입니다.

## 구현 가능성
**상** — 코드 개발이 필요 없고, 약관 원문 수집과 요약, 체크리스트 작성만으로 완결됩니다. 기술적 난이도가 거의 없고(대시보드 평가 난이도 1점), 첫 단계도 명확히 제시되어 있어 오늘 바로 실행 가능합니다.

## 필요 도구
- **증권사 Open API 개발자센터 웹페이지** (무료, 로그인 필요)
  - 한국투자증권(KIS) Developers: https://apiportal.koreainvestment.com
  - 키움증권 Open API+: https://openapi.kiwoom.com
  - 토스증권 Open API (문서 페이지, 정식 공개 여부 확인 필요)
- **Claude/ChatGPT** (약관 원문 요약·조항 비교용, 무료/유료 티어 중 선택)
- **Notion 또는 Obsidian** (체크리스트·비교표 관리, 무료)
- **macOS 단축어(Shortcuts) 또는 cron/launchd** (약관 페이지 변경 감지 자동화, 무료, 선택사항)
- **모의투자 계좌** (KIS/키움 제공, 무료) — 실전 배포 전 테스트용

## 구현 단계
1. 사용할 증권사(KIS, 키움, 토스 등) Open API 개발자 포털에 가입하고 API 이용약관 원문 PDF/웹페이지를 다운로드한다.
2. 약관 원문을 Claude/ChatGPT에 붙여넣고 "법인 사용 금지 여부, 시세 재배포 금지 여부, 개인 목적 한정 범위, 위반 시 제재 조항"을 표로 정리해달라고 요청한다.
3. 정리된 표를 Notion/Obsidian에 "증권사별 API 약관 비교표"로 저장하고, 자신의 자동매매 아이디어(예: 시세를 웹 대시보드에 공개, 다른 사람과 공유 등)와 대조해 위반 소지 항목에 체크한다.
4. 위반 소지가 있는 기능(예: 실시간 시세를 외부에 노출)은 설계 단계에서 제거하거나 "개인 브라우저 내 로컬 표시"로 한정하도록 아키텍처를 수정한다.
5. 자동매매 로직 개발은 반드시 모의투자 계좌 API 키로 먼저 연결·테스트하고, 최소 1~2주 정상 동작을 확인한 뒤에만 실전 계좌 키로 전환한다.
6. (선택) macOS 단축어나 간단한 스크립트로 증권사 API 공지사항 페이지를 주 1회 스크래핑해 약관 변경 여부를 이메일/알림으로 받는다.

## 예상 공수
- 약관 조사 및 비교표 작성: **1~2시간** (난이도: 하)
- 자신의 설계와 대조·수정: **1시간** (난이도: 하)
- 모의투자 계좌 연동 테스트: **2~4시간** (난이도: 중, API 인증 방식에 따라 상이)
- 약관 변경 알림 자동화(선택): **1~2시간** (난이도: 중)
- **총 예상: 반나절 내외**, 별도 기술 스택 학습 불필요

## 리스크/유의점
- 약관은 증권사가 수시로 개정할 수 있으므로, 요약 결과를 한 번 정리해도 주기적으로(분기 1회 이상) 재확인이 필요합니다.
- LLM이 약관을 요약할 때 법적 뉘앙스를 놓칠 수 있으므로, 최종 판단(특히 계좌 제한·형사책임 소지 조항)은 반드시 원문을 직접 재확인해야 합니다.
- "개인 목적 한정" 조항은 해석 여지가 있어, 자동매매 결과를 블로그/SNS에 공유하는 것도 애매할 수 있으니 보수적으로 접근하는 것이 안전합니다.
- 실전 계좌로 전환하기 전 반드시 모의투자로 충분히 검증하지 않으면, 코드 버그로 인한 금전적 손실 리스크가 약관 위반 리스크보다 더 클 수 있습니다.
