# aSPARK(Claude Code용 애자일 AI 제품팀 프레임워크)를 커스터마이즈해 "즉시 투입형 에이전트 팀" 템플릿 판매하기

## 개요
aSPARK는 Claude Code 위에서 PM·디자이너·개발자·QA 역할을 하는 서브에이전트들이 애자일 스프린트처럼 협업하도록 짜인 오픈소스 프레임워크(설정 파일 + 서브에이전트 정의 + 워크플로 스크립트 묶음)다. 이 자체는 무료 공개 프로젝트지만, 이를 실제 업무(스타트업 MVP 개발, 사내 프로젝트)에 맞게 커스터마이즈하고 검증한 "업종별/용도별 에이전트 팀 템플릿"을 Gumroad나 노션 템플릿 형태로 판매하거나, 클라이언트 컨설팅 시 세팅 대행 서비스로 수익화할 수 있다. 원문 자체는 HN 반응이 거의 없어(포인트 1, 댓글 0) 검증되지 않은 초기 프로젝트이므로, 직접 써보고 개선한 뒤 "실전 검증된 버전"으로 차별화하는 것이 핵심이다.

## 구현 가능성 — 중
- 근거(가능): Claude Code의 서브에이전트/커스텀 명령/훅 시스템은 이미 안정적으로 공개된 기능이라(.claude/agents/*.md, settings.json 등) aSPARK 같은 프레임워크를 로컬에서 설치·수정·확장하는 작업은 순수 설정 파일 편집 수준이라 macOS에서 바로 가능.
- 근거(제약): 저장소가 신생(HN 포인트 1)이라 실전 신뢰성·유지보수 여부가 불확실하고, 코드/문서를 직접 읽고 검증하는 데 시간이 들며, "판매 가능한 수준"으로 다듬으려면 최소 1개 실제 프로젝트에 적용해 결과물을 만들어봐야 설득력이 생김.

## 필요 도구
- Claude Code CLI (구독형, 이미 보유 — 추가 비용 없음)
- aSPARK 저장소 (github.com/a-lottes/aSPARK, 무료 오픈소스, 라이선스 확인 필요)
- Git / GitHub (무료)
- Gumroad 또는 Lemon Squeezy — 템플릿 판매 플랫폼 (거래 수수료만 발생)
- Notion 또는 GitHub Pages — 템플릿 문서화/랜딩페이지 (무료)
- 테스트용 소규모 실제 프로젝트 1개 (예: 사이드 프로젝트, 사내 자동화 스크립트) — 검증용
- (선택) Loom — 데모 영상 녹화로 신뢰도 제고 (무료 티어 있음)

## 구현 단계
1. aSPARK 저장소를 클론해 라이선스(MIT/Apache 등)와 실제 구성(서브에이전트 정의, 훅, 커스텀 명령)을 직접 읽어보고, `.claude/agents/`, `.claude/commands/` 구조가 실제로 동작하는지 로컬에서 `claude` 실행해 검증한다.
2. 검증에 쓸 소규모 실제 과제(예: 개인 사이드 프로젝트의 기능 하나)를 정해, aSPARK의 PM→디자인→개발→QA 사이클을 그대로 돌려보고 어디서 막히는지(역할 정의 모호, 컨텍스트 유실, 승인 루프 부재 등) 기록한다.
3. 발견한 문제점을 고쳐 "한국어 대응 + 특정 업종(예: 이커머스 MVP, 사내 백오피스 자동화) 특화" 버전으로 fork/수정한다 — 역할별 프롬프트, 체크리스트, 품질 게이트를 실전에서 검증된 내용으로 교체.
4. 개선한 결과를 별도 저장소로 정리하고 README에 "Before/After" 데모(스프린트 진행 로그, 산출물 스크린샷)를 포함시켜 신뢰도를 확보한다.
5. Gumroad에 "Claude Code 애자일 에이전트 팀 스타터 킷"으로 등록 — 설치 가이드 + 커스터마이징 문서 + 1회 화상 온보딩 옵션을 묶어 가격대(예: $29~99)를 책정한다.
6. 별도로 "세팅 대행" 서비스도 제공 — 관심 있는 소규모 스타트업/에이전시에 aSPARK 기반 개발 워크플로를 직접 설치해주는 1회성 컨설팅(시간당 또는 프로젝트당 과금)을 링크드인/X에 홍보한다.

## 예상 공수
- 저장소 분석 + 로컬 검증: 3~4시간
- 실전 프로젝트 적용 및 문제 발견/수정: 8~12시간
- 커스텀 버전 정리 + 문서화: 4~6시간
- 랜딩페이지/Gumroad 등록 + 데모 영상: 3~5시간
- 총 18~27시간 (약 1주), 난이도: 중

## 리스크/유의점
- 원문 신뢰도가 매우 낮음(HN 포인트 1, 댓글 0) — 실제로 써보기 전까지는 "동작하는 프레임워크"인지 "아이디어 수준 프로토타입"인지 알 수 없으므로, 판매를 결정하기 전 반드시 1단계 로컬 검증을 먼저 거칠 것.
- 오픈소스 원저작자의 라이선스 조건(재배포·상업적 이용 허용 여부)을 반드시 먼저 확인 — MIT 계열이 아니면 "판매"가 아니라 "컨설팅/세팅 대행" 모델로만 가야 함.
- 멀티 에이전트 협업 방식은 Anthropic/Claude Code 자체가 공식 기능(서브에이전트, 훅)으로 빠르게 흡수할 가능성이 있어, 이 컨셉의 차별화 수명이 짧을 수 있음 — 빠르게 검증하고 빠르게 출시하는 것이 중요.
