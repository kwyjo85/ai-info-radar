# jev-router로 Claude Code 모델 비용 최적화 자동 라우팅 구축하기

## 개요
jev-router는 Claude Code에서 작업의 난이도/유형을 판단해 가장 저렴한 모델(Haiku 등)로 우선 라우팅하고, 필요할 때만 고성능 모델(Sonnet/Opus)로 승격시키는 오픈소스 라우터입니다. 반복적인 코드 작업 중 상당수는 저비용 모델로도 충분히 처리 가능하므로, 이를 자동화하면 개인 개발 환경에서 API 비용을 눈에 띄게 절감할 수 있습니다. 특히 사이드 프로젝트나 실험적 작업이 많은 1인 개발 환경에서 비용 대비 효율이 큽니다.

## 구현 가능성 — 중
근거: GitHub 저장소 기반 오픈소스 도구로 설치 자체는 어렵지 않으나, (1) 저장소 성숙도가 낮음(HN 포인트 3점, 댓글 0개로 커뮤니티 검증이 거의 없음), (2) Claude Code의 모델 라우팅/프록시 메커니즘과 호환되도록 설정하는 과정에서 문서화 부족 시 시행착오가 예상됨, (3) 라우팅 로직이 기대만큼 정교하지 않을 경우 품질 저하 위험이 있어 "상"보다는 "중"으로 평가.

## 필요 도구
- **jev-router** (GitHub: gargpratyush/jev-router) — 무료, 오픈소스
- **Claude Code CLI** — Anthropic 정식 배포, 무료(사용량은 API 과금)
- **Anthropic API Key** (Haiku 4.5 / Sonnet 5 / Opus 5 접근용) — 사용량 기반 과금
- **Node.js 또는 Python** (저장소의 실제 구현 언어에 따라 다름, 저장소 확인 필요) — 무료
- **직접 리서치 필요**: README 및 소스코드 확인 (설치법, 설정 파일 포맷, 라우팅 규칙 정의 방식) — 저장소 자체가 신생/저인지도라 사전 조사가 필수

## 구현 단계
1. `git clone https://github.com/gargpratyush/jev-router` 로 저장소를 로컬에 클론하고 README, package.json/pyproject.toml 등을 확인해 실제 언어·의존성·최소 요구사항(Node/Python 버전)을 파악한다.
2. 저장소가 Claude Code와 통합되는 방식을 코드 레벨에서 확인한다 — (a) Claude Code의 `ANTHROPIC_BASE_URL` 환경변수를 가로채는 프록시 서버 방식인지, (b) Claude Code 설정(`~/.claude/settings.json`)의 모델 필드를 직접 치환하는 방식인지 구분한다.
3. 로컬에서 격리된 테스트 환경(별도 macOS 사용자 셸 세션 또는 프로젝트 전용 디렉터리)에 설치하고, 기존 Claude Code 설정을 백업(`cp ~/.claude/settings.json ~/.claude/settings.json.bak`)한 뒤 라우터를 연결한다.
4. 라우팅 규칙(예: 파일 읽기/간단한 질의응답 → Haiku, 코드 생성/리팩터링 → Sonnet, 복잡한 아키텍처 설계 → Opus)을 정의하는 설정 파일을 작성한다. jev-router가 규칙 기반(rule-based)인지 자체 분류 모델을 쓰는지에 따라 설정 포맷이 다르므로 소스코드 확인 후 진행.
5. 실제 반복 작업(간단한 리팩터링, 파일 조회, 커밋 메시지 생성 등) 몇 가지를 실행해 응답 품질과 실제 라우팅 결과를 비교 검증한다.
6. Anthropic 콘솔의 사용량 대시보드에서 모델별 호출 비중과 비용 변화를 1주일간 모니터링한다.
7. 문제없이 동작하면 프로젝트별로 선택적 적용(`.claude/settings.local.json`)하거나 전역 적용 여부를 결정한다.

## 예상 공수
- 저장소 조사 및 호환성 파악: 1~2시간
- 설치 및 테스트 환경 구축: 1시간
- 라우팅 규칙 튜닝 및 검증: 2~3시간
- 1주일 모니터링(수동 확인 시간만 집계): 총 30분~1시간
- 난이도: 중 (신생 오픈소스 도구의 문서 부족을 스스로 코드 리딩으로 보완해야 함)

## 리스크/유의점
- 저장소가 매우 신생(HN 반응 미미)이라 유지보수 중단 가능성이 있고, 프로덕션 워크플로우에 바로 적용하기보다 사이드 프로젝트에서 먼저 검증 필요.
- 저비용 모델로 잘못 라우팅될 경우 코드 품질 저하(버그 누락, 불완전한 리팩터링) 위험이 있어, 중요 작업(보안 관련 코드, 프로덕션 배포 전 코드)에는 수동으로 고성능 모델을 강제 지정하는 안전장치를 둘 것.
- API 키를 프록시 서버에 노출하는 구조라면, 로컬 네트워크 외부에 키가 유출되지 않도록 방화벽/바인딩 설정(`localhost` only)을 반드시 확인.
- Claude Code 자체가 향후 공식적으로 모델별 자동 라우팅 기능을 내장할 가능성이 있으므로, 서드파티 도구 도입 전 Claude Code 공식 릴리스 노트를 확인해 중복 투자를 피할 것.
