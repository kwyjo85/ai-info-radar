# Gobag 기반 Claude Code 세션 아카이빙으로 jev 작업 파이프라인 수익화

## 개요
Gobag은 Claude Code 세션 로그를 의미 기반(semantic)으로 검색 가능한 장기 기억 저장소로 변환해주는 오픈소스 도구다. jev를 활용해 수익을 창출하는 작업(코드 자동화 납품, 반복 프로젝트 컨설팅, 템플릿/스니펫 판매 등)에서 과거 세션의 맥락과 해결책을 즉시 재사용할 수 있게 되어, 동일 유형 작업의 처리 시간을 줄이고 청구 가능한 작업량을 늘릴 수 있다. 특히 반복 고객·반복 프로젝트가 많은 프리랜스/컨설팅 구조에서 "과거에 어떻게 풀었는지"를 즉시 불러오는 것 자체가 시간당 단가를 방어하는 무기가 된다.

## 구현 가능성 — 중
- Gobag은 CLI/라이브러리 형태로 로컬 설치 가능하며 macOS 환경에서 특별한 제약 없이 구동 가능 (근거: GitHub 저장소가 Go 기반 CLI로 배포됨).
- 다만 별점 3점, 코멘트 0개로 아직 검증 데이터가 적은 신생 프로젝트라 README 외 문서화가 부족할 가능성이 높고, Claude Code 세션 로그 포맷 변경 시 파서가 깨질 리스크가 있음.
- jev 수익화 파이프라인에 실제로 연결하려면 "저장된 세션 지식을 어떻게 견적/작업에 재사용할지"에 대한 워크플로우를 직접 설계해야 하므로 도구 설치보다 활용 설계에 더 큰 노력이 든다.

## 필요 도구
- **Gobag** (무료, OSS) — https://github.com/satmihir/gobag
- **Go 런타임** (무료) — Gobag 빌드/실행용
- **Claude Code CLI** (Pro/Max 구독 필요, 유료) — 세션 원본 로그 생성원
- **임베딩/벡터 검색 백엔드** — Gobag 내장 벡터 스토어 사용 시 무료, 별도 벡터 DB(예: Chroma, 로컬) 연동 시 무료(로컬 실행 기준)
- (선택) **Anthropic API 키** (사용량 기반 유료) — Gobag이 자체 요약/임베딩에 Claude API를 호출하는 경우
- **jev 워크플로우 스크립트/저장소** — 아카이빙된 지식을 실제 견적·산출물 생성에 연결할 자동화 스크립트 (직접 작성)

## 구현 단계
1. macOS에 Homebrew로 Go 설치 (`brew install go`) 후 Gobag 저장소 클론 및 `go build`로 로컬 바이너리 생성.
2. Claude Code 세션 로그 저장 위치(`~/.claude/projects/`) 확인 후, Gobag 설정 파일에 해당 경로를 아카이빙 소스로 지정.
3. 초기 1회 배치 실행으로 기존 jev 관련 프로젝트 세션들을 전부 아카이빙, 의미 기반 인덱스 생성.
4. jev로 처리 중인 신규 작업(견적, 코드 리뷰, 반복 요청 등) 시작 전에 Gobag 검색 명령으로 "유사 과거 세션" 조회를 표준 루틴으로 삽입 (예: 새 세션 시작 전 체크리스트에 추가).
5. 재사용 가능한 해결 패턴(자주 등장하는 버그 수정, 견적 산출 로직, 클라이언트별 요구사항)을 Gobag 검색 결과에서 뽑아 별도 "재사용 스니펫 노트"로 정리, jev 작업 템플릿화.
6. 신뢰도가 쌓이면 이 아카이빙+재사용 프로세스 자체를 "빠른 납품이 가능한 이유"로 패키징해 상위 단가 패키지나 정기 리테이너 계약 제안에 활용.
7. 매주 새 세션이 누적될 때마다 증분 인덱싱이 되도록 cron(launchd) 잡으로 Gobag 재실행 스케줄링.

## 예상 공수
- 설치 및 초기 세팅: 2~3시간 (난이도: 하)
- 기존 세션 아카이빙 + 인덱스 검증: 2~4시간 (난이도: 중, 로그 포맷 이슈 가능)
- jev 워크플로우에 검색·재사용 루틴 통합: 4~8시간 (난이도: 중~상, 문서화되지 않은 부분 직접 설계 필요)
- 총 예상: 1~2일 (실작업 시간 기준 8~15시간)

## 리스크/유의점
- 프로젝트가 아직 초기 단계(별 3, 이슈/코멘트 0)라 향후 유지보수 중단 또는 breaking change 가능성이 있음 — 로컬 포크본을 보관해두는 것을 권장.
- Claude Code 세션 로그에는 클라이언트 프로젝트의 민감 정보가 포함될 수 있으므로, 아카이빙된 인덱스를 외부 서비스나 클라우드 벡터 DB로 내보낼 경우 계약상 기밀유지 조항 위반 여부를 반드시 확인.
- 임베딩 생성에 Anthropic API를 호출하는 구조라면 세션 양이 많을 때 API 비용이 누적될 수 있으므로 사용량 모니터링 필요.
- "수익창출"로 직결되려면 단순 아카이빙을 넘어 실제 영업/견적 프로세스에 통합하는 별도 설계가 필수이며, 도구 자체는 이 통합을 자동으로 해주지 않음.
