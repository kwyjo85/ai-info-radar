# Ollaya — 오픈소스 Jev 스타일 AI 의사결정 모델

## 쉽게 말하면
Ollaya는 최근 화제가 된 "Jev" 같은 고급 AI 의사결정 모델을 아무나 내려받아 직접 돌려볼 수 있게 만든 공개판이라고 보면 됩니다. 유료 레스토랑의 셰프 레시피를 누군가 그대로 공개해서, 내 주방(맥북)에서도 비슷한 요리를 만들 수 있게 해준 셈입니다.

## 이걸로 할 수 있는 것
1. 매일 아침 뉴스·리포트를 모아 "이 정보가 내 사업에 중요한가?"를 자동으로 판단시켜 브리핑을 정제할 수 있습니다.
2. 클라이언트 요청서를 넣으면 "지금 바로 처리/보류/거절" 같은 의사결정 초안을 자동 생성해 컨설팅 답변 속도를 높일 수 있습니다.
3. Claude Code 안에 서브 판단 엔진으로 붙여서, 여러 자동화 스크립트가 내려야 하는 소소한 판단(우선순위, 리스크 등급 등)을 API 비용 없이 로컬에서 처리하게 만들 수 있습니다.

## 개요
Ollaya는 "정보를 보고 판단을 내리는" 의사결정형 AI 모델을 오픈소스로 공개한 프로젝트로, Jev류 상용 모델의 핵심 기능(분류·우선순위·판단 근거 생성)을 로컬 또는 저비용 인프라에서 재현하는 것이 목표입니다. 가치는 "판단"이라는 반복 작업을 API 호출 없이 자동화해 운영비를 낮추고, 자신만의 판단 기준으로 파인튜닝해 컨설팅/자동화 상품에 차별화된 로직을 넣을 수 있다는 점입니다.

## 구현 가능성 — 중
- 근거: 공개된 지 얼마 안 된 프로젝트(HN 포인트 462, 댓글 117로 관심은 높음)라 문서화·안정성이 검증 전 단계일 가능성이 높습니다.
- 오픈소스라 맥북(Apple Silicon)에서 로컬 구동 자체는 기술적으로 가능하나, 모델 크기·양자화 지원 여부·한국어 성능은 실제 레포를 확인해야 확정 가능합니다.
- Claude Code와의 연동(서브 판단 엔진 역할)은 API/CLI 래핑만 하면 되므로 통합 난이도는 낮은 편입니다.

## 필요 도구
- Ollaya 레포 (GitHub, 무료 — 라이선스 확인 필요)
- Ollama 또는 llama.cpp (로컬 추론 런타임, 무료)
- Python 3.11+ / uv 또는 venv (무료)
- Claude Code CLI (기존 사용 중, 유료 구독)
- (선택) LangChain/LlamaIndex 또는 자체 스크립트로 파이프라인 연결 (무료)
- (선택) Modal/Replicate 등 클라우드 GPU (모델이 로컬에 안 돌 경우 대비, 종량제 유료)

## 구현 단계
1. `ollaya.dev` 사이트와 GitHub 레포를 열어 라이선스, 모델 크기(파라미터 수), 요구 스펙(RAM/VRAM), 실행 예제를 확인한다.
2. 맥북에서 Ollama로 구동 가능한 포맷(GGUF 등)을 지원하는지 확인하고, 지원 시 `ollama pull`로 로컬 설치를 시도한다.
3. 샘플 판단 태스크(예: "이 뉴스가 AI 자동화 수익화에 관련 있는가 Y/N + 이유") 5~10개로 프롬프트를 짜고 응답 품질을 Jev/Claude와 비교 테스트한다.
4. 품질이 쓸만하면, 기존 ai-info-radar 파이프라인의 "채점" 단계에 Ollaya를 1차 필터로 붙이고, Claude Code(Claude)는 2차 정제·브리핑 작성에만 쓰도록 역할을 분리해 API 비용을 절감한다.
5. 컨설팅 상품화 관점에서, 클라이언트별 판단 기준(회사 정책, 업종 특성)으로 소규모 파인튜닝/프롬프트 세트를 만들어 "맞춤 의사결정 어시스턴트"를 패키지 상품으로 제안해본다.
6. 결과를 로그로 남겨 Claude 대비 Ollaya의 오판율을 주기적으로 점검하고, 기준 미달 시 즉시 Claude로 롤백하는 안전장치를 둔다.

## 예상 공수
- 탐색 및 로컬 설치 테스트: 2~3시간 (난이도: 하)
- 기존 파이프라인 통합(1차 필터 역할): 4~6시간 (난이도: 중)
- 클라이언트 맞춤 파인튜닝/상품화 실험: 1~2일 (난이도: 상, 데이터·평가 기준 설계 필요)

## 리스크/유의점
- 공개 직후 프로젝트라 문서·커뮤니티 지원이 부족할 수 있고, 실제 성능이 Jev/Claude 대비 크게 떨어질 위험이 있습니다.
- 로컬 모델의 판단을 고객 대상 자동화에 그대로 노출하면 오판 시 신뢰도 문제가 생기므로, 반드시 사람 또는 Claude의 2차 검증 단계를 거쳐야 합니다.
- 라이선스(상업적 이용 가능 여부)를 확인하지 않고 수익화 상품에 바로 쓰면 법적 리스크가 있으니 사용 전 라이선스 조항을 반드시 확인해야 합니다.
