# Jev와 Pi로 커스텀 하네스 구축하기

## 쉽게 말하면
Pi SDK는 자동차의 "섀시(뼈대)"이고, Jev는 그 위에 얹는 "엔진(판단하는 뇌)"이라고 보면 됩니다. 즉 판단 로직을 직접 다 짜는 대신, 이미 만들어진 뼈대(Pi)에 원하는 두뇌(Jev)를 꽂아서 나만의 자동화 프로그램을 조립하는 방식입니다.

## 이걸로 할 수 있는 것
1. 반복적인 클라이언트 업무(초안 작성, 리포트 생성)를 Jev 판단 로직이 들어간 Pi 하네스로 자동 처리해 대행 서비스 상품으로 판매한다.
2. Claude Code로 진행 중인 프로젝트 안에 Pi 기반 서브 자동화를 심어, 재무·법무 등 특정 도메인 판단만 Jev에 위임하는 사이드 프로젝트를 만든다.
3. 지금 운영 중인 ai-info-radar 같은 정보 수집 파이프라인에 Pi 하네스+Jev 판단 노드를 추가해 "이 정보가 사업 기회인지"를 자동으로 채점한다.

## 개요
Pi SDK로 에이전트 실행 흐름(하네스)의 뼈대를 구성하고, 그 안의 핵심 판단(decision) 단계를 Jev 모델에 맡기는 구조입니다. 한 번 만들어두면 여러 자동화 파이프라인에 재사용 가능한 "판단 엔진"이 되어, Jev 자체를 서비스로 팔지 않아도 그 판단력을 활용한 자동화 상품/워크플로우를 만들 수 있습니다.

## 구현 가능성 — 중
근거: 개념 자체는 "SDK 하네스 + 외부 모델을 판단 노드로 연결"이라는 익숙한 에이전트 패턴이라 구현 방식은 어렵지 않습니다. 다만 Jev(2026-09 출시, 어시스턴트 지식 컷오프 이후 모델)와 Pi SDK 모두 실사양을 직접 확인한 적이 없고, 제공된 원문도 HN 포인트 1점·댓글 0개의 짧은 글이라 세부 API·설치법을 아직 검증하지 못했습니다. 원문 전체와 공식 문서를 먼저 열람해야 정확한 구현이 가능합니다.

## 필요 도구
- Pi SDK (하네스/오케스트레이션 프레임워크) — 오픈소스 여부 및 설치 패키지명 확인 필요 (비용 미확인)
- Jev API 접근 권한 (TypeSafe AI System One 제공사) — 유료 가능성 높음, API 키 발급 필요
- Python 또는 TypeScript 로컬 개발 환경 (맥북)
- Claude Code — 기존 워크플로우 통합 및 코드 작성/리뷰용 (기 보유)
- launchd — 파일럿 안정화 후 자동 실행 등록용 (macOS 기본 제공, 무료)

## 구현 단계
1. dair.ai 원문 기사(https://academy.dair.ai/resources/jev-decisions-in-a-pi-sdk-harness) 전체를 열람해 Pi SDK 설치법과 Jev 연동 예제 코드를 확인한다.
2. Pi SDK 공식 GitHub/문서에서 실제 패키지명과 버전, 라이선스(무료/유료)를 확인한다.
3. Jev(TypeSafe AI System One) API 키 발급 절차와 요금 체계를 제공사 문서에서 직접 확인한다.
4. 맥북에 Python 가상환경을 만들고 Pi SDK를 설치한 뒤, "hello world" 수준의 최소 하네스를 실행해 정상 동작을 확인한다.
5. Jev API를 하네스의 decision 노드로 연결하는 어댑터 코드를 작성한다.
6. 파일럿 시나리오를 하나 정한다 (예: ai-info-radar의 블루프린트 채점 로직 일부를 Jev 판단으로 대체 실험).
7. 로컬에서 소규모로 실행해 결과 로그를 남기고, Claude Code로 결과를 리뷰·디버깅한다.
8. 결과가 안정적이면 launchd cron에 등록해 기존 파이프라인에 통합한다.
9. 판단 정확도와 API 비용을 검증한 뒤, 외주·대행 서비스로 상품화할지 결정한다.

## 예상 공수
- 원문·공식문서 리서치: 2~3시간
- Pi SDK 기본 셋업 및 hello world: 2~4시간
- Jev 연동 및 파일럿 시나리오 구현: 4~8시간
- 총합: 약 1~2일(8~15시간), 난이도: 중~상 (신규 SDK·모델 조합이라 문서 부족 시 상승 가능)

## 리스크/유의점
- Jev는 2026-09 출시된 최신 모델로 어시스턴트 지식 컷오프 이후라 API 사양·가격·가용성은 추측하지 말고 반드시 공식 문서로 직접 확인해야 한다.
- 제공된 원문은 HN 포인트 1점, 댓글 0개인 소규모 글이라 본문 내용을 아직 확보하지 못했으므로, 원문 전체를 먼저 읽어야 구체적 구현 방향이 확정된다.
- 신규 SDK·모델 조합은 커뮤니티 지원과 예제가 부족해 디버깅 시간이 예상보다 길어질 수 있다.
- Jev API 사용료 구조를 미리 확인하지 않으면 파일럿 단계에서 예상 밖 과금이 발생할 수 있다.
