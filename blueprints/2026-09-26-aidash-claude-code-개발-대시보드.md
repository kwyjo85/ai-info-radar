# AIDash: Claude Code 개발 대시보드로 "AI 자동화 컨설팅" 상품 만들기

## 쉽게 말하면
AIDash는 여러 개의 Claude Code 작업(세션·프로젝트·비용·진행 상황)을 한 화면에서 모아 보여주는 관제탑 같은 도구입니다. 여러 대의 배달 오토바이(=여러 Claude Code 세션)가 동시에 돌아갈 때, 배달 상황판 하나로 전체를 한눈에 보는 것과 비슷합니다. 지금 사용자가 Jev·인스타 대시보드처럼 여러 자동화 파이프라인을 직접 운영하고 있다는 점에서, 이런 "여러 AI 작업을 관리하는 대시보드" 개념 자체를 자신의 자동화 수익 사업에 재사용할 수 있습니다.

## 이걸로 할 수 있는 것
1. 매일 새벽에 launchd로 돌아가는 ai-info-radar, Jev 관련 자동화 스크립트들의 실행 상태·에러·비용을 아침에 대시보드 한 번 보고 파악한다.
2. 여러 클라이언트(외주)에게 "Claude Code 기반 자동화"를 판매할 때, 각 클라이언트 프로젝트의 작업 현황을 보여주는 관리 화면으로 재활용해 신뢰도를 높인다.
3. 여러 병렬 Claude Code 세션(예: 블루프린트 생성, 인스타 데이터 수집, 정보 레이더 채점)의 토큰 사용량·비용을 추적해 개인/클라이언트별 과금 근거 자료로 쓴다.

## 개요
AIDash는 Claude Code로 돌아가는 여러 작업의 상태·로그·비용을 시각화하는 개발자용 대시보드입니다. 자동화를 "여러 개" 운영하기 시작하면 반드시 생기는 문제(뭐가 돌고 있는지, 얼마나 썼는지, 뭐가 실패했는지 모름)를 해결해 주며, 이는 곧 자동화를 상품화·외주화할 때 신뢰를 주는 "가시성" 자산이 됩니다.

## 구현 가능성
**중** — 사이트 자체는 즉시 설치해 개인 대시보드로 쓰는 것은 쉽지만(상), 이걸 "수익화 상품"으로 확장하려면 멀티 테넌시·클라이언트별 인증·화이트라벨링 작업이 추가로 필요해(중) 종합적으로는 중간 난이도로 평가합니다. 근거: HN 포인트 4점·댓글 2개로 아직 검증 초기 단계 도구이며, API/내부 구조가 공개적으로 문서화되어 있는지 확인이 필요합니다.

## 필요 도구
- **AIDash** (aidash.dev) — 도구 자체, 가격/오픈소스 여부 확인 필요 (무료 가능성 있으나 사이트 방문 후 확인 필요)
- **Claude Code CLI** — 이미 사용자가 쓰고 있음, 유료 (Anthropic 구독/API 과금)
- **launchd** (macOS 내장, 무료) — 기존 자동화 스케줄러와 연동
- **GitHub Pages / gh-pages** (무료) — 기존 ai-info-radar 배포 방식과 동일하게 대시보드도 공개/비공개 배포 가능
- **ntfy 또는 Slack Webhook** (무료~저가) — 대시보드에서 이상 감지 시 알림 연동용

## 구현 단계
1. `https://aidash.dev/` 방문해 셀프호스팅 가능 여부, 오픈소스 저장소(GitHub) 존재 여부, 가격 정책을 먼저 확인한다.
2. 로컬 MacBook에 설치(또는 Docker/CLI로 실행)하여 현재 ai-info-radar와 Jev 관련 launchd 작업들을 AIDash가 인식하는 형식(로그 경로, 세션 메타데이터)에 맞게 연결한다.
3. 하루 정도 실사용하며 어떤 지표(비용, 실패율, 실행시간)가 실제로 유용한지 걸러낸다.
4. 유용하다고 판단되면, 외주 자동화 프로젝트(예: 소상공인 대상 "Claude Code로 만든 자동화" 패키지) 납품 시 이 대시보드를 화면 공유용 리포트로 붙여 "투명하게 관리해준다"는 차별점으로 제안한다.
5. 여력이 되면 AIDash 위에 간단한 비용 계산 로직(작업당 토큰×단가)을 얹어 클라이언트별 월 사용량 청구서 자동 생성 스크립트로 확장한다.

## 예상 공수
- 1단계 설치·연동 확인: 1~2시간, 난이도 하
- 3단계 실사용 검증: 며칠간 관찰 (실작업 시간은 하루 10분 내외), 난이도 하
- 4~5단계 상품화(청구서 자동화 포함): 4~8시간, 난이도 중

## 리스크/유의점
- 초기 단계 도구(HN 반응 미미)라 유지보수 중단·버그 가능성이 있어, 핵심 자동화 파이프라인의 단일 장애점으로 의존하지 말 것.
- 클라이언트 프로젝트 데이터를 보여줄 경우 API 키·비용 정보 등 민감 정보가 노출되지 않도록 화면 공유 전 반드시 필터링.
- 셀프호스팅이 아니라 외부 SaaS 형태라면, 프로젝트 코드/로그가 제3자 서버로 전송될 수 있으니 클라이언트 데이터 다루기 전 개인정보·보안 정책 확인 필요.
