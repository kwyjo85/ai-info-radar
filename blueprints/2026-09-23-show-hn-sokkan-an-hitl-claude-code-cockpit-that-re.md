# Sokkan 스타일 HITL Claude Code 콕핏 — 세션 기억 레이어 구축

## 개요
Sokkan은 Claude Code 세션이 시작될 때 이전 작업 맥락(진행 상황, 결정 사항, 미해결 이슈)을 자동으로 불러와 사람이 개입하는 지점(HITL)만 확인하면 바로 이어서 작업할 수 있게 하는 "콕핏"형 레이어다. 개인 MacBook에서는 이를 그대로 클론해 쓰거나, 유사한 구조를 직접 구현해 "세션 간 기억이 유지되는 Claude Code 환경"을 컨설팅 상품이나 내부 자동화 도구로 재판매할 수 있다는 점에서 가치가 있다.

## 구현 가능성 — 중
- 오픈소스(GitHub)로 코드가 공개되어 있어 클론 후 로컬 실행은 난이도가 낮음(상).
- 다만 Claude Code의 세션 훅(SessionStart 등)·MCP 연동 구조를 이해하고 커스터마이징(고객사별 브랜딩, 기존 `MEMORY.md`/블루프린트 워크플로우와의 통합)하려면 코드 구조 파악과 어댑터 작성이 필요해 전체적으로는 "중" 난이도로 평가.
- 이미 사용자 환경에는 자체 auto-memory 시스템(`MEMORY.md`)이 구축돼 있어, Sokkan을 그대로 쓰기보다 "참고해서 필요한 기능만 이식"하는 방향이 더 현실적.

## 필요 도구
- **Claude Code** (기존 사용 중, 무료/구독 내 포함)
- **Sokkan 소스코드** — https://github.com/ninabot-ch/sokkan (오픈소스, 무료)
- **Git / GitHub CLI(`gh`)** — 클론 및 향후 fork 관리 (무료)
- **Node.js 또는 Python 런타임** (Sokkan 구현 언어 확인 후 매칭 — 리포 확인 필요, 무료)
- **SQLite 또는 JSON 파일 스토어** — 세션 상태 영속화용 (무료)
- **Claude Code Hooks (SessionStart/Stop)** — 기존 harness 기능 활용 (무료, 별도 설정 필요)
- (선택) **Notion API / Linear API** — 콕핏에서 표시할 태스크·이슈를 외부 시스템과 동기화할 경우 (무료 티어 존재, 초과 시 유료)

## 구현 단계
1. `gh repo clone ninabot-ch/sokkan`으로 리포를 로컬에 받아 README와 아키텍처(세션 상태를 어디에 어떻게 저장하는지, HITL 확인 지점을 어떻게 UI/CLI로 노출하는지)를 파악한다.
2. 로컬에서 최소 설정으로 실행해보고, 세션 재시작 시 실제로 이전 맥락을 불러오는지 동작을 검증한다.
3. 현재 `ai-info-radar` 프로젝트의 `MEMORY.md` + `scripts/cycle.py` 파이프라인과 비교해, Sokkan에서 가져올 만한 기능(예: 세션 시작 시 "확인 필요" 항목만 요약해서 보여주는 HITL 브리핑 화면)을 식별한다.
4. Claude Code의 `SessionStart` 훅에 연결되는 스크립트를 작성해, Sokkan 방식대로 이전 세션의 미결정 사항·블루프린트 목록을 요약해 터미널에 출력하도록 만든다.
5. 자신의 블루프린트 자동화(`cycle.py`)에 이 기능을 통합해, 매 실행마다 "이전 사이클에서 보류된 항목"을 콕핏 형태로 보여주는 프로토타입을 만든다.
6. 프로토타입이 안정화되면, 이를 "Claude Code 세션 기억 콕핏 셋업" 서비스로 패키징해 소규모 팀/1인 개발자 대상 유료 템플릿(Gumroad, 노션 템플릿 등)이나 컨설팅 세팅 서비스로 판매 가능성을 검토한다.

## 예상 공수
- 클론 및 동작 검증: 1~2시간 (난이도: 하)
- 기존 파이프라인과의 통합 프로토타입: 4~8시간 (난이도: 중)
- 판매 가능한 형태로 패키징(문서화, 셋업 스크립트화): 추가 4~6시간 (난이도: 중)
- 총합: 약 1~2일 작업

## 리스크/유의점
- HN 포인트 1점, 댓글 1개로 검증된 트래픽/수요 신호가 거의 없음 — 대중적 수요보다는 "직접 써보고 본인 워크플로우에 이식"하는 개인 생산성 도구로 접근하는 것이 안전.
- 오픈소스 초기 프로젝트 특성상 문서 미비·API 불안정 가능성이 높아, 클론 후 실제 유지보수 상태를 먼저 확인해야 함.
- 세션 기억 데이터에 업무상 민감 정보(고객명, 내부 의사결정)가 포함될 수 있어, 이를 외부 서비스로 판매/공유하기 전 데이터 격리·익명화 처리가 필요.
- 이미 자체 `MEMORY.md` 체계가 있으므로 Sokkan을 통째로 도입하기보다 "부분 이식"이 중복 구축을 피하는 길.
