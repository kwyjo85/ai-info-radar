# Anthropic 공식 금융 에이전트 레퍼런스로 내 도메인 에이전트 설계도 훔치기

## 쉽게 말하면
이 저장소는 Anthropic이 "은행/투자 업무용 AI 비서를 이렇게 만들면 된다"고 공개한 공식 설계도입니다. 마치 유명 셰프가 자기 레시피북을 통째로 공개한 것과 같아서, 내가 금융업이 아니어도 "재료 손질법(스킬 구성)"과 "같은 요리를 배달앱과 홀서빙 양쪽에 파는 법(플러그인+API 이중 배포)"만 배워서 내 요리(내 업무 에이전트)에 그대로 적용할 수 있습니다.

## 이걸로 할 수 있는 것
1. ai-info-radar 프로젝트의 "트렌드 리서치·채점" 로직을 이 저장소의 skills/agents/connectors 폴더 구조 그대로 재구성해 유지보수하기 쉬운 에이전트로 정리한다.
2. Claude Code(Cowork 플러그인)와 API(Managed Agents) 양쪽에서 똑같이 도는 "리서치 에이전트"를 한 벌만 만들어, 나는 터미널에서 쓰고 고객에게는 API로 파는 이중 판매 구조를 만든다.
3. 이 설계 패턴을 "우리 회사 도메인(예: 육아용품 소싱, 유통)"에 이식한 미니 에이전트 템플릿을 만들어 소상공인 대상 유료 셋업 대행 상품으로 판다.

## 개요
이 레퍼런스는 특정 금융 기능을 그대로 쓰라는 게 아니라, "시스템 프롬프트+스킬+데이터 커넥터"를 한 벌로 만들고 이를 Cowork 플러그인(사람이 채팅으로 씀)과 Managed Agents API(서버가 자동 호출함) 두 방식에 동일하게 배포하는 아키텍처 패턴을 보여줍니다. 가치는 콘텐츠(금융 지식)가 아니라 "재사용 가능한 에이전트 설계 틀"에 있으며, 이를 본인 프로젝트나 고객 도메인에 이식하면 개발 시간을 크게 아낄 수 있습니다.

## 구현 가능성 — 상
- 공식 Anthropic 저장소라 문서·구조가 안정적이고 과장이 없음(스코어 근거상 "과장 1"로 매우 낮음).
- Python 기반이며 폴더 구조를 읽고 모사하는 수준이라 코딩 난이도가 낮음 — 실제로 새 인프라를 배우는 게 아니라 기존 Claude Code/Cowork 지식을 재배치하는 작업.
- 실제 금융 도메인 지식 없이도 "구조 학습 → 내 도메인 이식"만으로 가치가 나오므로 나에게 바로 적용 가능.

## 필요 도구
- Claude Code (이미 보유, 무료/구독) — 저장소 클론·분석·이식 작업 수행
- GitHub CLI `gh` 또는 브라우저 — anthropics/financial-services 클론 (무료)
- Claude Cowork 플러그인 환경 (구독 필요, 이미 사용 중이면 추가 비용 없음)
- Anthropic Managed Agents API 키 (유료, 사용량 과금 — 실제 배포 단계에서만 필요)
- 기존 ai-info-radar 저장소 (내 코드베이스, 무료) — 이식 대상
- 노션 또는 마크다운 — 설계 패턴 문서화용 (무료)

## 구현 단계
1. `gh repo clone anthropics/financial-services`로 로컬 MacBook에 저장소를 받고, `skills/`, `agents/`, `connectors/` 세 폴더만 30분간 훑어 각 폴더의 역할(스킬=능력 단위, 에이전트=시스템 프롬프트+스킬 조합, 커넥터=외부 데이터 연결)을 표로 정리한다.
2. 그중 하나의 대표 스킬 파일(예: 리서치/요약 스킬)을 열어 "SKILL.md 프론트매터 + 지시문" 형식을 확인하고, 같은 형식을 내 도메인(트렌드 리서치)에 맞춰 빈 템플릿으로 복제한다.
3. ai-info-radar 저장소 안에 `agents/trend-research/` 폴더를 새로 만들어, 현재 흩어져 있는 채점·요약 로직을 이 저장소 구조를 본떠 `skills/scoring.md`, `skills/summarize.md`, `connectors/rss.md` 형태로 재구성한다.
4. 같은 스킬 정의를 Claude Code Cowork 플러그인(로컬 채팅용)에서 먼저 동작 확인한다 — 프롬프트 하나로 스킬이 호출되는지 테스트.
5. 이후 동일 스킬 정의를 Managed Agents API 호출 payload에 그대로 재사용하는 얇은 Python 래퍼(`agents/trend_research_api.py`)를 작성해, "로컬 채팅용"과 "서버 자동화용"이 코드 중복 없이 같은 스킬 파일을 참조하도록 만든다.
6. 이 이식 결과(폴더 구조 + 이중 배포 스크립트)를 별도 깃허브 템플릿 저장소로 분리해 "Anthropic 공식 패턴 기반 도메인 에이전트 스타터"로 정리한다.
7. 지인/소상공인 대상으로 "당신 업무(예: 재고 문의 응대, 견적 요청 분류)를 이 구조로 세팅해드립니다"라는 셋업 대행 서비스를 소개하고 1건 무료/할인 시범 진행 후 유료 전환한다.

## 예상 공수
- 구조 학습 30분~1시간 + ai-info-radar 이식 4~6시간 + 이중 배포 래퍼 작성 2~3시간 + 템플릿 정리·문서화 2시간, 총 실작업 9~12시간.
- 난이도: 하~중 (읽고 모사하는 작업이 대부분이나, Managed Agents API 실제 배포 부분은 처음이라면 API 문서 확인 시간이 추가로 필요할 수 있음).

## 리스크/유의점
- 금융 도메인 특화 스킬 내용(규정 준수, 리스크 계산 등)은 내 업무와 무관하므로 그대로 가져다 쓰면 안 되고, 반드시 "구조만" 이식해야 함 — 세부 프롬프트 문구를 그대로 복사하면 엉뚱한 도메인 지식이 섞여 들어갈 수 있음.
- Managed Agents API는 사용량 과금이라 요금제 확인 없이 프로토타입을 서버에 상시 배포하면 예상외 비용이 발생할 수 있음 — 배포 전 요금 확인 필수.
- 저장소가 활발히 업데이트 중(오늘 +438 스타)이므로 구조가 향후 바뀔 수 있어, 이식 후에는 원본을 계속 추적하기보다 내 버전으로 완전히 분리해 유지하는 것이 안전.
- 셋업 대행을 유료 서비스로 팔 경우, 고객 데이터(재고, 문의 내역 등)를 다루게 되므로 최소한의 데이터 처리 동의·보안 조치가 필요.
