# Jev-pilot: 프롬프트별 최적 설정 자동 선택

## 쉽게 말하면
프롬프트(질문·명령)마다 "이번엔 어떤 모델, 어떤 파라미터(온도·토큰 길이 등)를 쓸지"를 사람이 매번 고민하지 않아도, 도구가 프롬프트 내용을 보고 자동으로 골라주는 시스템입니다. 마치 사진 찍을 때 카메라가 "인물 모드", "야경 모드"를 자동으로 골라주는 것과 비슷합니다.

## 이걸로 할 수 있는 것
1. Claude Code로 코드 리뷰용 프롬프트를 보낼 땐 저온도(정확성 우선) 설정을, 아이디어 브레인스토밍 프롬프트를 보낼 땐 고온도(창의성 우선) 설정을 자동 전환해서 매번 수동으로 --model, --temperature 옵션을 바꾸지 않게 합니다.
2. Jev(TypeSafe AI System One)와 Claude 등 여러 모델을 동시에 쓰는 자동화 파이프라인에서, 작업 성격(요약/분류/생성/코드)에 따라 가장 비용 효율적인 모델을 자동 라우팅해 API 비용을 절감합니다.
3. 외주로 "AI 자동화 컨설팅"을 할 때, 고객사의 반복 업무 프롬프트를 분석해 최적 설정 프리셋을 자동 추천해주는 미니 SaaS/스크립트를 만들어 판매합니다.

## 개요
이 프로젝트는 입력 프롬프트의 특징(길이, 의도, 카테고리 등)을 분석해 모델·온도·max_tokens 같은 실행 설정을 자동으로 결정해주는 "설정 자동 선택기(config selector)"입니다. 여러 프롬프트를 반복적으로 다루는 자동화 워크플로우에서 설정값 튜닝을 사람이 매번 하지 않아도 되게 만들어, 시간 절약과 비용 최적화(불필요하게 비싼 모델/긴 토큰 사용 방지)라는 가치를 제공합니다.

## 구현 가능성
**중** — 개념 자체(프롬프트 분류 → 규칙/모델 기반 설정 매핑)는 개인 MacBook에서 Python/Node 스크립트로 충분히 구현 가능하지만, 원본 저장소(Akramovic1/jev-pilot)가 GitHub·HN에서 확인 시 코드 내용·문서·의존성을 직접 확인하지 못한 상태(포인트 2점, 댓글 0개로 초기 단계 프로젝트로 추정)라, 그대로 가져다 쓰기보다는 아이디어를 참고해 자체 구현하는 편이 안전합니다.

## 필요 도구
- **Claude Code / Claude API** — 실제 실행 엔진 (유료, 토큰 종량)
- **Python 3.11+ 또는 Node.js** — 라우팅 로직 스크립트 작성 (무료)
- **간단한 분류기** — 규칙 기반(정규식/키워드) 또는 소형 임베딩 모델(예: `sentence-transformers`, 무료/로컬) 로 프롬프트 유형 분류
- **설정 프리셋 파일(YAML/JSON)** — "코드리뷰: temperature 0.1", "브레인스토밍: temperature 0.8" 등 매핑 테이블 (무료)
- **GitHub 저장소(Akramovic1/jev-pilot)** — 참고용 원본 코드 (무료, 단 라이선스 확인 필요)
- (선택) **LangChain 또는 자체 라우터 스크립트** — 다중 모델(예: Claude, Jev) 라우팅 시 (무료 오픈소스)

## 구현 단계
1. GitHub에서 `Akramovic1/jev-pilot` 저장소를 clone하고 README·소스코드를 직접 읽어 실제 로직(어떤 기준으로 설정을 고르는지)을 정확히 파악한다.
2. 본인이 반복적으로 쓰는 프롬프트 유형 5~10개(코드 리뷰, 요약, 아이디어 생성, 번역 등)를 목록화하고 각각에 어울리는 모델/temperature/max_tokens 값을 표로 정리한다.
3. Python으로 간단한 분류 함수를 작성한다 — 처음엔 키워드 규칙 기반(예: "review", "버그" 포함 시 코드리뷰 프리셋)으로 시작해 빠르게 프로토타입을 완성한다.
4. 분류 결과에 따라 Claude API 호출 파라미터(model, temperature, max_tokens)를 자동 매핑하는 wrapper 함수를 만든다.
5. 본인의 실제 자동화 스크립트(예: Claude Code 훅, cron 작업, 인스타 대시보드 데이터 가공 스크립트 등)에 이 wrapper를 끼워 넣어 A/B로 "수동 설정 vs 자동 설정" 결과 품질과 비용을 비교한다.
6. 결과가 만족스러우면 macOS launchd 또는 Claude Code 커스텀 커맨드로 상시 적용하고, 프리셋 매핑 표를 지속적으로 업데이트한다.
7. (수익화 단계) 이 라우터를 소규모 컨설팅 상품(예: "고객사 프롬프트 자동 최적화 스크립트")으로 패키징해 Fiverr/크몽 등에 올리거나, 블로그/유튜브로 구현 과정을 콘텐츠화한다.

## 예상 공수
- 저장소 분석 + 프로토타입(키워드 규칙 기반): 2~4시간, **난이도 하**
- 실제 자동화 파이프라인에 통합 + 테스트: 4~8시간, **난이도 중**
- 수익화용 패키징(문서화, 판매 페이지 등): 별도 4~6시간, **난이도 중**

## 리스크/유의점
- 원본 저장소는 포인트 2점·댓글 0개로 검증되지 않은 초기 프로젝트이므로, 코드를 그대로 신뢰해 실행하지 말고 직접 읽고 이해한 뒤 사용할 것.
- 프롬프트 자동 분류가 오분류될 경우 오히려 비용이 늘거나(불필요하게 비싼 모델 선택) 품질이 떨어질 수 있으므로 초기에는 반드시 결과를 사람이 검토하는 단계를 둘 것.
- 여러 모델(Jev, Claude 등) API 키를 한 스크립트에서 관리하게 되므로 `.env` 파일과 `.gitignore` 관리를 철저히 하여 키 유출을 방지할 것.
- 수익화 목적으로 고객 프롬프트 데이터를 다룰 경우, 고객 데이터를 외부 API로 전송하는 것에 대한 사전 동의·보안 고지가 필요함.
