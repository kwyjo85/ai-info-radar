# Claude Code Projects: 장기 프로젝트 관리로 AI 자동화 수익 파이프라인 만들기

## 쉽게 말하면
Claude Code Projects는 AI 비서에게 "이 프로젝트는 몇 주에서 몇 달씩 이어질 거야"라고 알려주고, 그 프로젝트의 맥락(목표, 진행 상황, 과거 결정들)을 계속 기억하게 해주는 기능입니다. 마치 신입 직원에게 매번 처음부터 설명하는 대신, 프로젝트 전담 팀원이 생겨서 어제 어디까지 했는지 스스로 기억하고 이어서 일하는 것과 비슷합니다.

## 이걸로 할 수 있는 것
1. 여러 클라이언트의 자동화 외주 작업(예: 인스타 대시보드 연동, Jev 챗봇 커스터마이징)을 프로젝트별로 분리해 두고, 몇 주 뒤에 돌아와도 "이 클라이언트는 이런 요구사항이었지"를 AI가 바로 떠올려 작업을 재개한다.
2. 매일 하는 "AI 자동화 정보 레이더"(현재 이 저장소) 같은 반복 콘텐츠 제작 프로젝트를 하나의 Project로 묶어, 블루프린트 스타일·과거 산출물 이력을 AI가 자동으로 참고하게 해 품질 편차를 줄인다.
3. 여러 개의 사이드 프로젝트(수익형 자동화 도구, Jev 관련 프롬프트 상품 등)를 동시에 운영하면서 프로젝트 전환 시 발생하는 "맥락 재설명" 시간을 없애 실질 작업 시간을 늘린다.

## 개요
Claude Code Projects는 단발성 대화가 아니라 여러 세션·여러 날에 걸친 작업 흐름에서 목표, 결정 이력, 미완료 작업을 유지시켜주는 장기 컨텍스트 관리 기능입니다. 프리랜서/1인 개발자가 동시에 여러 유료 프로젝트(자동화 외주, 콘텐츠 자동 생산, Jev 기반 서비스 등)를 운영할 때 "맥락 스위칭 비용"을 크게 줄여, 같은 시간에 더 많은 프로젝트를 유료로 병행할 수 있게 해준다는 점에서 직접적인 수익화 가치가 있습니다.

## 구현 가능성
**상**
- 근거: 이미 Claude Code CLI를 MacBook에서 사용 중이고(현재 이 저장소가 그 증거), 프로젝트 단위 문서(CLAUDE.md), 메모리 시스템, blueprints 폴더 관리 등 유사한 패턴을 직접 운영해 본 경험이 있음. 추가 설치 없이 기존 워크플로우 위에 "프로젝트 단위 분리"만 얹으면 되는 구조.

## 필요 도구
- Claude Code CLI (이미 사용 중, Claude Pro/Max 또는 API 크레딧 요금제 — 유료, 기존 구독 활용 가능)
- Git/GitHub (프로젝트별 브랜치 또는 리포지토리 분리용, 무료)
- 로컬 폴더 구조 + CLAUDE.md / MEMORY.md 스타일 컨텍스트 문서 (무료, 직접 작성)
- (선택) Notion 또는 Obsidian — 클라이언트별 요구사항·계약 조건 기록용 (무료~유료 플랜)
- (선택) cron/스케줄 기능 — 반복 산출물(예: 일일 정보 레이더) 자동 실행용 (Claude Code 내장, 별도 비용 없음)

## 구현 단계
1. `~/Documents/` 아래에 클라이언트/사이드프로젝트별 폴더를 만들고 각각을 별도 git 리포지토리로 초기화한다 (예: `cocobaby-ai-info-radar`, `jev-client-A`, `ig-dashboard-sync`).
2. 각 프로젝트 루트에 `CLAUDE.md`를 작성해 목표, 현재 단계, 클라이언트 요구사항, 절대 하지 말아야 할 것을 명시한다.
3. Claude Code를 해당 폴더에서 실행할 때마다 프로젝트 전용 컨텍스트가 자동 로드되는지 확인하고, 프로젝트 전환 시 폴더만 바꾸면 되는 구조를 만든다.
4. 반복 산출물이 있는 프로젝트(예: 정보 레이더 블루프린트)는 `/loop` 또는 스케줄 기능으로 정기 실행을 걸어, 매번 수작업으로 컨텍스트를 다시 설명하지 않아도 되게 한다.
5. 프로젝트별 진행 이력을 `blueprints/` 또는 `progress.md` 형태로 축적해, 몇 주 뒤 재개 시 AI가 과거 결정을 읽고 이어받을 수 있게 한다.
6. 클라이언트에게 납품 시 이 구조를 "프로젝트 관리 프로세스"로 제시해, 반복 유지보수 계약(월 구독형 자동화 관리)으로 전환할 수 있는지 타진한다.

## 예상 공수
- 초기 폴더/문서 구조 세팅: 1~2시간, 난이도 하
- 기존 프로젝트(현재 리포지토리 포함) 재정리 및 CLAUDE.md 작성: 프로젝트당 30분~1시간, 난이도 하
- 반복 산출물 자동 스케줄링 연결: 1~2시간, 난이도 중
- 클라이언트향 월 구독형 관리 프로세스로 패키징: 2~3시간(제안서 작성 포함), 난이도 중

## 리스크/유의점
- 프로젝트가 늘어날수록 컨텍스트 문서(CLAUDE.md, 메모리)가 방치되어 오히려 낡은 정보로 AI를 오도할 수 있으므로 주기적 정리가 필요하다.
- 여러 클라이언트 프로젝트를 한 계정/구독으로 돌릴 경우 토큰·사용량 한도를 넘으면 작업이 동시에 막힐 수 있어, 유료 클라이언트 작업에는 여유 있는 요금제를 유지해야 한다.
- 클라이언트 데이터(계약서, 민감 정보)를 프로젝트 문서에 그대로 적어두면 실수로 공개 리포지토리에 커밋될 위험이 있으므로 `.gitignore` 및 비공개 리포 설정을 반드시 확인한다.
