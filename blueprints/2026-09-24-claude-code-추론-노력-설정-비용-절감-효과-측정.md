# Claude Code 추론 노력(Effort) 설정으로 비용 절감 효과 측정하기

## 쉽게 말하면
Claude Code는 "얼마나 깊이 생각할지"를 낮음/중간/높음처럼 단계로 조절할 수 있는데, 이걸 요리에 비유하면 "간단한 라면은 약불로, 손님 초대 요리는 센불로" 조절하는 것과 같습니다. 이 프로젝트는 그 "불 조절"을 작업 난이도에 맞게 자동으로 골라줘서, 쓸데없이 센불(비싼 고비용 추론)을 쓰지 않도록 하고 실제로 얼마를 아꼈는지 숫자로 보여줍니다.

## 이걸로 할 수 있는 것
1. 매일 반복하는 Jev 자동 분류·요약 작업에 "낮은 노력" 모드를 자동 적용해서 API 비용을 줄인다.
2. Claude Code로 클라이언트 코드 작업을 할 때, 간단한 리팩터링은 저비용 모드, 복잡한 아키텍처 설계는 고비용 모드로 자동 전환해 프로젝트 마진을 개선한다.
3. 월말에 "이번 달 추론 노력 조절로 얼마를 아꼈는지" 리포트를 뽑아 컨설팅 고객에게 "AI 도입 시 비용 최적화 사례"로 제시해 영업 자료로 활용한다.

## 개요
이 프로젝트는 Claude Code(또는 Claude API)의 reasoning effort 파라미터를 작업 유형별로 다르게 설정하고, 그 결과 토큰 사용량·비용·응답 품질이 어떻게 달라지는지 비교 측정하는 도구입니다. 개인/소규모 AI 자동화 운영자 입장에서는 "무조건 최고 성능 모드"를 쓰지 않고도 품질을 유지하면서 API 비용을 줄이는 근거 데이터를 확보할 수 있다는 점에서, Jev 기반 자동화나 Claude Code 외주 작업의 원가를 낮추는 실질적 수익 개선 수단이 됩니다.

## 구현 가능성 — 중
GitHub 공개 저장소(ifoster01/jev-effort)의 코드를 그대로 참고/포크해 개인 환경에 맞게 조정하면 되므로 기술적 난이도는 낮지만, 이름이 "jev"라는 사용자의 다른 프로젝트(TypeSafe AI System One)와 혼동되지 않게 구조를 분리해야 하고, 실제 비용 측정을 위해서는 자신의 Claude API 사용 패턴에 맞춘 벤치마크 케이스를 직접 설계해야 하므로 순수 구현보다 "측정 설계"에 시간이 더 든다. 저장소 자체의 활동도(포인트 1, 댓글 0)로 보아 성숙도가 낮아 코드 품질 검증이 추가로 필요하다.

## 필요 도구
- Claude API (Anthropic) — 사용량만큼 과금, 이미 보유 중인 API 키 활용 가능
- Claude Code CLI — 무료(구독/API 사용량 기반)
- Python 또는 Node.js 스크립트 환경 — 무료 (측정/로깅 스크립트 작성용)
- jev-effort GitHub 저장소 (참고/포크) — 무료, https://github.com/ifoster01/jev-effort
- 간단한 비용 추적 시트 (Google Sheets 또는 SQLite/CSV) — 무료
- (선택) Anthropic 콘솔의 사용량 대시보드 — 무료 (계정 내 기본 제공)

## 구현 단계
1. `git clone https://github.com/ifoster01/jev-effort` 로 저장소를 로컬에 받아 코드 구조와 효과 측정 로직(어떤 지표를 재는지)을 먼저 읽어본다.
2. 자신의 Jev/Claude Code 실제 작업 중 반복되는 3~5가지 태스크 유형(예: 기사 분류, 요약, 코드 리팩터링, 아키텍처 설계)을 뽑아 난이도별 샘플 프롬프트 세트를 만든다.
3. 각 태스크를 low/medium/high effort 설정으로 각각 실행하고, 응답 시간·토큰 수·비용(입력+출력 토큰 × 단가)·결과 품질(수동 채점 1~5점)을 기록하는 스크립트를 작성한다.
4. 결과를 CSV/시트에 누적하고, "효과 대비 비용" 표를 만들어 어떤 태스크 유형에 어떤 effort 레벨이 최적인지 규칙을 도출한다(예: 단순 요약은 low, 코드 설계는 high).
5. 이 규칙을 실제 ai-info-radar/Jev 자동화 파이프라인의 채점·요약 스크립트에 조건문으로 적용해 effort 레벨을 자동 선택하게 한다.
6. 한 달간 실사용 데이터를 모아 "적용 전 대비 비용 절감률"을 계산하고, 이를 블루프린트/포트폴리오 자료로 정리해 컨설팅 영업에 활용한다.

## 예상 공수
- 저장소 파악 및 로컬 세팅: 1~2시간, 난이도 하
- 벤치마크 케이스 설계 및 측정 스크립트 작성: 3~5시간, 난이도 중
- 실제 파이프라인에 규칙 통합: 2~3시간, 난이도 중
- 1개월 데이터 수집 후 리포트화: 별도 시간 소요 없음(자동 로깅), 분석 1~2시간
- 총 실작업 시간: 약 6~10시간, 전체 난이도 중

## 리스크/유의점
- effort 낮춤이 품질 저하로 이어져 고객 납품물 품질 문제를 일으킬 수 있으므로, 반드시 품질 채점을 병행해 임계치 이하로 떨어지면 자동으로 high로 승격하는 안전장치가 필요하다.
- 외부 저장소 코드 품질이 검증되지 않았으므로(포인트/댓글 거의 없음) 그대로 프로덕션에 붙이지 말고 로직만 참고해 직접 재구현하는 것을 권장한다.
- Claude Code의 effort 파라미터 이름/동작은 버전에 따라 바뀔 수 있어, 정기적으로 공식 문서 변경 여부를 확인해야 한다.
