# Jev로 프롬프트의 허점 찾기

## 쉽게 말하면
내가 만든 AI 프롬프트(지시문)에 숨어있는 구멍—AI가 오해하거나 악용될 수 있는 지점—을 또 다른 AI(Jev)가 대신 찾아주는 도구입니다. 비유하자면 계약서를 쓰고 나서 변호사에게 "이 조항 악용될 여지 있나요?"라고 검토받는 것과 비슷합니다.

## 이걸로 할 수 있는 것
1. 텔레그램 다이제스트 브리핑에 쓰는 프롬프트를 Jev에 넣어, 사용자가 이상한 입력을 줬을 때 엉뚱한 답이 나올 여지가 있는지 미리 점검한다.
2. 고객사에 납품하는 Claude Code 자동화 스크립트의 시스템 프롬프트를 검수 서비스 상품으로 묶어, "프롬프트 보안 감사" 유료 컨설팅으로 판매한다.
3. 사이클 산출 블루프린트 같은 반복 업무 자동화 프롬프트를 배포 전에 Jev로 자동 검증하는 CI 단계를 만들어, 실수로 인한 재작업을 줄인다.

## 개요
Jev-blindspot은 프롬프트를 입력하면 모호성, 탈옥(jailbreak) 취약점, 상충되는 지시, 누락된 예외 처리 등을 자동 분석해 리포트로 알려주는 도구로 추정됩니다(GitHub 저장소, 스타·코멘트 거의 없는 신생 프로젝트). 개인이 만드는 자동화 프롬프트나 고객에게 판매하는 AI 워크플로우의 신뢰성을 사전에 검증하는 QA 계층으로 활용할 수 있어, "프롬프트 감사" 자체를 수익화하거나 기존 자동화 상품의 품질 보증 도구로 쓸 수 있습니다.

## 구현 가능성: 중
- 근거: 저장소가 신생(포인트 2, 댓글 0)이라 문서화·안정성이 검증되지 않음. Jev 자체가 2026-09 출시된 최신 모델이라 통합 API/SDK 성숙도가 낮을 가능성 높음. 다만 "프롬프트를 다른 LLM에 넣어 취약점 분석"이라는 패턴 자체는 Claude Code로도 직접 재현 가능(도구 없이도 자체 구현 가능)해 구현 가능성은 중간 이상으로 판단.

## 필요 도구
- GitHub 저장소 `jsk4581/jev-blindspot` 클론 (무료, 단 코드 품질/라이선스 확인 필요)
- Jev API 키 또는 접근 경로 (유료 추정, 정확한 가격 정책은 출시 초기라 미확인 — 확인 필요)
- Python 또는 Node.js 실행 환경 (무료, 기존 macOS 개발환경 활용)
- (대안) Jev API 대신 Claude API로 동일 로직 자체 구현 — Anthropic API 키 필요 (사용량 과금, claude-api 스킬 참고)
- 기존 자동화 프롬프트 저장소(사이클 산출/디이제스트 브리핑 등) — 이미 보유

## 구현 단계
1. `git clone https://github.com/jsk4581/jev-blindspot` 후 README·코드 직접 읽어 실제 입출력 형식(CLI인지 API인지) 확인.
2. Jev API 키 발급 절차 확인 — 없으면 이 도구는 스킵하고 3번으로 대체.
3. 로컬에서 테스트: 기존에 쓰는 텔레그램 브리핑 프롬프트 1개를 입력해 실제로 유의미한 취약점 리포트가 나오는지 검증 (기대에 못 미치면 도구 자체 신뢰도 낮음으로 판단하고 중단).
4. 유효하다고 판단되면, `ai-info-radar` 저장소에 `scripts/audit_prompt.py` 같은 래퍼 스크립트 작성 — 프롬프트 파일 경로를 입력받아 Jev(or Claude) 분석 결과를 마크다운 리포트로 저장.
5. 기존 프롬프트 파일들(디이제스트, 사이클 산출 등)에 일괄 실행해 베이스라인 리포트 작성.
6. 유료 컨설팅 상품화를 고려한다면: 이 감사 프로세스를 "AI 자동화 프롬프트 보안 점검" 1회성 서비스로 패키징하고, 리포트 템플릿을 표준화.
7. (선택) Claude Code hook으로 등록해 프롬프트 파일 커밋 전 자동 감사 실행.

## 예상 공수
- 저장소 탐색·검증: 1~2시간
- 로컬 통합 스크립트 작성: 2~4시간
- 기존 프롬프트 일괄 감사 + 결과 정리: 2~3시간
- 상품화(서비스 문서·가격 책정)까지 포함 시 +4~6시간
- 난이도: 중 (도구 자체는 신생이라 문서 부족, API 안정성 리스크가 관건)

## 리스크/유의점
- 저장소가 포인트 2·댓글 0인 신생 프로젝트라 유지보수 중단 가능성 있음 — 프로덕션 의존은 지양, 검증용으로만 활용 권장.
- Jev가 2026-09 출시 최신 모델이라 API 문서·가격·레이트리밋이 유동적일 수 있음 — 사용 전 반드시 최신 공식 문서 확인.
- 프롬프트에 고객 정보나 내부 로직이 포함된 경우 외부 API(Jev)로 전송 시 데이터 유출 리스크 — 민감한 프롬프트는 로컬/자체 구현(Claude API 등) 경로로 우회 고려.
- "허점 찾기" 도구 자체가 오탐(false positive)을 많이 낼 경우 업무 효율보다 검토 부담이 커질 수 있으니, 초기엔 소규모 프롬프트로 신뢰도부터 검증할 것.
