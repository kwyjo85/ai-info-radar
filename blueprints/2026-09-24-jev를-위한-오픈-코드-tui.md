# Jev를 위한 오픈소스 TUI "jevelry"

## 쉽게 말하면
Jev는 문장을 만들지 않고 "이거다/저거다" 하는 빠른 판단만 순식간에 내려주는 AI인데, 이번에 나온 "jevelry"는 이 판단 AI를 터미널에서 바로 불러다 쓸 수 있게 만든 도구예요. 마치 Claude Code에 "스킬"을 등록해두고 반복 작업을 시키듯, Jev에게도 "이런 상황엔 이렇게 판단해"라는 템플릿을 미리 등록해두고, 판단이 틀리면 피드백을 줘서 점점 똑똑해지게 만드는 대시보드까지 딸려 있습니다.

## 이걸로 할 수 있는 것
1. Claude Code 자동화 파이프라인 안에서 "이 커밋을 배포해도 되나/재시도할까/스킵할까" 같은 이분법 판단을 LLM 대신 Jev에게 맡겨 속도와 비용을 줄인다.
2. ai-info-radar의 채점 단계(관련도·실행가능성 점수) 중 단순 가/부 판정(예: "이 기사는 뉴스인가 구현 사례인가")을 Jev 템플릿으로 대체해 haiku 호출 횟수를 줄인다.
3. 반복되는 의사결정(예: "이 PR을 자동 머지해도 되는가")에 대해 jevelry 대시보드로 과거 판단 결과를 보고 피드백을 주며 팀만의 판단 기준을 점점 정교하게 다듬는다.

## 개요
jevelry는 Jev API를 감싼 오픈소스 TUI로, (1) 미리 정의한 "결정 템플릿"을 등록·재사용하고 (2) 실제 판단 이력을 대시보드로 보여주며 (3) 잘못된 판단에 피드백을 주어 다음 판단 정확도를 높이는 구조입니다. Claude Code나 자동화 스크립트가 LLM을 부를 필요 없이 정형화된 판단만 필요할 때 Jev+jevelry로 대체하면, 응답 속도와 비용 면에서 수익화 여지가 생깁니다(예: 대량 배치 판단을 값싸게 처리해주는 서비스화).

## 구현 가능성 — 중
- 근거(긍정): TypeSafe 공식 SDK(TYPESAFE_API_KEY)만 있으면 되고, jevelry는 오픈소스라 코드 확인 후 직접 붙이거나 포크해서 커스터마이즈 가능. TUI 기반이라 macOS 터미널 환경과 궁합이 좋음.
- 근거(불확실): Jev/jevelry 모두 2026-09 출시 극초기 제품(HN 포인트 1, 댓글 0)이라 문서·안정성·API 변경 가능성이 낮게 검증됨. Claude 모델 지식 컷오프 이후 제품이라 사전 학습된 정보가 없어 리포지토리를 직접 읽어야 함.

## 필요 도구
- Jev API 키 (TYPESAFE_API_KEY) — 유료(early access, 정확한 요금제 확인 필요)
- jevelry TUI (github.com/backant-io/jevelry) — 무료/오픈소스
- Node.js 또는 Go 런타임 (jevelry 빌드 요구사항, 리포 확인 필요) — 무료
- 기존 ai-info-radar 파이프라인 (Python/Node, .env 관리) — 무료
- (선택) jev-router — Claude Code 작업을 Jev로 라우팅하는 도구, 사용자 메모에 기록된 파생 도구 — 무료/오픈소스 추정

## 구현 단계
1. `git clone https://github.com/backant-io/jevelry`로 리포지토리를 받아 README와 설치 스크립트를 확인해 런타임 의존성(Node/Go 등)을 파악한다.
2. TypeSafe 사이트에서 Jev early access API 키를 신청하고 `.env`에 `TYPESAFE_API_KEY`로 저장한다(ai-info-radar의 기존 `.env` 관리 방식 재사용).
3. jevelry를 로컬에서 실행해 TUI가 뜨는지, 기본 제공 "결정 템플릿" 예시가 무엇인지 확인한다.
4. ai-info-radar의 채점 로직(scripts/score 관련 파일) 중 이분법 판단(예: kind: 구현|뉴스 분류)을 뽑아 jevelry 결정 템플릿 형식으로 옮겨보고, 소량 샘플로 haiku 결과와 Jev 결과를 비교한다.
5. 정확도가 충분하면(예: 90% 이상 일치) 파이프라인의 해당 판단 지점만 Jev 호출로 교체하고, 나머지(요약·title_ko 생성 등 텍스트 생성)는 기존 LLM 그대로 둔다.
6. jevelry 대시보드로 판단 이력을 모니터링하면서 오분류 건에 피드백을 입력해 템플릿 정확도를 개선하는 루틴을 1~2주 운영해본다.
7. 결과가 안정적이면 이 구조(빠른 판단은 Jev, 생성은 Claude)를 "저비용 배치 판단 서비스"로 패키징해 소규모 유료 제공 가능성을 검토한다(예: 다른 팀의 콘텐츠 분류/필터링 대행).

## 예상 공수
- 리포 클론·환경 파악·API 키 발급: 1~2시간
- jevelry 로컬 실행 및 템플릿 구조 학습: 2~3시간
- ai-info-radar 채점 로직 중 일부를 Jev 템플릿으로 이식·비교 테스트: 4~6시간
- 대시보드 피드백 루프 운영 및 튜닝: 1~2주에 걸쳐 틈틈이 (실 작업시간 3~5시간)
- 난이도: 중 (신제품 문서 부족으로 리포 코드를 직접 읽어야 하는 부분이 시간을 좌우함)

## 리스크/유의점
- Jev·jevelry 둘 다 출시 극초기(HN 포인트 1)라 API 스펙이 바뀌거나 서비스가 중단될 위험이 있음 — 핵심 파이프라인을 통째로 의존시키지 말고 부분 교체로 시작할 것.
- TypeSafe API 가격 정책이 아직 공개적으로 검증되지 않아 배치 판단량이 많아지면 비용이 예상과 다를 수 있음 — 소량으로 먼저 비용 테스트.
- jevelry가 오픈소스라 해도 관리(메인테이너)가 backant.io 개인/소규모 팀일 가능성이 높아 보안 검토(의존성, 원격 코드 실행 여부) 없이 그대로 프로덕션에 붙이지 말 것.
- ai-info-radar는 텔레그램 명령 기반 원격 실행 기능을 이미 안전상의 이유로 취소한 이력이 있으므로, Jev 연동도 자동 판단이 배포·머지 같은 되돌리기 어려운 액션을 직접 트리거하지 않도록 설계할 것.
