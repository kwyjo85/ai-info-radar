# LinkedIn 포스트 자동 작성 Claude 스킬 세트

## 쉽게 말하면
회사에 "글 잘 쓰는 후배"를 한 명 두는 것과 비슷합니다. 이 후배는 초안을 써서 책상에 올려두기만 하고, 실제로 우편함에 넣는 건(=게시하는 건) 항상 상사인 나의 확인을 받은 뒤에만 합니다. 이 세트는 LinkedIn 글쓰기용으로 만들어졌지만, "AI가 초안을 만들고 → 사람이 검토 → 승인 후에만 실행"이라는 뼈대 자체가 재사용 가능한 부품입니다.

## 이걸로 할 수 있는 것
1. 매일 아침 인스타/GitHub 대시보드 리포트를 사람이 읽기 편한 "발행용 요약 초안"으로 자동 변환해 카톡이나 메모앱에 승인 대기 상태로 던져놓기.
2. Jev나 다른 자동화 결과물(코드 변경, 리포트, 분석)을 "사람 말투"로 재작성해, 클라이언트나 팀에 바로 보낼 수 있는 메시지 초안 만들기.
3. 사이클 산출 블루프린트 같은 반복 리포트에 "생성 → 승인 대기 → 확정" 3단계 워크플로우를 추가해, 실수로 잘못된 정보가 그대로 나가는 것을 방지하기.

## 개요
이 저장소는 LinkedIn 글쓰기 자체를 자동화하는 스킬 11개를 제공하지만, 핵심 가치는 "AI 콘텐츠 생성 + 사람 승인 게이트" 패턴의 설계도입니다. LinkedIn 계정 연동 없이도, SKILL.md 구조와 승인 대기 로직만 뽑아내 이 프로젝트(ai-info-radar)의 리포트/브리핑 자동화나, 향후 부업으로 "AI 자동화 콘텐츠 대행" 서비스를 만들 때 재사용할 수 있습니다.

## 구현 가능성
**중** — 근거: (1) 저장소를 읽고 패턴만 차용하는 작업은 난이도가 낮아 상에 가깝지만, (2) 실제로 이걸 "수익화 가능한 자동화"로 발전시키려면 LinkedIn API 정책(자동 게시 제한, ToS 이슈)과 콘텐츠 품질 검증 로직을 추가로 설계해야 해서 중간 난이도로 내려갑니다. 실제 LinkedIn 자동 게시까지 가지 않고 "패턴 차용"만 한다면 상.

## 필요 도구
- Claude Code (이미 보유, 무료 사용 중인 플랜 내)
- ~/.claude/skills/ 디렉토리 (무료, 로컬 설정)
- GitHub CLI `gh` (무료, 저장소 클론용) — 이미 설치되어 있을 가능성 높음
- (선택, 실제 LinkedIn 자동화까지 갈 경우) LinkedIn API 또는 브라우저 자동화 도구 — LinkedIn API는 파트너 승인 필요해 사실상 개인이 접근 어려움, 유료/제한적
- 텍스트 알림 채널 (카카오톡 API, macOS 알림, 또는 기존 launchd 알림 방식) — 기존 인프라 재사용 가능

## 구현 단계
1. `gh repo clone sergebulaev/linkedin-skills /tmp/linkedin-skills`로 저장소를 임시 위치에 클론한다 (실제 계정 연동 없이 코드만 읽기 위함).
2. `/tmp/linkedin-skills`의 각 스킬 폴더에서 `SKILL.md`만 열어, "초안 생성 → 승인 대기 → 게시" 단계가 어떤 프롬프트/구조로 짜여 있는지 확인한다.
3. 승인 대기 로직(예: 출력 파일에 상태 필드 `draft` / `approved` / `published` 추가)을 뽑아내 별도 메모나 스니펫으로 정리한다.
4. ai-info-radar 프로젝트의 기존 리포트 생성 스크립트(사이클 산출 블루프린트 관련 코드)를 찾아, 리포트 생성 직후 "확정 전 검토" 단계를 넣을 지점을 확인한다.
5. 해당 지점에 상태 필드나 별도 draft 파일(`data/draft_YYYYMMDD.md` 등)을 만들어, 사용자가 확인 후 명시적으로 승인해야 다음 단계(예: git push, 배포)가 진행되도록 조건 분기를 추가한다.
6. 승인 알림은 기존에 쓰던 채널(카톡/메모/터미널 출력)로 보내고, 승인 방법(예: 특정 파일 이름 변경, 명령어 실행)을 문서화한다.
7. 실제 LinkedIn 계정 연동은 하지 않고, 이 패턴이 잘 동작하는지 로컬 테스트로만 확인한다.

## 예상 공수
- 저장소 읽기 + 패턴 파악: 1~2시간, 난이도 하
- ai-info-radar에 승인 게이트 추가: 2~4시간, 난이도 중 (기존 스크립트 구조 파악 포함)
- 실제 LinkedIn 자동 게시까지 확장 시: 추가 1~2일, 난이도 상 (API 접근 제한 때문)

## 리스크/유의점
- "AI 티 제거"라는 문구는 과장된 마케팅 표현일 수 있음 — 실제 결과물 품질은 검증 없이 신뢰하지 말 것.
- LinkedIn은 자동화된 게시/스크래핑에 민감한 플랫폼으로, 브라우저 자동화 방식은 계정 정지 리스크가 있음 — 이번 활용은 "게시 자동화"가 아니라 "패턴 차용"에 그치는 것을 권장.
- MIT 라이선스이므로 코드 재사용은 법적으로 문제없으나, 스킬 내 프롬프트 문구를 그대로 복붙하기보다 자신의 워크플로우에 맞게 재작성하는 것이 유지보수에 유리함.
